# T296 (PAY-04): 预付线上充值、自动扣费、低余额提醒

## 任务背景与目标

依据 `docs/19-生产化路线图.md` §5 (PAY-04 / T296)，预付账户目前仅支持管理员后台手动登记流水，缺乏租客端线上充值渠道，且低余额提醒采用 UTC 日界导致与上海业务日错位；同时缺少基于设置中心规则的自动化账单抵扣能力。

本任务目标：
1. **线上充值闭环**：租客端通过微信支付 JSAPI 对预付账户进行线上充值（`POST /api/prepay-accounts/my/recharge/wechat-jsapi` 与查单 `POST /api/prepay-accounts/my/recharge/wechat-query`），微信异步回调（`POST /api/payments/wechat/notify`）解析 `attach.purpose = 'PREPAY_RECHARGE'` 并执行幂等入账与流水记录。
2. **自动扣费机制**：依据设置中心（FIN-11）的扣费开关、账单类型与部分抵扣策略，在账单出账或批量扣费时执行原子扣款，流水与账单严格关联并防止并发透支。
3. **低余额提醒治理**：低余额通知切换至 `BusinessClock` 上海业务日界，防止跨日重复发送，支持携带一键充值跳转路径。
4. **租客端体验升级**：租客端展示预付余额、近 30 天日均消耗与预估可用天数，小程序支持线上充值拉起微信支付。
5. **完整门禁与测试**：补齐单元测试、真实 PostgreSQL 集成测试（BE-INT）与小程序测试，更新 OpenAPI 规范。

## 验收标准

- [x] 线上充值入账幂等，重复回调或重复重试不重复加余额，流水记录精确追溯到支付订单号。
- [x] 自动扣费遵循设置中心开关（默认关闭），规则可配，支持全额或部分抵扣且金额不变量成立。
- [x] 低余额提醒在每个业务日恰发一次，日界严格基于 `BusinessClock`。
- [x] 租客端可查询账户近 30 天日均用量与预估可用天数，小程序支持充值。
- [x] 后端、前端与小程序自动化测试全绿，OpenAPI 契约无漂移，oxlint 0 报错。
