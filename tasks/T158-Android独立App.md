# T158: 独立 Android App（方案B：独立项目）

## 背景与决策

- **2026-10-13 决策**：Android 端采用**独立项目**路线，不在 `miniprogram/` 上叠加 `app-plus` 平台构建（避免与正在迭代的小程序互相干扰）。
- 依据：`docs/00-项目计划书.md` §2.2、`docs/08-任务拆分总览.md` 延后清单、`docs/09-待确认清单.md` #15——**Android APP 放第二阶段**，预计第一版试用 2–4 周后启动，与小程序**共用 REST 接口**。
- 后端侧已预留：`DeviceToken` 表（`backend/prisma/schema.prisma` 第 22 张表），用户注册接口预留 APP 调用（`docs/02-数据模型.md`）。
- 现状：`miniprogram/manifest.json` 有 `app-plus` 配置段，但 `miniprogram/package.json` 只装了 `uni-mp-weixin` / `uni-h5`，**没有** `build:app` 脚本与 `@dcloudio/uni-app-plus` 依赖——即当前仓库不具备 Android 打包能力，这也是选 B 的客观原因之一。

## 子路线（开工前需拍板，二选一）

| 路线 | 说明 | 成本/风险 |
|------|------|-----------|
| **B1 独立 uni-app 项目（建议）** | 新目录 `android-app/`（uni-app + Vue3），页面/主题实现方式对齐 `miniprogram/`，但**代码不共享** | 复用现有技术栈与人员能力，UI 需为 App 端重新适配（返回键、安全区、权限弹窗） |
| **B2 原生 App（Kotlin / Compose）** | 全新技术栈 | 成本高、需新技能、需独立维护一套 UI；若选此路**先补 ADR**（ADR 新增需人工批准） |

> 无论 B1/B2：独立构建脚本、独立分支、独立版本号；不得改动 `miniprogram/**`。

## 任务范围（草案）

### 1. 工程与基础设施
- 新目录 `android-app/`，与 `frontend-admin/`、`miniprogram/` 并列；纳入 CI（单独的 build job）。
- 后端接口复用现有 REST（注意全局前缀为 `/api`，以 `backend/src/main.ts` 为准；`docs/05` 的版本前缀差异见 `docs/09-待确认清单.md`）。
- 登录：`POST /api/auth/login`（`identifier` + 密码）；令牌刷新 `POST /api/auth/refresh`；登录态本地安全存储（Android Keystore）。
- 文件上传：复用 `files` 模块 → 阿里云 OSS。
- 推送：`DeviceToken` 目前**只有表**，需补「注册设备令牌」接口与推送通道选型（个推 / 厂商推送 / FCM 不适用国内，需明确）。

### 2. 功能范围（与小程序对齐）
- 租客：合同、账单、报修（含多图 ≤9）、余额/流水、通知列表。
- 保洁：待清洁列表、接单、标记完成（含照片）、角色入口。
- 管理端：只读概览（P2，可选）。

### 3. 资质与合规（`docs/06-安全与合规清单.md` §6.2）
- 上架资质：软件著作权、ICP 备案（华为/小米/OPPO/vivo/应用宝均要求备案）。
- 隐私合规：首次启动展示隐私政策、第三方 SDK 声明、"注销账号"功能。
- 提审周期不可控，需预留 3–5 天。

## 启动门槛（全部满足才开工）

1. 第一版试用反馈收集完成（2–4 周观察期，见 `docs/08-任务拆分总览.md` 观察期章节）。
2. 小程序真机验收通过（阶段3 未完成项：真实 API 联调与真机验收）。
3. ICP 备案与上架资质明确（`docs/09-待确认清单.md` 中优先级第 1 条）。
4. 子路线 B1/B2 拍板 + ADR（若选 B2）。
5. 统筹者分配编号/分支、建档 Worktree（按 AGENTS.md §4.2）。

## 验收标准（草案，开工时细化）

1. `android-app/` 可独立构建出 APK（CI job 绿）。
2. 登录 → 查看账单 → 报修（多图）→ 查看余额/通知 主流程在真机（≥Android 10）走通。
3. 越权用例与小程序一致：租客不可见他人数据；保洁不可见租客信息（复用 T138/T148 的收口结论）。
4. 令牌刷新与登出（令牌失效）在 App 端正确。
5. 隐私政策可随时访问，含注销入口。

## 依赖与风险

| 项 | 说明 |
|----|------|
| 后端接口稳定性 | App 与小程序共用接口，任何契约变更需同时通知两端（T138 教训） |
| 推送通道 | 未选型；国内 Android 需厂商推送通道，工作量和资质依赖较多 |
