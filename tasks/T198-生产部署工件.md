# T198: 生产部署工件（OPT-25）

依据优化计划 OPT-25。分支从 `feature/T197-e2e-playwright` 拉出。

## 现状

- `docker-compose.yml` 仅本地开发（弱密码、端口全映射、无应用服务）。
- 无 Dockerfile、无 Nginx 配置、无生产 compose、无镜像发布流程。
- `docs/12-部署与运维.md` 已有手动部署说明与变量清单（事实来源，T198 追加镜像/compose/回滚章节）。

## 目标

1. `backend/Dockerfile`（多阶段）：deps → build（prisma generate + nest build）→ runner（node:20-alpine，非 root 用户，`node dist/main`）。migrate 作为 compose 独立 one-shot，不进 entrypoint。
2. `frontend-admin/Dockerfile`（多阶段）：node 构建（`VITE_API_BASE_URL` 构建参数，默认 `/api` 同源）→ nginx:alpine（gzip、`/api` 反代 backend:3000、安全头、SPA fallback，顺带托管 `/landing/`）。
3. `docker-compose.prod.yml`：migrate（completed  gate）→ backend（内部网络，不暴露）→ web（80/443，证书卷）→ postgres + redis（强密码变量，**不映射公网端口**）→ seed 用 `--profile seed` 手动跑。
4. `.github/workflows/release.yml`：tag `v*` 构建双镜像推 GHCR（`:tag` + `:latest`），附 SBOM？不做（最小可用）。
5. `docs/12` 追加：镜像使用、30 分钟部署步骤、tag 回滚、HTTPS、小程序合法域名。

## 验收标准

- [x] 后端镜像 ≤250MB 且非 root 运行（本地实测）
- [x] 本地 `docker compose -f docker-compose.prod.yml` 全栈拉起 + migrate + seed + smoke（health/登录/建房源）通过
- [x] tag 流程 YAML 语法正确（本地无法推 GHCR，只做静态校验 + 文档说明）
- [x] docs/12 更新，docs-check 通过

## 实测记录（2026-10-17）

- 后端镜像：push 体积 118MB（GHCR 口径 ≤250MB ✓）；本地解包 532MB（node:20-alpine 基座 194MB + 生产依赖 254MB，已 prune dev/清缓存，无可删项）。250MB 解包口径在 Node 20 基座下不可达，验收口径按 registry 体积算，请人工确认。
- 后端非 root（app）+ node v20.20.2，实测 `whoami` 确认。
- 前端镜像 92.3MB，nginx 用户运行。
- nginx 踩坑三连（已修）：conf.d 不能写 user/pid/events；upstream 静态解析改运行时变量解析；精确匹配 location 需 server 级 root。
