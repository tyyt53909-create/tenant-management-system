# T191: 清理死代码与独立邀请码表治理（OPT-18）

依据优化计划 OPT-18。分支从 `feature/T190-type-safety` 拉出。

## 目标

1. **清理死代码**：
   - 彻底删除未被任何路由或业务模块引用的 `BuildingGuard`（`backend/src/common/guards/building.guard.ts`）。
   - 全面扫描仓库，确保无任何未被引用的 guard 或 service。
2. **独立 InviteCode 实体与数据库迁移**：
   - 新增 `InviteCode` 数据表（一码一记录，包含 code, role, status, notes, creatorId, usedById, usedAt, expiresAt 等字段）。
   - 编写并执行 Prisma 数据库迁移，平滑迁移 `User.inviteCode` 历史数据，解除邀请码对 `User` 记录的耦合。
3. **修复批量邀请码覆盖缺陷（待确认清单 §19）**：
   - 支持批量生成 $N$ 个独立邀请码，每个邀请码均可被各自独立使用一次（保证一次性语义）。
   - 完善邀请码过期检查、作废状态流转与使用原子标记。
4. **管理端邀请码全生命周期管理接口与后台界面**：
   - 提供 `GET /api/auth/invite-codes`（分页查询、状态筛选、模糊检索）。
   - 提供 `POST /api/auth/invite-codes`（支持批量生成、有效期与备注）。
   - 提供 `DELETE /api/auth/invite-codes/:id`（作废未使用邀请码）。
   - 管理后台支持查看邀请码列表、批量生成与作废操作。
5. **保证系统兼容性与既有测试通过**：
   - 现有注册、Google GIS 登录、邮箱验证码登录与延迟绑定邀请码流程无缝衔接。
   - 所有测试全绿通过，OpenAPI 规范保持同步。

## 验收标准

- [x] 一次批量生成 N 个邀请码，N 个都可以各自使用一次
- [x] 后台可以查看邀请码列表与使用状态，并可以作废
- [x] 仓库里没有未被引用的 guard / service
- [x] 后端测试、E2E 测试、OpenAPI 检查与前端测试全绿通过
