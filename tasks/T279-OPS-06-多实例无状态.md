# T279：无状态化与多实例验证（OPS-06）

## 背景

ISS-33 / ISS-49：上传写本地 volume、README 曾宣称多实例；会话/OTP/限流依赖 Redis，但 `RedisService.connect()` 在并发调用时直接返回（`started` 标志），后到的模块（如 `REFRESH_STORE`）可能在 Redis 未 ready 时退化成内存会话，导致多实例刷新令牌失效。

## 范围

- 修复 `RedisService.connect()` 并发语义：共享同一个连接 Promise，后到调用等待 ready；不再用 `started` 提前返回。
- 启动校验：`MULTI_INSTANCE=true` 时必须 `STORAGE_DRIVER=s3`（本地 uploads 不跨实例共享）；生产/预发违反直接拒绝启动。
- readiness：对象存储模式下不再把本地 uploads 目录当依赖。
- 环境变量：`MULTI_INSTANCE`、`INSTANCE_ID`，两套模板同步。
- 集成测试：同一进程两个 Nest 实例共享 DB/Redis，A 登录的 access token 可在 B 使用，A 的 refresh token 可在 B 轮换。
- 文档：新增 `docs/24-多实例运行约束.md`，补充 docs/12 与 INDEX。
- 测试基建：集成 harness 安装 `cookie-parser`，与 main.ts 对齐。

## 非目标

- 真正部署两个容器做压测（OPS-09 性能基准）。
- 对象存储迁移/历史文件搬迁（SEC-07 / OPS-06 后续）。
- 粘性会话、共享文件系统方案。

## 验收

| # | 标准 | 验证 |
|---|---|---|
| 1 | 并发 `connect()` 共享同一连接 Promise | 代码审查 + 集成 |
| 2 | 实例 A token 在实例 B 可用，refresh 可在 B 轮换 | 集成 |
| 3 | `MULTI_INSTANCE=true` + 本地存储在生产被拒 | 单元 |
| 4 | S3 模式 readiness 不检查本地 uploads | 单元/代码 |
| 5 | 全量单测、lint、tsc、e2e、集成通过 | `tasks/evidence/T279.md` |

## 风险

- 连接 Promise 失败后会清空，后续调用可重试；生产仍会在失败时拒绝启动。
- `MULTI_INSTANCE` 仅做启动约束，不自动迁移历史本地文件。
- 多实例 cron 仍依赖咨询锁；队列模式下由 `QUEUE_PREFIX` 保证同队列。
