# T284：公告与定向消息（COM-04）

## 背景

ISS-28：通知只有站内一条条发，没有「一次发给一群人」的能力。管理员发停水停电、缴费提醒、
规则变更时只能逐个用户建通知，无法回答「这次发给了谁、送达多少人、有没有重发过」。

## 范围

- 新增 `announcements` 表（`AnnouncementStatus` / `AnnouncementAudience` 枚举、`targetIds` 数组）。
- 受众解析：全部在租租客 / 按楼栋（ACTIVE 合同）/ 按标签 / 指定租客；只统计有登录账号的租客。
- 发布复用通知中心：站内通知 + WebSocket 实时推送；去重键保证重发幂等。
- 管理接口：列表、详情、创建（可立即发布）、编辑（仅草稿）、发布/重发、归档、删除（仅草稿）。
- 管理后台 `/announcements` 页面：状态筛选、定向目标选择（楼栋/标签/租客远程搜索）、发布结果提示。
- 集成测试（真实 DB）覆盖定向解析、幂等重发、生命周期约束与越权。
- 文档 `docs/29-公告与定向消息.md`，同步 docs/02/03/05/INDEX。

## 非目标

- 定时发布（`publishAt` 保留字段，未接调度）。
- 公告已读统计/送达回执。
- 短信/微信订阅消息通道（WX-02 / WX-03）。
- 富文本与附件。

## 验收

| # | 标准 | 验证 |
|---|---|---|
| 1 | 定向公告只投递给目标租客 | 集成（BUILDING / TAGS） |
| 2 | 重发幂等，同一公告不重复投递 | 集成 |
| 3 | 已发布公告不可编辑/删除，只能归档 | 集成 + 单元 |
| 4 | 目标 ID 不存在或缺失 → 400，不落库 | 单元 |
| 5 | CLEANER / TENANT 访问公告接口 → 403 | 集成 |
| 6 | 全量门禁通过 | `tasks/evidence/T284.md` |

## 风险

- 受众是发布时刻快照，发布后新增租客需手动重发。
- 逐个用户投递，租客规模大时发布耗时线性增长；批量投递可后续走队列（OPS-05 通道）。
- `targetIds` 用数组存储，没有外键约束；删除楼栋/标签后旧公告仍保留原 ID（仅历史展示）。
