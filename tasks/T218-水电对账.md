# T218: 水电对账

## 背景

`docs/00-项目计划书.md` §2.2 把「水电对账」列为第二阶段（第一版数据量小、手动对账）。
智能表接入（ADR-003）之前，更需要一个能验证「读数 → 扣费 → 账单」三方一致的只读对账视图。

## 范围

- 接口：`GET /meters/reconciliation?period=YYYY-MM&buildingId=&meterType=`（仅 ADMIN，未传账期默认上个月）
- 对账维度（每块表一行）：
  1. **读数**：当月末读数 − 月初读数，与逐笔读数 `usage` 合计比对（暴露乱序、补录、覆盖）
  2. **扣费**：该表读数关联的预付账户扣费流水合计
  3. **账单**：快照中 `readingId` 指向这些读数的 UTILITY 账单合计
  4. **应收** = 用量 × 单价；`difference = 扣费 + 账单 − 应收`
- 汇总：表数、有问题表数、三项合计与总差额
- 模拟读数不计入（与结算口径一致）

## 验收标准

| # | 标准 | 验证 |
|---|---|---|
| 1 | 三方一致时 difference=0、无问题 | `meter-reconciliation.service.spec.ts` |
| 2 | 扣费与应收不等时列出差额 | 同文件 |
| 3 | 读数差值与落库用量不一致时提示 | 同文件 |
| 4 | 读数不足两笔 / 无表时行为正确 | 同文件 |
| 5 | 仅 ADMIN 可访问 | `authorization.e2e-spec.ts`「水电对账（T218）」 |
| 6 | OpenAPI 无漂移 | `npm run openapi:check` |
