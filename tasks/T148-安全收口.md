# T148 安全收口

## 背景（均为实测，非推测）
| 编号 | 问题 | 实测证据 |
|---|---|---|
| S1 | `GET /api/tenants` 无 `@Roles`，`RolesGuard` 缺省放行 | CLEANER 与 TENANT 均返回 200（应 403），可读取全部租客手机号 |
| S2 | seed 无 `NODE_ENV` 守卫 | 生产会创建 `admin@example.com/Admin@123`、`cleaner@example.com/Cleaner@123` |
| S3 | 邀请码服务无 HTTP 入口 | `InviteCodeService.generateInviteCode` 存在但无路由，生产无法发放邀请码 |
| S4 | 注册第二个租客必 500 | `Tenant.phone` 为 `@unique`，注册写空串 `''`，第二个空串触发唯一约束冲突 |

## 交付物
- `backend/prisma/seed.ts`：production 下必须显式提供 `ADMIN_`/`CLEANER_` 账号环境变量，否则拒绝创建默认账号；配套 `prisma/seed.spec.ts`（8 用例）。
- `tenants.controller.ts`：`GET /tenants`、`GET /tenants/:id` 收紧为仅 ADMIN。
- 同类审计：`buildings` / `meters` / `rooms` / `checkout` 等 controller 中「有 `JwtAuthGuard` 但无 `@Roles`」的 GET 路由逐条按 `docs/03-权限矩阵.md` 判定。
- `checkout`：新增 `findByTenant` / `findOneForTenant`，租客仅可见自己的退租记录（越权 404）。
- 新增 `POST /api/auth/invite-codes`（仅 ADMIN），复用既有服务方法。
- 修复 S4：注册时若缺 phone 则生成唯一占位值。
- 新增 `backend/test/authorization.spec.ts`（32 用例，含真实 `RoomsService` 保洁/租客房源隔离）。
