# T294：微信支付退款、日终对账与差异处理（PAY-02）

## 背景与目标

根据生产化路线图（docs/19 §4/§5 里程碑 M3）与架构决策 DEC-04，在完成线上微信支付 JSAPI 收款（T293 / PAY-01）的基础上，建立线上收款的退款闭环与日终自动对账机制。

本任务依托 T293（PAY-01 微信支付基础设施与服务通道）与 T264/T265（财务资料不可硬删除、冲正机制）：
1. **统一支付通道退款抽象扩展（`PaymentProvider`）**：
   - 扩充 `PaymentProvider` 契约，支持退款申请 `createRefund`、退款查询 `queryRefund`、退款异步回调通知验签与解密 `verifyAndParseRefundNotify`。
   - 在 `WechatPaymentProvider` 中实现微信 API v3 国内退款规范（`POST /v3/refund/domestic/refunds`），支持 API v3 构造请求签名与 AEAD_AES_256_GCM 退款通知报文解密。
   - 在 `MockPaymentProvider` 中支持自洽模拟退款申请、状态查询与退款成功/异常通知生成。
2. **管理员发起退款与账单财务冲正联动**：
   - 暴露 `POST /api/bills/:id/payments/:paymentId/refund`（仅管理员 `@Roles('ADMIN')`）：
     - 校验目标付款记录存在、来源渠道为 `WECHAT`、处于已生效状态。
     - 校验退款金额（`amount > 0` 且累计退款不得超过收款原额）。
     - 调用微信支付退款接口成功后，在本地记录退款明细，并通过财务冲正逻辑（或负向收款记录）冲减账单已缴金额 `paidAmount`（状态重算为 PARTIAL 或 PENDING），若是押金账单同步冲减押金台账。
     - 具备幂等性防护：相同 `outRefundNo` 重复调用返回相同退款结果。
3. **退款异步结果通知回调**：
   - 暴露 `POST /api/payments/wechat/refund-notify`（公开路由 `@Public()`）：
     - 验签并解密微信支付退款结果报文，确认退款成功状态。
4. **日终自动对账与差异报表（Reconciliation）**：
   - 扩充支付服务对账功能：调用微信支付对账单下载接口（或 Mock 模式下生成当日交易凭据清单），与本地 `payment_records` 表中 WECHAT 渠道收款流水进行精确比对。
   - 比对状态分类：
     - `MATCHED`（平账：单号、交易号、金额完全一致）
     - `REMOTE_ONLY`（微信单边账：微信有记录但本地漏单，支持触发自动补账入账）
     - `LOCAL_ONLY`（本地单边账：本地有记录但微信无凭单，标红可疑交易）
     - `AMOUNT_MISMATCH`（金额不一致）
   - 暴露管理端对账接口 `POST /api/bills/reconciliation/wechat`（仅管理员 `@Roles('ADMIN')`），支持传入指定日期 `billDate` 触发对账并返回结构化差异报表。
5. **测试保障与证据**：
   - 包含完整的单元测试、覆盖率检查及真实 PostgreSQL 集成测试。
