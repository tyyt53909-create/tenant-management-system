# T294：退款、对账与差异处理（PAY-02）

## 背景与目标

根据生产化路线图（docs/19 §4/§5 里程碑 M3），在 T293（PAY-01 微信支付 JSAPI 线上收款）落地后，建立完善的资金流安全闭环——涵盖线上原路退款、微信退款异步通知处理、日终交易对账单下载与比对、差异台账登记与掉单自动补账。

本任务依托 T293 沉淀的 `WechatPaymentProvider` API v3 验签解密基石与 `BillPaymentService` 严密财务入账机制：
1. **线上原路退款闭环**：
   - 增加 `RefundRecord` 数据模型，记录商户退款单号 `outRefundNo`、微信退款单号 `refundId`、退款金额（分）、退款原因与状态（`PROCESSING` / `SUCCESS` / `FAILED`）。
   - 扩展 `PaymentProvider` 接口：增加 `createRefund` 与 `queryRefund` 契约，支持微信 API v3 `POST /v3/refund/domestic/refunds`。
   - 实现退款异步通知端点 `POST /api/payments/wechat/refund-notify`（公开路由 `@Public()`），严格验签解密，退款成功后自动驱动财务冲正（`REVERSAL` 负数冲正记录，若涉及押金账单则同步核减押金台账余额，财务记录绝不硬删除）。
2. **微信支付日终对账单比对引擎**：
   - 扩展 `PaymentProvider`：支持微信官方交易对账单下载接口 `GET /v3/bill/tradebill` 解析 CSV 对账流水；`MockPaymentProvider` 提供自洽对账单生成器。
   - 新建对账台账表 `PaymentReconciliationBatch` 与 `PaymentReconciliationItem`，按指定自然日执行双向比对。
   - 精确识别四种对账差异状态：
     - `SYSTEM_MISSING`：微信有流水，本地无记录（掉单）。
     - `WECHAT_MISSING`：系统有收款记录，微信无记录。
     - `AMOUNT_MISMATCH`：金额不一致。
     - `STATUS_MISMATCH`：状态不一致。
3. **差异处理与补单机制**：
   - 管理端提供对账触发端点 `POST /api/payments/reconciliation/run` 与批次列表/明细查询端点。
   - 提供差异处理端点 `POST /api/payments/reconciliation/items/:id/resolve`，支持对 `SYSTEM_MISSING` 掉单触发安全自动补账入账，或人工复核平账。
4. **测试保障与契约同步**：
   - 补充单元测试、覆盖率检查及真实 PostgreSQL 数据库测试。
   - 更新 OpenAPI 快照与白名单，全套门禁保持全绿。
