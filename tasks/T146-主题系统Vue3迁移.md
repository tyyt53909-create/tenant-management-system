# T146 主题系统迁移至 Vue 3（reactive）

## 背景

主工作区存在一套未提交的主题系统（约 1,180 行），采用 **Vue 2 / Vuex** 写法。
T145 已将小程序修正为 **Vue 3（createSSRApp + Vue 3.4.21）**，两者冲突：

| 冲突点 | 原主题写法 | T144/T145 架构 |
|---|---|---|
| 应用入口 | `new Vue()` / `Vue.prototype` / `App.mpType` | `createSSRApp(App)` |
| 状态管理 | Vuex（`store/` 目录） | 无状态库；`utils/session.js` 纯函数 + uni storage |
| 用户态 | `store/index.js` 管 userInfo/token | `utils/session.js` 管 access_token/refresh_token/user_role |
| 依赖版本 | `^3.0.0` 浮动 | `3.0.0-5020620260917001` 精确锁定 |

其中 `store/index.js` 的 userInfo/token 逻辑与 `utils/session.js` **完全重复**，
若引入 Vuex/Pinia 会让小程序同时存在两套状态管理机制。

## 决策

**不引入任何状态管理库**，将主题状态改为基于 Vue 3 `reactive()` 的轻量响应式模块，
与 `utils/session.js` 的"工具函数 + uni storage"模式保持一致。

## 交付物

| 文件 | 变更 |
|---|---|
| `miniprogram/store/` | **删除**（theme.js、index.js 整体移除） |
| `miniprogram/utils/theme.js` | 重写：`reactive` 状态 + getter/setter + `themeMixin` + 原工具函数 |
| `miniprogram/components/ThemeSelector.vue` | 改用 `computed` 读取 `themeState`；**修复导入路径** |
| `miniprogram/pages/theme/theme.vue` | 统一使用 `themeMixin` 提供的 `theme` |
| `miniprogram/App.vue` | `onLaunch` 调用 `initTheme()`（替换 `store.dispatch('init')`） |
| `miniprogram/tests/theme.test.mjs` | 新增 12 项测试 |
| `miniprogram/theme/README.md` / `QUICKSTART.md` | 同步 Vuex → reactive 用法 |

### 导出接口

```javascript
themeState                    // 响应式状态 { currentTheme, isDarkMode }
getTheme()                    // 完整主题配置（含夜间模式颜色覆盖）
getThemeName() / isDark()     // 读取
setTheme(name) / setDarkMode(bool) / toggleDarkMode()
initTheme()                   // 从 storage 恢复
themeMixin                    // options API 便捷接入
```

## 保留语义（未改动）

- 从 `uni.getStorageSync('theme')` / `('darkMode')` 恢复
- 夜间模式**仅覆盖 colors**，其余字段继承 baseTheme
- `generateCSSVariables` 与 `camelToKebab` 逻辑逐字未变

## 顺带修复

`components/ThemeSelector.vue` 原导入路径为 `../../theme/tokens.js`，
但 `components/` 的上一层即项目根，`../../` 会跳出项目 —— **构建必失败**。
原主题代码从未构建验证过，因此该问题一直未暴露。已改为 `../theme/tokens.js`。
