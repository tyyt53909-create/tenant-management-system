# T272：账单状态拆分、滞纳金按日、催缴节点（FIN-04）

## 背景

ISS-17：`Bill.status` 同时表达「缴付进度」和「是否逾期」——
- `PARTIAL` 收款后若账单逾期，状态仍是 `PARTIAL`；定时任务又把它改成 `OVERDUE`，缴付进度被覆盖。
- 作废收款时用 `dueDate < today` 反推 `OVERDUE`，与收款路径的状态计算不一致。
- 滞纳金由定时任务每天「刷新一条建议」，没有按日累计的分日记录，无法核对某天该收多少。
- 逾期当天 `checkOverdueBills` 直接发 `BILL_OVERDUE:{user}:{bill}`，与提醒任务的 `overdue-d1` 节点重复。

## 范围

### 1. 状态拆分

- `Bill` 增加 `isOverdue Boolean`、`overdueDays Int`；`status` 只表示缴付进度：`PENDING / PARTIAL / PAID / CANCELLED`。
- 迁移：现有 `status='OVERDUE'` 的账单按 `paidAmount` 回填为 `PENDING`/`PARTIAL`，同时 `isOverdue=true` 与 `overdueDays`。
- `OVERDUE` 枚举值保留（历史兼容），但服务不再写入。
- 收款/作废：`PAID` 时清空 `isOverdue/overdueDays`；`PARTIAL` 保留逾期标记。
- 列表筛选：`GET /bills?overdue=true`；`status=OVERDUE` 作为兼容参数映射到 `isOverdue=true`（返回 `PENDING/PARTIAL`）。

### 2. 滞纳金按日累计

- 新增 `LateFeeAccrual`（billId + accrualDate 唯一，金额分）：每日任务按「累计应付 − 前一日累计」写当日增量，重复执行幂等。
- 当日增量 = `LateFeeUtil.calculate(rule, base, today) - calculate(rule, base, today-1)`，封顶后归零。
- 未确认建议值仍由 `LateFee` 承载，刷新为累计应计；确认/核销逻辑不变。
- 部分收款导致 base 变化时，未来增量按新 base 计算；历史 accrual 不重写。

### 3. 催缴节点

- 逾期检查只更新 `isOverdue/overdueDays`、写 accrual、刷新建议，不再发即时逾期通知（避免与 `overdue-d1` 重复）。
- 提醒任务覆盖 −3 / 0 / +1 / +3 / +7 节点，去重键含节点维度；查询改用 `PENDING/PARTIAL` + `isOverdue`。

### 4. 指标与前端

- 统计、管理摘要、仪表板「逾期账单」改用 `isOverdue` 计数。
- 账单列表：逾期行显示「逾期 N 天」；「逾期」Tab 走 `overdue=true`；金额与状态标签不再依赖 `OVERDUE`。
- 前端类型补 `isOverdue` / `overdueDays`。

### 5. 测试与文档

- 单元：状态推导、每日增量、accrual 幂等、提醒去重、统计口径。
- 集成（真实 DB）：逾期账单迁移语义（新建后跑日任务 → isOverdue=true 且 status 不变）、`overdue=true` 筛选、重复跑任务只产生一条 accrual。
- 文档：`docs/02` Bill/LateFeeAccrual、`docs/04` 账单状态机、`docs/05` §7.6.9、`docs/21` 逾期口径、`docs/INDEX`。

## 风险

- 迁移会改写现有 `OVERDUE` 行状态；必须先备份并核对 `paidAmount` 语义。
- 外部系统/脚本若按 `status=OVERDUE` 过滤，需改用 `overdue=true`（本任务保留兼容映射）。
- 滞纳金 accrual 与已确认 LateFee 并存，报表需明确「应计」与「已确认」不是同一个数。
- 部分收款后 base 变化：历史 accrual 保持原值，可能出现累计应计与 `LateFeeUtil` 当前累计不一致，需在页面注明。
