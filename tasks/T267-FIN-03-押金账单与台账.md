# T267：押金账单与押金台账（FIN-03）

## 背景

UAT 第 6 步要求「生成押金账单并收款 → 押金台账余额 = 押金」。当前 `BillType` 没有押金类型，押金金额只存在合同字段里，收款后无法追踪押金在管余额，也无法扣除/退还/转移（DEC-09 允许押金转入续签）。

## 范围

### 1. 数据模型

- `BillType` 增加 `DEPOSIT`。
- 新增 `DepositLedger`（每合同一本，`contractId @unique`）：
  - `amount` 应缴押金、`balance` 在管余额、`status`（`HELD` / `PARTIAL` / `REFUNDED`）。
- 新增 `DepositTransaction`：`COLLECT` / `REFUND` / `DEDUCT` / `TRANSFER` / `REVERSAL`，记录 `amount`（正入负出）与 `balanceAfter`。
- 迁移 `20261024210000_deposit_ledger`；表数 35 → 37。

### 2. 账单与收款

- `POST /bills` 支持 `billType=DEPOSIT`；同一合同仅一张押金账单（`dedupKey=DEPOSIT:{contractId}`）。
- 押金账单收款时，在同一事务内写 `COLLECT` 并累加台账余额；余额 ≥ 应缴时 `HELD`，否则 `PARTIAL`。
- 作废押金收款时写 `REVERSAL` 并扣回余额（不为负）。

### 3. 台账接口

- `GET /deposits/:contractId`：ADMIN 任意；TENANT 仅自己的合同（否则 404）。
- `POST /deposits/:contractId/deduct`：ADMIN，扣减押金；余额不足 400。
- `POST /deposits/:contractId/refund`：ADMIN，退还押金；余额归零时 `REFUNDED`。
- `POST /deposits/:contractId/transfer`：ADMIN，将余额转入续签合同（DEC-09）。

### 4. 测试

- 单元：押金台账写入/冲正（非 DEPOSIT 忽略、累加、收满 HELD、冲正不为负）。
- 集成（真实 DB）：押金账单 20 万 + 10 万收款 → 余额 30 万 HELD；扣 5 万、退 25 万 → 0 REFUNDED；作废收款 → 余额回退。

## 非目标

- 退租结算单自动读取押金台账（FIN-07 / T273）。
- 押金收据 PDF（PAY-03）。
- 押金利息、跨合同部分转移的复杂分摊。
- 历史合同押金回填（无押金流水，按 0 处理）。

## 风险

- 押金账单可被部分收款；台账按实收累计，不强制一次收满。
- 历史合同没有押金台账；需要时由 ADMIN 先建押金账单再收款。
- 转移接口未校验目标合同租客一致；当前单组织，若跨租客转移需人工复核。
- 退租结算仍不自动扣减押金（T273 接入）。
