# T206: 安全与权限修复（全专案审查第一轮）

修复全专案审查（七角度 + 逐条验证）中 P0/P1 级的安全与权限缺陷。

## 背景

审查发现的最严重一类问题：授权判定在某些路径上被绕过或依赖配置是否「刚好没设」。四条已确认缺陷：

1. **档案下载越权（IDOR）**：`files.controller.ts` 的 `?expiresIn=` 分支在调用 `assertCanRead` **之前**就 `return`，任何已登入用户可取得他人档案的签名 URL；生产用 OSS 时那是可直接下载的真预签名位址。
2. **OTP 路由失去每 IP 限流**：`OtpEmailThrottle` 把 `default` 限流器的 tracker 换成 email，而 throttler 每条路由对每个命名限流器只保留一个 tracker → 未登入者可换不同邮箱对不限数量收件人寄验证码信。
3. **Google 模拟登入后门**：mock 分支仅以 `NODE_ENV !== 'production'` 把关，未配 `GOOGLE_CLIENT_ID` 时以 `mock-google-token:<email>` 冒充既有帐号；与 OTP 万能码的「双开关」设计不对称。
4. **登入页硬编码种子帐密**：`login/index.vue` 预填 `admin@example.com` / `Admin@123` 并随生产 bundle 发布（违反 AGENTS.md §8.1）。

## 目标

四条全部修复 + 补测试（含「修复前会红」的回归验证）+ 文档同步。

## 验收标准

- [x] `?expiresIn=` 分支先过 `assertCanRead`；新增 `files.controller.spec.ts` 5 例，且已验证在修复前代码上会失败。
- [x] 发送验证码同时受「每邮箱 5/小时」与「每 IP 30/小时」（`THROTTLE_OTP_IP_LIMIT`）两层限制；新增「换邮箱不能绕」回归测试。
- [x] 模拟 Google 登入需 `GOOGLE_AUTH_MOCK=true` 且非 production；未开时明确报错而非静默按 mock；前端入口改由后端 `mockEnabled` 决定。
