# T287：小程序工程化：分包、隐私、型别、页面测试（FE-02）

## 背景

ISS-29：小程序 12 个页面全在主包，无 `lazyCodeLoading`；从未处理微信隐私授权
（`chooseImage` / 剪贴板 / 保存相册均属隐私接口）；`api/**`、`utils/**` 无类型检查；
合同、账户、主题、通知、详情页没有页面测试。

## 范围

- 分包：`packageA` 收纳合同/账户/主题/通知/账单详情/报修进度；主包只留 4 个 tab + 保洁 + 登录。
- `preloadRule` 首页与个人中心预下载；`manifest.json` 开启 `lazyCodeLoading`。
- 隐私：`utils/privacy.js`（条目、文案、`installPrivacyHandler`、`withPrivacy`），报修页接入。
- 类型：`tsconfig.json` + `globals.d.ts`，`npm run typecheck` 纳入 CI；修正 request/upload/theme/voucher 类型问题。
- 页面测试：`tests/pages-extra.test.mjs` 覆盖通知/账户/合同/主题；`tests/subpackage.test.mjs` 校验包结构与跳转；`tests/privacy.test.mjs`。
- 测试基建：`tests/_page-loader.mjs` 按逻辑名跨主包/分包定位页面。
- 修正 `SpaceMiniMap` 楼栋排序依赖 ICU 的不确定性。
- 文档 `docs/32-小程序工程化.md`，同步 INDEX。

## 非目标

- `wx.login` / 订阅消息 / 微信支付（WX-01、PAY-01）。
- 填入真实 appid 与服务器域名（需人工）。
- 主包体积硬阈值门禁（当前产物 <1MB）。
- `.vue` 模板类型检查。

## 风险

- 分包路径变更影响所有跳转；已由 `subpackage.test.mjs` 静态校验。
- 隐私弹窗文案需与小程序后台《隐私保护指引》人工保持一致。
- `ctx.setLineDash` 补 `offset` 参数后，微信与 H5 表现一致（均为 0 偏移）。
- 类型检查只覆盖 JS 工具与 API 层，页面脚本靠 node:test。
