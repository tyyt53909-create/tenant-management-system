# T277：可观测性：日志、指标、错误追踪与告警（OPS-04）

## 背景

ISS-31 / ISS-32：只有 `/health` 与 stdout 日志；没有业务指标、没有告警通道；`JobRun` 在子任务失败时仍记 `SUCCESS`（`SchedulerService` 收集 errors 后继续）；咨询锁固定 30 分钟。

## 范围

### 1. 指标（Prometheus 文本格式，零外部依赖）

- 新增轻量 `MetricsRegistry`（counter / gauge / histogram），`MetricsService` 暴露：
  - `app_http_requests_total{method,route,status}`
  - `app_http_request_duration_seconds{method,route}`（0.05/0.1/0.3/1/3/5/10）
  - `app_scheduler_runs_total{job,status}`
  - `app_bills_overdue`（每日任务后更新）
  - `app_process_uptime_seconds`、`app_process_resident_memory_bytes`
- `GET /api/metrics`：
  - 设置 `METRICS_TOKEN` 时要求 `Authorization: Bearer <token>`（或 `?token=`），否则 401；
  - 未设置 token 时仅非 production/staging 暴露，生产返回 404；
  - 路由 `@Public()` + 跳过限流，避免 Prometheus 抓取被 JWT 拦住。

### 2. 错误追踪与告警

- 新增 `AlertService`：`ALERT_WEBHOOK_URL` 通用 JSON webhook；按标题 + 去重键限频（`ALERT_MIN_INTERVAL_MS`，默认 60s）；无 URL 时只记结构化日志。
- 5xx 经 `AllExceptionsFilter` 发告警（含 requestId、method、path、status，不含请求体/个资）。
- 定时任务失败/部分失败发告警；`SchedulerService` 的 errors 非空即告警。
- 外部 SDK（Sentry 等）暂不引入；webhook 可对接任意告警平台。

### 3. JobRun 真实性

- `JobRunStatus` 增加 `PARTIAL`；`JobRunner` 在结果含非空 `errors` 时记 `PARTIAL`，不再伪装 `SUCCESS`。
- 全量失败仍 `FAILED` 并上抛；跳过仍 `SKIPPED`。
- `SCHEDULER_LOCK_TTL_SECONDS`（默认 900）替换硬编码 30 分钟，并在 docs/12 记录。

### 4. 测试与文档

- 单元：registry 计数/直方图/文本转义、`/metrics` token 与生产开关、Alert 限频与无 URL、JobRunner PARTIAL、5xx 告警接线。
- 集成（真实 DB）：`/metrics` 带 token 200、无 token 401、生产无 token 404（用配置覆盖）。
- 文档：新增 `docs/22-可观测性与告警.md`；`docs/02` JobRun、`docs/05` metrics 端点、`docs/12` 环境变量、`docs/INDEX`。

## 非目标

- 接入 Prometheus/Grafana/Loki 实例（部署侧）。
- Sentry/OpenTelemetry 分布式追踪。
- 日志采集与轮转（stdout 由容器负责）。
- 业务告警规则编排（逾期率、5xx 阈值等，后续 OPS-09）。

## 风险

- `/metrics` 可能泄露路由与业务规模；生产必须设置 `METRICS_TOKEN` 或由网关限制访问。
- webhook 在故障时同步失败不影响主流程（异步 + 超时），但可能丢告警；后续接 OPS-09 告警平台。
- `PARTIAL` 是新增枚举值，历史看板需按 `status != SUCCESS` 统计失败。
- 锁 TTL 调小可能让长任务并发（任务本体在锁事务内执行，TTL 必须大于最长任务耗时）。
