# T261：文件与附件模型（SEC-07）

## 背景

ISS-06：公开看房页的照片仍指向 `/api/files/:key`，该路由要求 JWT，匿名访客必然加载失败；同时 `FileAsset` 只有「上传者」概念，缺少用途、可见性与归属对象，无法安全地把房源照片公开，也无法区分合同、报修、收据等附件。

本任务把文件从「上传即孤岛」升级为可被业务引用的附件模型：**私有默认、公开显式授权、按用途与归属校验**。

## 范围

### 1. 数据模型（expand）

`FileAsset` 新增：

- `purpose`（`FilePurpose` 枚举：`ROOM_PHOTO` / `CONTRACT` / `MAINTENANCE` / `AVATAR` / `RECEIPT` / `OTHER`，默认 `OTHER`）
- `visibility`（`FileVisibility` 枚举：`PRIVATE` / `PUBLIC`，默认 `PRIVATE`）
- `ownerType`（可空字符串，如 `ROOM` / `CONTRACT` / `MAINTENANCE`）
- `ownerId`（可空字符串）
- `thumbnailKey`（可空，缩略图对象键）
- `@@index([ownerType, ownerId])`、`@@index([visibility])`

迁移 `20261024180000_file_asset_attachment`：

- 加枚举与列（带默认值）；
- 把 `room_photos.file_url` / `thumbnail` 中引用的对象键回填为 `purpose=ROOM_PHOTO`、`visibility=PUBLIC`、`ownerType=ROOM`、`ownerId=<roomId>`。

### 2. 上传与下载

- `POST /api/files/upload` 支持 `purpose`、`visibility` 查询参数：
  - `purpose` 必须是枚举值；
  - `visibility=PUBLIC` 仅 **ADMIN** 允许（普通用户只能上传私有文件）；
  - 响应增加 `id`、`purpose`、`visibility`、`thumbnail`。
- 私有下载 `GET /api/files/:key` 保持归属校验：ADMIN、上传者本人、或同一 `tenantId` 的租客；越权仍 404。
- 新增公开下载 `GET /api/public/files/:key`（无鉴权）：
  - 仅返回 `visibility=PUBLIC` 的对象；
  - 缓存 `public, max-age=3600`，带 `nosniff` 与正确 `Content-Type`；
  - 非公开/不存在统一 404，不泄露存在性。

### 3. 房源照片

- `RoomPhotoDto` 同时接受 `/api/files/<key>` 与 `/api/public/files/<key>`。
- 房源创建/更新时校验每个照片/缩略图对应的 `FileAsset` 存在；不存在或外部链接直接 400。
- 绑定照片时把资产置为 `purpose=ROOM_PHOTO`、`visibility=PUBLIC`、`ownerType=ROOM`、`ownerId=<roomId>`，确保公开页可读。
- 公开房源接口把历史 `/api/files/` 地址改写为 `/api/public/files/`，旧数据无需重传。

### 4. 路由与文档

- `backend/test/route-policy.snapshot.json` 增加 `/api/public/files/:key`（public）。
- `docs/02` FileAsset 章节与实现对齐；`docs/03` 公开面增加公开文件；`docs/05` 文件接口与可见性；`docs/19` SEC-07 置 active；`docs/INDEX` 登记。
- `openapi.json` 与前端类型重新生成。

## 风险

- 公开文件是**永久可读**（对象键不可猜测但不等于授权撤销）；撤回公开需显式改回 PRIVATE，缓存最长 1 小时。
- 迁移会把所有被 RoomPhoto 引用的资产置为 PUBLIC；若库中存在误引用的敏感文件，需人工复核。
- `RoomPhoto.fileUrl` 冗余列保留，公开 URL 在响应层改写；contract 阶段再统一。
- S3 驱动下服务端代理下载会增加流量，后续可切 CDN/直签。
