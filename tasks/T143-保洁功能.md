# T143: 保洁功能（CLEANER 角色闭环）

## 背景

`docs/09-待确认清单.md` #3 已确认保洁需求：**需要登录账号、使用小程序、可查看待清洁房间列表、标记已清洁（可选上传照片）、不可见租客信息**。`docs/03-权限矩阵.md` 定义了保洁的可见范围（仅待清洁房间）与「房间变为待清洁 → 通知保洁（所有）」；`docs/04-状态机.md` §1 定义了 VACANT+PENDING_CLEAN → VACANT+CLEANING（接单）→ VACANT+CLEAN（完成）流转；`docs/05-接口规范.md` §8.2 已列 `PATCH /rooms/:id/clean`。

T139 已实现房态状态机（含 CLEANING→CLEAN），但保洁专属能力缺失：保洁账号无从创建、看不到待清洁列表（当前 GET /rooms 对所有角色返回全部房间）、无法接单/标记完成、房屋转待清洁不通知保洁。本任务补齐后端闭环（保洁小程序页面留待联调阶段）。

## 任务范围

### 后端

1. **角色权限收紧**（`docs/03-权限矩阵.md`）：
   - `GET /rooms`：CLEANER 仅可见 `VACANT + (PENDING_CLEAN/CLEANING)` 房间；忽略 status 过滤参数
   - `GET /rooms/:id`：CLEANER 访问非待清洁房间 → 403
   - `PATCH /rooms/:id/status`：放行 CLEANER（流转表已天然限制其只能做 PENDING_CLEAN→CLEANING、CLEANING→CLEAN）
2. **`PATCH /rooms/:id/clean`**（ADMIN, CLEANER，docs/05 §8.2）：
   - 仅「清洁中」房间可标记完成（未接单 400，带提示）；VACANT+CLEANING → VACANT+CLEAN
   - `version` 可选（提供则乐观锁冲突 409）
   - 可选清洁照片（`photo.fileUrl/thumbnail/fileSize`）写入 `RoomPhoto`
3. **待清洁通知**：房间流转至 VACANT+PENDING_CLEAN 时，通知所有在职 CLEANER（NORMAL，`data.roomId`）；通知失败不阻断流转
4. **保洁账号**：seed 增加保洁测试账号（`CLEANER_EMAIL/CLEANER_PASSWORD` 可覆盖）；生产账号创建流程留待后续（见遗留）

### 测试与文档

5. `rooms.service.spec.ts`：+7 例（保洁列表过滤/详情 403/标记完成+照片/未接单 400/版本冲突 409/待清洁通知/无保洁账号不报错）
6. `docs/INDEX.md`、`STATUS.md`、交接记录；docs/03/04/05 已与实现对齐（无需修改，逐条核对）

## 决策记录

- **接单与完成分离**：遵循状态机 VACANT+PENDING_CLEAN → VACANT+CLEANING（接单，可用 `PATCH /:id/status`）→ VACANT+CLEAN（完成，用 `/:id/clean`）；`/clean` 不隐式接单，避免状态机被绕过
- **保洁列表强制过滤**：CLEANER 的列表条件由服务端固定，不信任查询参数（安全优先）；`status` 参数对 CLEANER 忽略
- **通知范围**：全部在职 CLEANER（多楼栋时按楼栋过滤留待多楼栋启用后扩展；当前 v1 单楼栋）
- **保洁账号创建**：v1 用 seed（开发/试用）；管理后台邀请保洁账号留待后续任务（register 固定 TENANT 角色）
- **照片**：直接接受已上传 URL（复用 files 模块），fileSize 缺省 0
