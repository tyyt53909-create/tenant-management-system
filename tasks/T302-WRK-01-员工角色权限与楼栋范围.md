# T302：员工角色、权限与楼栋范围（WRK-01）

## 背景与目标

根据生产化第二轮路线图（`docs/19-生产化路线图.md`）M4（全生命周期与协作）规划以及解决遗留缺陷 **ISS-47（单管理员模型，只有 3 个角色）** 与落实决策 **DEC-08（多角色：业主、楼管、财务、维修、保洁 + 楼栋范围）**，系统需要从原先简单的 3 角色（ADMIN, CLEANER, TENANT）升级为支持真实物业与租赁管理协作的完整多角色与楼栋管辖范围体系：

1. **员工多角色体系扩充（DEC-08 / ISS-47）**：
   - 扩充 `UserRole` 枚举：
     - `ADMIN`：系统超级管理员，全局配置与最高权限；
     - `PROPERTY_MANAGER`：楼管 / 管家，负责房源运营、带看、签约、验房交接、日常工单跟进；
     - `FINANCIAL`：财务人员，负责账单生成、线上线下收款、退款审批、日终对账与财务报表；
     - `MAINTAINER`：维修师傅，负责报修工单接单、现场维修与工单完工；
     - `CLEANER`：保洁人员，负责房源与公区保洁任务；
     - `OWNER`：房东 / 业主，只读查看名下楼栋房源状态、租约合同与经营收益；
     - `TENANT`：租客端。
2. **员工负责楼栋数据范围映射（StaffBuildingAssignment）**：
   - 新增 `StaffBuildingAssignment` 实体（表数扩充至 55 张表），建立员工与管辖楼栋的多对多关联；
   - 支持管家、维修、保洁、业主各自分配管辖的一栋或多栋楼宇；
   - `ADMIN` 默认具有全局所有楼栋范围权限。
3. **员工管理服务升级（StaffService & Controller）**：
   - 支持创建与更新全部员工角色（`PROPERTY_MANAGER`, `FINANCIAL`, `MAINTAINER`, `CLEANER`, `OWNER` 等）；
   - 支持在创建、更新或专属端点为员工指派负责楼栋列表（`assignedBuildingIds`）；
   - 提供 `GET /staff/me/buildings` 供员工查询本人管辖楼栋；
   - 保持对系统最后一位有效超级管理员的降级与停用防护；
   - 密码重置、停用与 JWT 会话作废（`revokeUserSessions`）原子联动。
4. **权限与前端后台契约对齐**：
   - `frontend-admin` 路由与访问控制（`AppRole`）同步支持多角色；
   - 保持现有权限矩阵的向后兼容，确保历史端点稳定。
5. **真实数据库测试与全门禁**：
   - 编写 `backend/test/integration/staff-roles-scope.int-spec.ts` 真实数据库集成测试（BE-INT）；
   - 通过全部质量门禁（lint、test:cov、test:int、test:e2e、check-docs、task-check）。

## 验收标准

- [ ] `UserRole` 扩充 4 个新角色（PROPERTY_MANAGER, FINANCIAL, MAINTAINER, OWNER），新增 `StaffBuildingAssignment` 实体并应用迁移（表数严格扩充至 55 张）。
- [ ] 员工管理（StaffService）支持全员工角色的创建、更新、查询、负责楼栋指派与密码重置。
- [ ] 提供员工本人管辖楼栋查询端点 `GET /staff/me/buildings`，以及管理端楼栋指派端点 `POST /staff/:id/buildings`。
- [ ] 维持最后一位超级管理员不被降级/停用的安全防线。
- [ ] 前端后台（`frontend-admin`）类型与访问控制对齐多角色体系。
- [ ] 编写真实 PostgreSQL 集成测试并跑通全部质量门禁。
