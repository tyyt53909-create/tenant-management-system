# T255：真实数据库测试骨架与 J1–J7（QLT-01）

## 背景

现有 e2e（`test/*.e2e-spec.ts`）主要验证守卫与路由，`scripts/e2e-mvp` 覆盖业务主流程但不做断言级隔离；单元测试大量使用 Prisma mock，抓不到唯一索引、事务回滚、外键与并发约束。

FIN-01/05/07 等金流任务依赖一个可重复、可并行于 CI 的真实 PostgreSQL 测试骨架。本任务交付：

1. 一套真实 DB 的集成测试 harness；
2. 当前代码已支持的 J1、J5 旅程；
3. 其余 J2/J3/J4/J6/J7 的显式留桩（`describe.skip`），避免把「未实现」伪装成「通过」；
4. CI gate 与看板纳入集成测试。

## 范围

### 1. Harness（`backend/test/integration/`）

- 固定使用 `DATABASE_URL` 指向的独立测试库；禁止连接生产。
- `resetDatabase()`：`TRUNCATE ... RESTART IDENTITY CASCADE`（排除 `_prisma_migrations`）。
- `seedBase()`：楼栋 + ADMIN + CLEANER（bcrypt cost 4，仅测试）。
- `createApp()`：真实 `AppModule` + 全局 `ValidationPipe`；supertest 走真实 HTTP。
- `setupTenancy()`：预建租客 → 邀请码注册 → 合同 DRAFT → 房源 RESERVED → 合同 ACTIVE。
- 串行执行（`fileParallelism: false`），避免共享库互相干扰。

### 2. 可执行旅程

- **J1 招租到入住**：
  - 注册后 `/auth/me` 绑定预建租客（不新建档案）；
  - 合同 ACTIVE 后房源 OCCUPIED；
  - 同房间第二份未结束合同被拒（409/422）。
- **J5 报修闭环**：
  - 租客提交（服务端推导房间/租客，忽略伪造 ID）；
  - ADMIN 按合法状态链派单到 COMPLETED；
  - 终态回退 409；租客只能看到自己的工单。

### 3. 留桩（依赖未完成业务）

- J2 计费引擎 → FIN-02 / T266
- J3 逾期与催缴 → FIN-04 / T272
- J4 收款并发/冲正 → FIN-05 / T264
- J6 续签 → FIN-01 / T263
- J7 退租结算 → FIN-07 / T273

留桩使用 `describe.skip` + `it.todo`，证据中明确 NOT_IMPLEMENTED。

### 4. CI 与看板

- `backend-e2e.yml` 在 e2e-mvp 之后运行 `npm run test:int`。
- `scripts/gates.mjs` 将 `integration` gate 接入 collect-gates；STATUS 不再固定显示「整合測試 not-run」。
- 新增 `npm run test:int`（`vitest.config.int.ts`）。

### 5. 文档

- `docs/07-测试策略.md` 增加「真实 DB 集成测试」章节与命令。
- `AGENTS.md` §7.3 增加 `npm run test:int`。
- `docs/19` QLT-01 置 active；`docs/INDEX` 登记。

## 非目标

- 不引入 Testcontainers；CI 使用 service container，本地使用 `DATABASE_URL`。
- 不做性能/压测（OPS-09）。

## 风险

- 集成测试会 `TRUNCATE` 整个测试库；必须使用独立库，禁止指向 staging/prod。
- J1/J5 依赖当前业务行为（房间状态机、能力开关、邀请码）；业务变更会导致断言失效，需要随任务更新。
- 串行执行会拉长 CI；当前仅 2 个旅程，后续 J2–J7 落地时需评估分片。
- `describe.skip` 是显式技术债，FIN 任务完成时必须取消并补断言。
