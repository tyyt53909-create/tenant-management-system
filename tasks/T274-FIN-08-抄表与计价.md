# T274：抄表与计价（FIN-08）

## 背景

ISS-35：`MeterReading` 没有数据库唯一约束，重复上报只能靠 `notes` 里的 `[msgId:]` / `[SETTLED]` 字符串判断；单价同时存在于 `Meter.unitPrice`、`MeterPriceHistory`（从未写入）、公共事业账单 DTO 与前端，调价后历史读数会被新价重算。T237（CSV 导入与楼栋一致性）也把抄表数据治理并入本任务。

路线图标注本任务依赖 FIN-11 / T276（设置中心）。本任务只落**表级生效单价 + 历史表 + 计价 API**，不建设置中心界面；T276 后续只做设置页与组织级默认价，任务书不因此放宽验收。

## 范围

### 1. 单价单一来源与生效日

- `MeterPriceHistory` 增加可空 `meterId`：表级价格优先，`meterId` 为空时作为该表类型的默认价（兼容既有模型设计）。
- 新增 `MeterPriceService`：
  - `resolveUnitPrice(meter, at)`：取 `effectiveDate <= at` 的最新一条（表级 → 类型级 → `Meter.unitPrice` 兜底）。
  - 批量解析，供统计/对账使用。
  - `recordPriceChange()`：调价时写历史；创建电表时写入初始价。
- `Meter.unitPrice` 保留为「当前价缓存」，不再作为历史计价的唯一依据。
- 新增接口：
  - `GET /meters/:id/price-history`：价格历史（ADMIN）。
  - `POST /meters/:id/price`：调价（ADMIN，写历史并更新当前价）。
  - `PATCH /meters/:id` 携带 `unitPrice` 时走同一调价逻辑，避免绕过历史表。

### 2. 读数幂等与唯一约束

- `MeterReading` 增加 `dedupKey`（可空），并建立 `@@unique([meterId, dedupKey])`。
- 生成规则：优先 `messageId`，否则由 `readingTime + currentReading + source` 生成稳定摘要；同一表重复上报命中唯一约束时返回已有记录，不抛 500。
- 既有 `[msgId:]` / 时间戳比对逻辑保留为前置快速路径。

### 3. 结算幂等

- 结算事务内对 `Meter` 行加 `SELECT ... FOR UPDATE`，串行化同一块表的并发结算。
- `MeterReading` 增加 `settledAt` / `settledUsage` / `settledUnitPrice` / `settledAmount`，结算以结构化字段为准，`[SETTLED]` 备注仅保留兼容。
- 重复结算返回 `settled: false, reason: 已结算`，不产生第二笔扣费/账单。

### 4. 计价一致性

以下路径统一经 `MeterPriceService` 按读数业务日期取价：

- `MeterBillingService.applyReadingDeduction` / `settleMeter` / `getUnsettledUsage`
- `MeterUsageQueryService`（概览与 CSV 导出的单价列）
- `MeterReconciliationService`（应收 = 用量 × 生效价）
- `PublicUtilitiesService`（未显式传价时按账期末日解析）

### 5. 测试

- 单元：价格解析（生效日、跨表兜底、批量）、调价写历史、读数去重、结算幂等与锁。
- 集成（真实 PostgreSQL）：调价跨月后按旧价结算；重复 messageId 只落一条；并发结算只扣一次。

## 风险

- 历史读数的 `settledAt` 为空：以既有 `[SETTLED]` / `[INITIAL]` 备注继续识别，避免重复扣费，但不回填历史结构字段。
- `Meter.unitPrice` 与历史价不一致时以历史价为准；`PATCH` 直接改价的历史数据在首次调价后才会进入历史表。
- 并发结算依赖 PostgreSQL 行锁；SQLite 等非目标数据库不保证。
- 结算口径变化对既有 `MeterUsageQueryService` 演示数据无影响（无数据时仍返回演示值，属 T275 指标治理范围）。
