# T334｜CORE-07 入住与周期收费端到端验收

基底 `e8e6e50`（#173，含 #172、#170、#171），实现 `b81336a`。用 Node.js 22、Playwright Chromium、真实 NestJS 服务和独立 PostgreSQL 16 / Redis。数据库由 T316 标记；测试以非超级用户及只读 psql 会话查询。HTTP fixture 只做资料准备及模拟另一个操作员，所有被验收的确认由浏览器点击。

每条旅程分别执行于 1440×900 桌面和 390×844 触控视口。金额、确认控件及提交响应均有必经断言，测试要求确认按钮位于视口内，且页面真的收到请求结果。

- **入住**：预览后另一操作员改房源版本。点确认收到实际 409，数据库仍为 VACANT、DRAFT，预付、账单、付款、底数和入住记录为空。刷新后重新预览及确认。PostgreSQL 核对该租客的 ACTIVE 租约、OCCUPIED 房态、一次入住、100 起表读数、零余额预付账户、300000 分首租和 600000 分押金应收，实收仍为零。
- **周期收费**：页面录入两块表，初次预览不扣费。另一操作员重检造成版本冲突，确认收到实际 409；原凭证和游标保持原样。刷新后确认可处理项目，SQL 核对正确租客的账户扣 200 分、同合同生成 300 分补缴账单，二者关联正确的表读数。另一租客缺账户受阻。补账户再刷新，页面重新检查后只确认该行，扣 400 分，原已成功账户与账单逐项不变。两份已存在租金维持无变化。
- **手机回归**：初测周期收费确认框受横向溢出裁切，遮罩截获点击。批次操作移到面板内容并允许换行，表格宽度受面板约束，确认框随视口收缩。手机用真实点击覆盖冲突、刷新后的首轮确认和补办确认。

运行 `npx playwright test --retries=0`。运行方式与 `.github/workflows/admin-ui.yml` 一致，先部署并播种独立 PostgreSQL，再准备 T316 标记，通过 `PLAYWRIGHT_DATABASE_URL` 及 `INTEGRATION_DATABASE_MARKER` 提供同库的只读验收连接。管理后台 lint、112 项单测和 build 已通过。

完整套件 16 项通过（含 4 项新旅程与 1 项认证 setup，禁用测试 runner 重试）。本地构建、lint、文档检查通过。
