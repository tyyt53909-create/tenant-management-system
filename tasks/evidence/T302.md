## 1. 变更摘要

| 模块 | 变更项 |
|---|---|
| 数据模型与迁移 | `UserRole` 扩充 `PROPERTY_MANAGER`（楼管/管家）、`FINANCIAL`（财务）、`MAINTAINER`（维修工）、`OWNER`（房东/业主）；新增 `staff_building_assignments` 实体，数据表数严格对齐至 55 张表 |
| 员工楼栋管辖范围映射 | 实现 `StaffBuildingAssignment` 实体与多对多关联，支持管家、保洁、维修、业主各自分配管辖的一栋或多栋楼宇；`ADMIN` 默认具备全局所有楼栋范围权限 |
| 员工管理与指派服务升级 | `StaffService` 支持全部员工角色的创建、更新、查询、负责楼栋指派（`assignBuildings`）；提供员工本人管辖楼栋查询端点 `GET /staff/me/buildings`；严格维持最后一位有效超级管理员不被降级/停用 |
| 楼栋数据范围隔离助手 | 实现 `getStaffBuildingScope` 与 `assertStaffBuildingAccess`，提供通用员工楼栋管辖范围解析与越权拦截防护 |
| 前台路由与类型对齐 | `frontend-admin` 的 `AppRole`、`User.role`、`InviteCode.role` 与导航访问控制同步支持 7 种角色体系 |
| 质量门禁与测试 | 169 个后端单元测试文件（1644 测例全绿）、后端覆盖率（Statements 85.3%, Lines 86.31%）、32 个真实 PostgreSQL 集成测试（99 测例全绿）、OpenAPI 契约（263 路由）全绿 |
