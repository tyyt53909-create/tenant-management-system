## 1. 变更摘要

| 模块 | 变更项 |
|---|---|
| 数据模型与迁移 | 新增 `CleaningTask` 模型与 `CleaningTaskType`（CHECKOUT/DAILY/DEEP/INSPECTION）、`CleaningTaskStatus`（PENDING/ASSIGNED/IN_PROGRESS/COMPLETED/ACCEPTED/CANCELLED）枚举；关联 `Building`、`Room`、`User`（CLEANER 角色），创建迁移 `20261028100000_cleaning_tasks`；表数扩充至 **56 张表** |
| 自动建单与退租联动 | 退租完成（`CheckoutService.update`）当房间退出占用并转入待清洁状态时，自动幂等触发创建 `CHECKOUT_AUTO` 类型的退租保洁工单（`CL-YYYYMMDD-XXXXXX`），避免重复建单 |
| 保洁派工与楼栋管辖范围 | 实现 `POST /api/cleaning/tasks` 手动建单、`POST /api/cleaning/tasks/:id/assign` 派工调度（指派保洁员并置为 `ASSIGNED` 状态），管家按负责楼栋范围执行鉴权拦截 |
| 保洁员专属端点与执行流转 | 保洁员查询专属指派工单 `GET /api/cleaning/tasks/assigned`；开工 `POST /api/cleaning/tasks/:id/start`（流转至 `IN_PROGRESS`，联动将房态置为 `CLEANING`）；完工 `POST /api/cleaning/tasks/:id/complete`（上传前后照片并流转至 `COMPLETED` 待验收） |
| 管家/管理员验收闭环 | 验收合格 `POST /api/cleaning/tasks/:id/accept`（评 1~5 星与验收评语，流转至 `ACCEPTED`，**核心联动将房态原子恢复为 `CLEAN`，可招租挂牌**）；验收驳回 `POST /api/cleaning/tasks/:id/reject`（退回 `IN_PROGRESS` 返工） |
| 契约与质量门禁 | OpenAPI 扩展至 280 条路由，前端契约类型同步更新；后单单元测试（173 测试文件，1697 测例全绿）；前端后台（112 测例全绿，build 通过）；小程序（168 测例全绿）；文档门禁（56 张表与 280 路由严格一致） |
