# T141: 滞纳金核销（收款含滞纳金 + 自动核销）

## 背景

T140（PR #10）实现了滞纳金的建议值与管理确认，但确认后仅是「账面记录」：收款接口仍只按账单金额校验，收款总额无法包含滞纳金，也无法标记滞纳金已收。本任务按 `docs/04-状态机.md` §3.3「OVERDUE → PAID 全额收款（含滞纳金）→ 确认滞纳金」补上核销环节（2026-10-13 用户决策：现在就做核销）。

> 任务编号说明：原计划 T141=定时任务，因核销涉及 schema 变更且定时任务依赖账单核销语义，调整为 T141=滞纳金核销、T142=定时任务、T143=保洁功能。

## 任务范围

### 数据模型（Prisma 迁移）

1. `LateFee` 新增字段：`settledAmount Int?`（已核销金额）、`settledAt DateTime?`（结清时间）、`settledBy String?`（结清操作人）

### 后端

2. **`addPayment` 扩展**（`POST /bills/:id/payments`）：
   - 收款上限 = 账单未缴金额 + 未核销滞纳金合计（超出 400）
   - 分配顺序：**先入账单，余额按确认时间先后核销滞纳金**（支持部分核销，结清时写 `settledAt/settledBy`）
   - 账单状态：`PAID` 条件收紧为 **账单全额缴清 且 滞纳金全部核销**；否则 `PARTIAL`（账单已满但滞纳金未清时仍可继续收款）
   - 返回体增加 `lateFees`（本次核销的滞纳金记录）
3. **`addLateFee` 补充**：确认金额为 0（减免）时直接标记结清（`settledAmount=0, settledAt, settledBy`），不产生新的应收
4. 租客账单详情增加 `settledAt`（租客可见自己的滞纳金是否结清）
5. 幂等保护不变（交易号唯一约束 + 应用层查重）

## 决策记录

- **核销顺序**：先入账单本金，余额按确认时间先后核销滞纳金（本金优先，符合惯例；同日多笔按创建先后）
- **PAID 条件收紧**：账单全额缴清 + 滞纳金全部核销才 PAID，与 `docs/04` §3.3「全额收款（含滞纳金）」一致；避免账单 PAID 后滞纳金无法收取（PAID 不可再收款）
- **部分核销**：`settledAmount` 累加，结清时写 `settledAt/settledBy`；不做「按比例分摊到收款记录」的明细关联（留待需要时扩展）
- **0 元确认（减免）**：视为已结清（无应收），直接标记 `settledAt`
- **收款上限**：账单未缴 + 未核销滞纳金，防止超收；多收场景（预收）不在第一版范围
