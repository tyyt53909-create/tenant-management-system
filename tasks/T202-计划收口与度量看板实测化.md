# T202: 计划收口与度量看板实测化

任务编号按 AGENTS.md §10 Q6 规则取 `tasks/` 现有最大编号 +1（T201 → T202）。

## 背景

`docs/13-架构与现有代码优化计划.md`（文档一 / OPT-01~OPT-28）整体完成标准已勾选，但逐条核对验收标准后发现：

1. **看板不是实测的**：`scripts/generate-status.mjs` 把测试数写成常量（后端 72 文件 / 740 例、前端 35 例），与实际（77/767、49）不一致；T201 交接称「由脚本直接执行命令统计测试数」与实现不符。
2. **后端生产构建是坏的**：`scoped-where.ts:16` 有 `TS2322`，`npx tsc --noEmit` 与 `npm run build`（Dockerfile 第 26 行使用）在 HEAD `8795d78` 上均失败。
3. **`openapi.json` 已漂移**：`npm run openapi:check` 失败，实际 121 条路由、已提交 120 条（缺 `/api/tenants/{id}/id-number`）。
4. **密钥变量名不一致（运行时缺陷）**：代码读 `FIELD_ENCRYPTION_KEY`，而 `.env.example`、`docker-compose.prod.yml`、`docs/12 §1.1` 只提供 `ENCRYPTION_KEY`，且 `env.validation` 只把它当可选项 → 按文档部署时证件号解密直接失败。
5. **验收项未勾/未达**：OPT-06「规则写进 AGENTS.md」、OPT-06 最后一处手写范围过滤、OPT-07「`.env.example` 与部署文档一致（docs-check 校验）」、`.env.example` 缺 `CLEANER_*`。

> 上述 2/3/4 之所以没被 CI 拦住，是因为 `develop`/`main` 共 32 个提交从未推送，仓库的 CI 从未跑过这批工作。

## 目标

1. 让度量看板真·实测：`generate-status.mjs` 执行三端测试套件并解析结果，失败则拒绝生成看板。
2. 修复 HEAD 上的两个 CI 阻断项（`tsc`/`build`、`openapi:check`）与密钥变量名运行时缺陷（含新增测试覆盖真实 `ConfigService` 接线）。
3. 收口 OPT-05/06/07/17/18/19 中已达标但未勾选的验收项；未达标项如实留空并注明原因。
4. 新增 `.env.example` ↔ `docs/12 §1.1` 变量清单一致性门禁；修正 `docs/INDEX.md` 过期计数。
