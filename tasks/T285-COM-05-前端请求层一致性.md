# T285：前端请求层一致性（COM-05）

## 背景

ISS-25：前端以中文 `message` 判断错误。三处具体问题：

1. 刷新令牌并发竞态靠 `message.includes('正在轮换中')` 判断，后端改文案即失效，多标签页会被强制登出；
2. 房态冲突靠 `status === 409` 猜原因，409 也可能是唯一键冲突；
3. 请求层已弹后端原因，页面 `catch` 又弹「删除失败」，用户看到两条矛盾提示。

## 范围

- 新增 `utils/apiError.ts`：统一解析 `{ code, message, details, requestId }`，错误码文案优先于后端 message；
  校验错误优先展示 `details`；网络错误与取消请求单独识别。
- 新增 `utils/notify.ts`：异常对象标记 + 去重提示，`notifyApiError` / `notifyLocalError`。
- `utils/request.ts`：改用统一解析；刷新竞态判断改为错误码。
- 后端新增 `AUTH_REFRESH_ROTATING`（401）错误码，`jwt.service.ts` 用 `apiError` 抛出；
  `docs/05` §5.2 登记，`error-codes.spec.ts` 双向校验。
- 替换全部按 `response.data.message` 分支/展示的调用点（composables、导出、页面、弹窗组件）。
- 文档 `docs/30-前端请求层一致性.md`，同步 docs/05/INDEX。

## 非目标

- 小程序请求层（FE-02）。
- 错误码国际化。
- 后端全部 `throw new XxxException(中文)` 的迁移（过滤器兜底映射继续保留）。

## 验收

| # | 标准 | 验证 |
|---|---|---|
| 1 | 刷新竞态按 `AUTH_REFRESH_ROTATING` 判断，改文案不影响重试 | 前端单测 |
| 2 | 错误码文案优先，校验错误展示 details | 前端单测 |
| 3 | 同一异常只提示一次；取消请求不提示 | 前端单测 |
| 4 | 前后端错误码目录与 docs/05 双向一致 | 后端 `error-codes.spec.ts` |
| 5 | 全量门禁通过 | `tasks/evidence/T285.md` |

## 风险

- 错误码文案表需与后端 `ERROR_CATALOG` 同步，漏登记时回退后端 message。
- 去重依赖异常对象同一性；若调用方重新包装异常（`new Error(e.message)`）会重复提示。
- 部分页面仍用固定文案提示本地校验错误，属预期。
