# T291：订阅消息通道与额度管理（WX-02）

## 背景与目标

根据生产化路线图（docs/19 §4/§5 里程碑 M3），在微信小程序环境中为租客提供微信服务通知与模板消息下发能力，解决租客在退出小程序后无法及时感知待缴账单、工单维修进展与租约到期提醒的问题。

本任务依托 T290（WX-01）沉淀的 `WechatApiService` 全局稳定版 Token 刷新管理机制与 `UserIdentity` 微信 openid 映射体系，对接现有统一通知调度器（`NotificationDispatcher`）：
1. **订阅消息渠道（`WechatSubscribeChannel`）**：
   - 接入微信小程序服务端订阅消息下发接口 `https://api.weixin.qq.com/cgi-bin/message/subscribe/send`。
   - 自动解析租客的 `UserIdentity(provider = WECHAT_MP)` 对应的 `providerUserId`（openid）。未绑定微信账号的租客优雅跳过，不阻断其他渠道（站内信、邮件）。
   - 针对三大核心业务场景进行消息格式适配与路径跳转：
     - 账单提醒（账单生成、逾期催缴）：跳转至账单详情。
     - 工单进展（报修受理、派工、完成）：跳转至工单时间线。
     - 租约提醒（到期预警、续租提醒）：跳转至合同详情。
2. **额度管理（`WechatSubscribeQuota`）**：
   - 支持小程序端授权状态上报接口 `POST /api/notifications/wechat/subscribe-report`。
   - 在 Redis / 缓存中维护 `(userId, templateId)` 维度的可用发送额度计数器。
   - 每次下发前检查可用额度；下发成功扣减额度。
   - 捕获微信错误码 `43101`（用户未授权或额度耗尽），自动清零本地对应额度并记录日志，降级为其他通知渠道。
   - 捕获 `40001`/`42001`（token 过期），自动强制刷新 token 并重试一次。
3. **Mock 模拟通道**：
   - 在 `WECHAT_AUTH_MOCK=true` 或未配置真实 AppSecret/模板 ID 时提供自洽模拟通道，支持本地开发与自动化 CI 门禁运行。
4. **前端与小程序引导**：
   - 小程序端提供订阅授权触发器与上报客户端函数，并在关节点（账单缴费前、报修提交后）友好提示租客订阅通知。
