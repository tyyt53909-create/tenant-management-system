# T290：微信登录与身份绑定（WX-01）

## 背景与目标

根据生产化路线图（docs/19 §4/§5 里程碑 M3），在微信小程序环境中为租客提供微信一键登录与预建租客身份绑定能力，解决当前小程序缺乏微信登录入口、依赖海外不可用的 Google 登录及低到达率邮箱 OTP 的问题（ISS-29 / ISS-50）。

本任务严格遵循 DEC-03 决策与 SEC-04 架构规范：
1. 首次出现的微信 openid 绝不自动建立租客账号或虚拟房源，必须经由预建租客验证流程绑定。
2. 绑定提供两条路径：
   - 邀请码绑定：基于既有预建租客邀请码机制完成核销与身份关联。
   - 手机号快速验证绑定：通过微信获取用户手机号，在租客档案中精确匹配唯一预建租客后完成关联；无匹配或多条匹配时安全拦截。
3. `session_key` 严格存入 Redis 短 TTL 缓存，严禁返回前端或进入日志；全局 `access_token` 基于官方稳定版接口单飞锁刷新并与后续 WX-02/WX-03 共享。
4. 全流程覆盖安全审计（SEC-06），openid 仅存储哈希或脱敏值。
5. 小程序端条件编译剥离 Google 登录，以微信一键登录为主入口。

## 验收标准

- [x] 后端通过 `jscode2session` 换取 openid 与 session_key，session_key 仅存 Redis（TTL 30m），不返回前端、不入日志。
- [x] access_token 使用稳定版接口 `/cgi-bin/stable_token`，Redis 缓存 + 单飞防击穿，到期前 5 分钟自动刷新。
- [x] 未绑定的 openid 登录返回 `AUTH_WECHAT_UNBOUND` 与一次性 5 分钟 `bindTicket`，数据库无孤儿 User/Tenant 产生。
- [x] 绑定接口验证 `bindTicket` 防重放，支持邀请码与手机号匹配两种方式；手机号 0 笔匹配返回 `AUTH_ACCOUNT_NOT_PROVISIONED`，多笔匹配安全拦截。
- [x] 绑定成功原子写入 `UserIdentity(provider = WECHAT_MP)` 并颁发登录态（JWT + HttpOnly refresh cookie）。
- [x] 提供 mock 模式（`WECHAT_AUTH_MOCK=true` 且非 production），在没有真实 AppSecret 时支持本地开发与自动化 CI 门禁运行。
- [x] 小程序端支持微信一键登录，未绑定时唤起身份绑定，完成绑定后自动进入系统。
- [x] 单元测试与端到端集成测试通过，覆盖正常及微信错误码（40029、45011、40001 重试等）分支。
