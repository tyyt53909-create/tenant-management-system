# T273：退租结算一致性（FIN-07）

## 背景

ISS + UAT 第 12 步：退租结算必须包含未缴/水电/扣款/押金退还，单一事务完成；此前 `PATCH /checkout/:id {status:COMPLETED}` 只改状态，不终止合同、不释放房间、不结清押金台账，结算等式也未校验。

## 范围

### 1. 状态机

- 允许 `DRAFT → PENDING → COMPLETED`、`PENDING → DRAFT`、`DRAFT → COMPLETED`（兼容历史 UI）、`DRAFT/PENDING → CANCELLED`。
- COMPLETED/CANCELLED 为终态；重复 COMPLETED 幂等返回，不二次扣减押金。

### 2. 结算等式

完成时校验：

`totalRefund = 退款项合计（RENT/DEPOSIT/UTILITY/OTHER） - 扣款项合计（DEPOSIT_DEDUCTION/OTHER_FEE）`

不成立返回 400，状态与数据不变。

### 3. 押金台账结清（T267）

- `DEPOSIT_REFUND` 视为应退押金总额；现金退还 = 应退 - `DEPOSIT_DEDUCTION`。
- 必须满足 `押金扣除 + 现金退还 = 台账余额`；否则 400。
- 写 `DEDUCT` / `REFUND` 流水，余额归零、状态 `REFUNDED`。
- 无台账时押金项必须为 0。

### 4. 单一事务

COMPLETED 在同一事务内：

1. 更新退租单 + 明细；
2. 结算押金；
3. 合同 `ACTIVE → TERMINATED`；
4. 房间 `OCCUPIED → VACANT + PENDING_CLEAN`（复用合同状态机副作用）；
5. 任一步失败整体回滚。

### 5. 测试

- 单元：状态流转、结算等式、押金结清、重复完成幂等、合同/房间副作用。
- 集成（真实 DB）：押金 30 万 → 扣 5 万/退 25 万 → 台账 0 REFUNDED、合同 TERMINATED、房间 PENDING_CLEAN；等式不成立 400。

## 非目标

- 自动抄表与水电计价（FIN-08 / T274）。
- 预付账户退款自动转账（后续）。
- 未缴账单自动作废/冲正（只要求结算单体现）。
- 退租验房与照片（LSE-03）。

## 风险

- `totalRefund` 语义定为「实退净额」；历史数据若按毛额录入，完成时可能 400，需要人工修正。
- DEPOSIT_REFUND 视为应退总额，现金退还 = 应退 - 扣除；前端提示需同步（FE-01）。
- 未缴账单不自动处理，可能仍留在合同下；FIN-07 只保证结算单与押金一致。
- 取消退租不恢复已终止合同（完成前合同未动，无需恢复）。
