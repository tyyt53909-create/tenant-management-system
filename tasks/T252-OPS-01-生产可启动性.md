# T252：生产可启动性与配置验证（OPS-01）

## 背景

生产编排在设置 `REDIS_PASSWORD` 时会以 `--requirepass` 启动 Redis，但后端只读 `REDIS_HOST`/`REDIS_PORT`，从不传密码，导致 `PING` 返回 `NOAUTH`、生产拒绝启动。同时 `retryStrategy: () => null` 让运行中的 Redis 一旦重启就永不重连，错误还被空监听吞掉；生产变量模板也缺少程序实际读取的若干配置。

本任务按 `docs/19` 的 OPS-01 落地：一次校验全部环境变量、支持带密码的 Redis URL、断线自动重连、补齐健康检查与生产模板。

## 范围

- 新增 `backend/src/config/env.schema.ts`：集中声明环境变量（必填环境、默认值、是否机密、校验规则），启动时一次报告全部缺漏，不输出机密值。
- `env.validation.ts` 改用 schema；生产/预发必填项缺失即拒绝启动；生产禁止 `ADMIN_PASSWORD`/`CLEANER_PASSWORD`、`OTP_DEV_BYPASS`、`GOOGLE_AUTH_MOCK`、模拟电表。
- 新增 `backend/src/redis/redis.config.ts`：解析 `REDIS_URL`（支持 `redis://`、`rediss://`、密码、db），保留 `REDIS_HOST`/`REDIS_PORT`/`REDIS_PASSWORD` 兼容。
- `RedisService`：指数退避重连（上限 5 秒）、`maxRetriesPerRequest: 3`、错误写日志、`ready` 随连接状态变化；生产首次连不上仍拒绝启动，开发/测试降级。
- 健康检查新增 `GET /api/health/live`（`/api/health` 保留为同义），`ready` 继续检查 DB/Redis/磁盘。
- `docker-compose.prod.yml` 传递 Redis 密码、CORS、SMTP、日志等变量；`.env.example`/`.env.prod.example` 补齐并标注必填。
- 新增 env 模板与 schema 的一致性检查脚本，接入后端测试或 CI。

## 验收

| # | 标准 | 验证 |
|---|---|---|
| 1 | 生产环境缺任一必填变量时启动失败，并一次列出全部缺漏 | 单元测试 + 手工启动 |
| 2 | `REDIS_URL=redis://:密码@host:6379/0` 能连接；`REDIS_PASSWORD` + HOST/PORT 兼容 | 单元测试 |
| 3 | 运行中 Redis 断开后自动重连，`ready` 随状态变化 | 单元测试（重连策略/事件） |
| 4 | `/api/health/live` 恒 200；`/api/health/ready` 依赖不可用时 503 | 单元测试 |
| 5 | 生产变量模板覆盖 schema 全部键，CI 一致 | 一致性脚本 |
| 6 | 后端 lint / tsc / unit 通过 | `npm run lint && npx tsc --noEmit && npm test` |
| 7 | 不改动业务逻辑与数据库 schema | diff 检查 |
