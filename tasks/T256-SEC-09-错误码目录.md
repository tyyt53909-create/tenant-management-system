# T256：错误码目录（SEC-09）

## 背景

`backend/src/common/errors/error-codes.ts` 目前只有 23 个码，且大量业务错误依赖 `codeForMessage()` 按中文消息或 HTTP 状态猜码；`docs/05-接口规范.md` §5.2 已定义 36 个码，但代码没有同步。消息一改，前端拿到的 `code` 就静默变化。

## 范围

- `ERROR_CATALOG` 作为代码侧唯一目录：每个错误码声明 HTTP 状态与默认文案，覆盖 docs/05 §5.2 全部 36 个码。
- `ErrorCode` 由目录派生，保留 `ErrorCode.XXX` 既有写法。
- 新增 `apiError(code, message?, details?)`：状态码与默认文案取自目录，响应体稳定带 `code`。
- `codeForMessage()` 降级为迁移期兜底；显式 code 必须存在于目录，避免拼写错误静默通过。
- 先迁移高风险路径到 `apiError()`：房态流转与乐观锁、滞纳金已缴清、预付余额不足。
- 新增 `error-codes.spec.ts`：与 docs/05 §5.2 双向校验（漏登记/多登记/状态码不一致都会失败）、命名与状态码合法性、`apiError` 行为、兜底映射。

## 非目标

- 一次性把 235 处 `throw new XxxException(...)` 全部改写：按模块逐步迁移，本轮先覆盖上述高风险路径。
- 前端错误码文案表重构：小程序/后台已有按 code 分支，保持不变。
- 修改 docs/05 的错误码清单：本轮以文档为准，代码对齐文档。

## 验收

| # | 标准 | 验证 |
|---|---|---|
| 1 | 代码目录与 docs/05 §5.2 完全一致（码与状态码） | `error-codes.spec.ts` 双向校验 |
| 2 | 目录码命名合法、状态码在 400–599、默认文案非空 | 同上 |
| 3 | `apiError()` 返回目录状态码与默认/覆盖文案 | 同上 |
| 4 | 显式 code 不在目录时回退推断，不产生非法码 | 同上 |
| 5 | 房态/财务高风险路径显式带码 | rooms、bills、prepay 测试 |
| 6 | lint / tsc / 全量测试通过 | `npm run lint && npx tsc --noEmit && npm test` |
