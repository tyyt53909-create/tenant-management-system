# T271：个资、登记与密钥轮换（SEC-08）

## 背景

- ISS-22：`TenantRegistration` 有表、有读取与明文查看接口，但**没有任何写入 API**；管理后台租客表单收集的 `idNumber` 在提交前被丢弃，证件号实际只能靠脚本导入。
- 证件号已 AES-256-GCM 加密 + HMAC 查重 hash，列表脱敏，`GET /tenants/:id/id-number` 有 `VIEW_ID_NUMBER` 审计；但缺登记状态流转、缺写入路径的冲突处理与测试。
- 密钥只有单把（`ENCRYPTION_KEY`），换钥后旧密文无法解密；`docs/12` 明确写着「没有换钥迁移脚本」。SEC-08 要求可轮换。

## 范围

### 1. 证件登记写入

- `CreateTenantDto` / `UpdateTenantDto` 增加可选 `idType` + `idNumber`（必须成对出现）：
  - 创建租客时在同一事务内写 `TenantRegistration`（加密 + hash）；
  - 更新租客时 upsert 登记；证件号 hash 冲突返回 **409**；
  - 任何响应只返回 `idNumberMasked`，不返回密文/明文/hash。
- 新增专用接口（ADMIN）：
  - `GET /tenants/:id/registration`：返回 `idType`、`idNumberMasked`、`status`、`registeredAt`、`notes`。
  - `PUT /tenants/:id/registration`：`{ idType, idNumber?, status?, notes? }`；不传 `idNumber` 时只更新状态/备注。
- 登记状态机：`NOT_REGISTERED → PENDING/REGISTERED`、`PENDING → REGISTERED/REJECTED`、`REJECTED → PENDING/REGISTERED`；禁止回退到 `NOT_REGISTERED`，非法流转 **409**。
- 进入 `REGISTERED` 时写 `registeredAt`；离开时清空。

### 2. 查看留痕

- 保留 `GET /tenants/:id/id-number` 的 `VIEW_ID_NUMBER` 审计；审计 `changes` 只含 `tenantId`，不含明文/密文/hash。
- 登记写入写 `UPDATE_TENANT_REGISTRATION` 审计，`changes` 只含 `idType`、`status`、`changedFields`（如 `['idNumber']`）。

### 3. 密钥轮换

- 新增可选 `ENCRYPTION_KEY_PREVIOUS`（逗号分隔多把旧钥）：
  - 解密/脱敏按「当前钥 → 旧钥列表」依次尝试；加密始终用当前钥。
  - 换钥流程：新钥写入 `ENCRYPTION_KEY`，旧钥放 `ENCRYPTION_KEY_PREVIOUS` → 运行 `npm run rotate:id-numbers -- --apply` → 确认后移除旧钥。
- `encrypt-id-numbers.ts` 增加 `--rotate` 模式：解密用旧钥、重新加密与重算 hash 用新钥；遇重复证件号整批停止。
- `env.schema` 登记新变量（可选、secret）；`.env.example` 与 `docs/12` 补换钥步骤。

### 4. 前端

- 租客新增/编辑表单不再丢弃 `idNumber`：按 `idType` 提交；列表与详情继续只显示脱敏值。
- 详情增加「登记状态」展示（只读）；编辑弹窗可维护证件类型/号码（留空表示不改）。

### 5. 测试与文档

- 单元：状态机、成对校验、重复 hash 409、审计不含敏感值、旧钥解密、轮换计划重算 hash。
- 集成（真实 DB）：创建带证件号 → 列表脱敏 → 明文查看留痕且审计无明文 → 重复证件号 409 → 更新状态 → `PUT` 只改状态不动证件号。
- 文档：`docs/02` §2.22、`docs/05` §7.6.8、`docs/12` §1.1/密钥轮换、`docs/INDEX`。
- `docs/06`（owner_tier=human）不在本任务修改；如发现与实现不一致，按 AGENTS §5.4 记录到 `docs/09`。

## 非目标

- 隐私政策/授权弹窗文案与 ICP（人工前置，DEC-01）。
- 员工证件、银行卡等其他敏感字段加密。
- 数据导出脱敏与跨境传输评估。
- 证件 OCR、有效期校验、实名核验服务。

## 风险

- 证件号一旦写入即受唯一 hash 约束；历史脚本导入的重复数据会在首次更新时暴露 409，需要人工清理。
- 换钥脚本必须在停机窗口或维护窗口执行；执行期间旧钥仍保留，失败可回滚（旧密文未被删除）。
- 前端表单暴露证件号输入；只有 ADMIN 能进租客页，但浏览器自动填充/密码管理器可能留存，需在发布说明提示。
- 新增环境变量可选，不设置时行为与现状一致（仅当前钥）。
