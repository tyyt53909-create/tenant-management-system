# T137: 水电读数登记 + 自动扣费 + 差额补缴

## 背景

`MeterReading` 表零接口：读数只能靠直接改库；「读数 → 扣费 → 不足补缴」链路缺失。本任务按 `docs/02-数据模型.md` §2.14 补齐，并**打通最后一笔资金闭环**。

---

## 任务范围

### 后端（meters 模块扩展）

1. `POST /api/meters/:id/readings`（仅 ADMIN）— 事务内完成：
   - 自动查上一条读数 → `previousReading`；`usage = current - previous`
   - 读数回退（< 上次）→ 400；表停用 → 400
   - **自动扣费**（用量 × 当前单价）：
     - 有生效合同 + 预付账户：先扣尽可用余额（条件更新防并发透支）
     - **余额不足：差额生成 `UTILITY` 补缴账单**（dueDate = 读数日 + 7 天，快照含用量/单价/已扣/差额）
     - 扣费写 `PrepayTransaction`（DEDUCTION, relatedType=METER_READING, relatedId=readingId）
   - 不扣费情形（返回原因）：公共区域表（运营成本）/ 无生效合同 / 无预付账户 / 用量为 0
2. `GET /api/meters/:id/readings` — 读数历史（分页倒序）
3. `CreateMeterReadingDto`（两位小数、非负、可选时间）+ `QueryMeterReadingsDto`

### 前端（水电表页）

4. 每行「读数」按钮（停用表置灰）→ 读数对话框：当前读数/时间/备注，提交后内联展示**用量 + 扣费 + 补缴**结果
5. 每行「记录」按钮 → 读数历史对话框（分页）
6. `api/meters.ts` 封装（含 `MeterReadingResult` 类型）

### 测试

7. `meters.service.spec.ts`（模块此前零测试）：13 例
   - 首次/非首次读数 usage、全额扣费、余额不足部分扣+差额账单、余额 0 全额账单
   - 无合同/无账户/公共区域/用量 0 不扣费（各带原因）
   - 读数回退 400、表不存在 404、表停用 400、历史分页
8. `dto-validation.spec.ts` 5 例

## 决策记录

- **不足处理**：先扣尽余额 + 差额生成 UTILITY 补缴账单（`dueDate` = 读数日 + 7 天）——已同步至 docs/02 §2.14
- **单价来源**：v1 用 `Meter.unitPrice`（当前价）；`MeterPriceHistory` 按生效日期取价的逻辑留待后续
- **首次读数**：`previousReading = 0`（视为从 0 起算）
