# T173: 租客账号能力开关（TENANT CAPABILITY OVERRIDES）

## 1. 任务背景

依据 `計劃.md`，管理后台需要能够对某个租客的登录账号进行精细化管控：
1. 禁用登录 / 恢复登录（通过 `User.isActive` 控制登录与 token 失效，与租客档案 `Tenant.isActive` 物理分离）。
2. 单独屏蔽或恢复某几项租客功能（通过新增覆写表 `UserCapabilityOverride` 控制）。
3. 保持数据隔离与权限红线：非完整 RBAC，不给租客提升角色，仅管理已注册的 `TENANT` 账号，不扩大数据范围。

## 2. 详细范围

### 2.1 数据模型（Prisma）
- 枚举 `CapabilityEffect { ALLOW, DENY }`
- 实体 `UserCapabilityOverride`：
  - `id`: CUID
  - `userId`: 关联 `User`
  - `capability`: 字符串（程序常量注册）
  - `effect`: `CapabilityEffect`
  - `reason`: 可选原因
  - `grantedBy`: 操作者 ID
  - 唯一索引 `@@unique([userId, capability])`
- 迁移：单批串行执行 `prisma migrate dev`

### 2.2 后端能力 (`backend/src/modules/tenant-capabilities/`)
- `tenant-capability.catalog.ts`：能力注册目录（6项可屏蔽项）
  - `tenant.contract.read`
  - `tenant.bill.read`
  - `tenant.prepay.read`
  - `tenant.maintenance.read`
  - `tenant.maintenance.create`
  - `tenant.checkout.read`
- 装饰器 `@RequireCapability(code)` 与守卫 `CapabilityGuard`
- 服务 `TenantCapabilityService`
- 四个管理接口：
  - `GET /tenants/:id/account`
  - `PATCH /tenants/:id/account`
  - `GET /tenants/:id/capabilities`
  - `PUT /tenants/:id/capabilities`
- `GET /auth/me` 返回 `capabilities: string[]`
- 审计日志：`DISABLE_TENANT_ACCOUNT`, `ENABLE_TENANT_ACCOUNT`, `UPDATE_TENANT_CAPABILITIES`

### 2.3 管理后台 (`frontend-admin/`)
- 租客详情抽屉（`resourceDetail.ts`）新增第 4 个 Tab：「登入帳號」
- 未注册提示 vs 已注册账号信息
- 禁用登录 / 恢复登录开关与提示
- 5组租客功能开关及屏蔽原因输入

### 2.4 小程序 (`miniprogram/`)
- 账单与报修 Tab 页面内屏蔽提示与提交按钮隐藏
- 首页与个人中心根据 `capabilities` 隐藏合同/预付/退租入口
- `/auth/me` 失败时安全回退
