# T264：收款正确性（FIN-05）

## 背景

ISS-12：收款 `SELECT ... FOR UPDATE` 的错误被空 `catch` 吞掉，锁失败时仍继续入账；应用层交易号查重与写入之间存在竞态；没有 `Idempotency-Key`；作废/冲正缺失，财务记录只能靠改库回退。

P0 目标：并发不超收、重放不重复入账、作废留痕且账单/滞纳金可精确回退。

## 范围

### 1. 数据模型

- 新增 `PaymentStatus`（`CONFIRMED` / `VOIDED` / `REVERSAL`）。
- `PaymentRecord` 新增：
  - `idempotencyKey @unique`、`receiptNumber @unique`；
  - `billPortion` / `lateFeePortion` / `lateFeeAllocations`（精确冲正）；
  - `voidedAt` / `voidedBy` / `voidReason`；
  - `reversalOfId @unique` 自关联（一条收款最多一条冲正）。
- 迁移 `20261024200000_payment_correctness`：加列/索引/序列 `payment_receipt_seq`；历史记录回填 `CONFIRMED` 与 `billPortion=amount`。

### 2. 收款

- 行锁失败不再吞掉：直接调用 `$queryRaw SELECT ... FOR UPDATE`，异常向上抛出。
- 同一账单并发收款串行化；仍按「本金 → 滞纳金」分配。
- 交易号重复由应用层 + 唯一索引双重保障；`P2002` 映射为 409。
- 收据号由数据库序列原子分配：`R{业务日}{6 位序号}`。
- `Idempotency-Key`（请求头）或 body `idempotencyKey`：
  - 同键同账单同金额 → 返回原收款（`idempotent=true`）；
  - 同键不同请求 → 409。

### 3. 作废与冲正

- `POST /api/bills/:id/payments/:paymentId/void`（ADMIN，需 reason）：
  - 原记录置 `VOIDED`，另建负额 `REVERSAL`；
  - 账单 `paidAmount` 按 `billPortion` 回退；
  - 滞纳金按 `lateFeeAllocations` 精确回滚，恢复未核销状态；
  - 账单状态重算：`PENDING` / `PARTIAL` / `OVERDUE`；
  - 重复作废幂等；`CANCELLED` 账单拒绝。

### 4. 测试

- 单元：幂等重放/冲突、收据号、锁异常上抛、作废回退、滞纳金回滚、重复作废。
- 集成 J4：真实 DB 下并发两笔 60000 只成功一笔；同 Idempotency-Key 只记一次；作废生成 -60000 冲正、账单回退。

## 非目标

- 微信支付/线上回调（PAY-01/02）。
- 收据 PDF 与验真（PAY-03）。
- 账单滞纳金规则调整（FIN-04 / T272）。
- 历史收款滞纳金拆分的精确回填（无法从旧数据还原，按本金处理）。

## 风险

- 冲正依赖 `lateFeeAllocations`；历史收款没有该字段，作废时只能回退本金。
- 收据号序列全局递增，跨日后不会重置；如需「每日从 1 开始」需改为按日重置。
- 行锁在 SQLite/无原生 SQL 环境会退化为无锁（仅测试替身）；生产 PostgreSQL 必须保持。
- 并发集成测试依赖真实 PostgreSQL 行锁语义。
