# T260：身份绑定与注册策略（SEC-04）

## 背景

DEC-03 已拍板：**禁止自动成为租客**，只允许「预建租客档案 + 邀请码」或「手机号精确匹配」。当前实现仍有三处越权隐患（ISS-07、ISS-23）：

- 邮箱 OTP 与 Google 首登会在事务里自动创建 `User` 与 `Tenant`，并用 `pending-<id>` 伪造手机号。
- Google 登录把缺失的 `email_verified` 当作 `true`（`payload.email_verified ?? true`）。
- 注册与绑定忽略邀请码的 `role`，一律建成 `TENANT`；邀请码核销不检查 `updateMany` 影响行数，可被并发重复使用。

同时缺少统一的外部身份表：Google 身份只存 `User.googleId`，无法承载后续微信/手机号身份（WX-01）。

## 范围

### 1. 数据模型（expand）

- 新增 `IdentityProvider` 枚举（`GOOGLE` / `EMAIL`）与 `UserIdentity` 表：
  - `userId`、`provider`、`providerUserId`、`email`、`emailVerifiedAt`、`createdAt`、`lastUsedAt`。
  - `@@unique([provider, providerUserId])`、`@@index([userId])`、`onDelete: Cascade`。
- `User` 新增可空 `emailVerifiedAt DateTime?` 与 `identities UserIdentity[]`。
- 迁移回填：把既有 `users.googleId` 写成 `GOOGLE` 身份，并给这些用户设置 `emailVerifiedAt`。
- 保留 `User.googleId` 作为兼容查询列（contract 阶段另立任务删除）。

### 2. Google 登录

- `email_verified` 必须显式为 `true`，否则拒绝（不再 `?? true`）。
- 先按 `UserIdentity(GOOGLE, sub)` 查用户，兼容旧 `googleId`。
- 已存在用户：补建身份、更新 `lastLoginAt` / `avatarUrl` / `emailVerifiedAt`。
- 不存在用户：必须同时满足
  1. 请求带有效邀请码；
  2. 存在 `userId = null` 且邮箱精确匹配的预建 `Tenant`；
  否则 403，不创建任何 `User` / `Tenant`。
- 新用户事务：建 `User`（role 取邀请码）→ 建 `GOOGLE` 身份（已验证）→ 绑定预建租客 → 原子核销邀请码。

### 3. 邮箱 OTP 登录

- `LoginEmailCodeDto` 新增可选 `inviteCode`。
- 已存在用户：正常登录，补建/刷新 `EMAIL` 身份与 `emailVerifiedAt`。
- 不存在用户：必须带有效邀请码且存在同邮箱预建租客，否则 403；不再自动创建 `Tenant`、不再生成 `pending-` 手机号。
- 新用户事务与 Google 相同。

### 4. 注册与邀请码绑定

- `POST /auth/register`：
  - 邀请码 `role` 生效（不再硬编码 `TENANT`）。
  - 必须存在 `userId = null` 且邮箱/手机号精确匹配的预建租客；否则 400，不创建任何档案。
  - 事务内绑定预建租客，不新建 `Tenant`。
- `POST /auth/bind-invite-code`：
  - 邀请码 `role` 生效；若用户当前无租客档案，按邮箱/手机号绑定预建租客。
  - 不允许把非 `TENANT` 账号降级/改角色（返回 409）。
- `consumeInviteCode` 改为检查 `updateMany.count`，为 0 时抛 409，确保一码只能用一次。

### 5. 前端与小程序

- 小程序登录页：新增可选邀请码输入，随 `login-email-code` 提交；文案由「首次登录自动创建」改为「需管理员预建并邀请」。
- 管理后台登录/注册 API 契约不变；仅在错误响应中展示后端文案。

## 非目标

- 员工账号生命周期、改密/找回、锁定策略（SEC-05）。
- 微信登录与手机号 OTP（WX-01、WX-03）。
- 删除 `User.googleId`（contract 阶段另立任务）。
- 租客登记（TenantRegistration）写入 API（SEC-08）。

## 风险

- 行为变更：新租客不能再自助创建档案；存量自动化测试与小程序文案必须同步，否则线上会出现「验证码正确但登录 403」。
- 预建租客按邮箱/手机号精确匹配；大小写与空格需统一规范化。
- `UserIdentity` 引入后保留 `googleId` 双写，需在 contract 阶段清理；期间以身份表为准、旧列兜底。
- 迁移为 expand（仅加表/列 + 回填），可前滚；不回滚数据。
