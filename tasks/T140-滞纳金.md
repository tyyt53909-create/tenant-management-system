# T140: 滞纳金（建议值 + 管理者确认）

## 背景

`docs/04-状态机.md` §3 早已定义账单状态机与逾期滞纳金流程（宽限期、按日比例/固定金额、封顶；系统只出建议值，管理者确认后才入账），`LateFee` 表与 `Contract.lateFeeRule` 字段在 T101 建表时已落地，但**计算与接口从未实现**：账单逾期后无法自动/手动产生滞纳金建议，也没有确认入口。本任务补齐这条闭环的核心逻辑。

## 任务范围

### 后端

1. **`LateFeeUtil` 计算工具**（`src/modules/bills/utils/late-fee.util.ts`）：
   - 规则：`{ graceDays, dailyRate, fixedDaily, cap }`（合同 `lateFeeRule`，单位分/比例）
   - 计费天数 = 逾期天数 − 宽限期（最小 0）；宽限期内金额为 0
   - 按日比例（优先）或固定金额（分/天）二选一；四舍五入到分
   - 封顶：超过 `cap` 取 `cap`，返回 `capped` 标记
   - `overdueDays(dueDate, now)`：按 UTC 自然日计算（到期日当天不算逾期），供服务层与定时任务复用
   - 返回完整计算过程（rule/overdueDays/effectiveDays/baseAmount/rawAmount/capped），写入 `LateFee.calculation`
2. **`POST /bills/:id/late-fees`**（ADMIN）：
   - 仅对「已逾期（dueDate < 今日）且未缴清」的账单生效
   - 不带 `confirmedAmount`：生成/刷新**建议值**（同一账单只保留一条未确认建议，重复调用不重复建单）
   - 带 `confirmedAmount`：管理者确认入账（可调整金额），记录 `confirmedAt/confirmedBy`；重复确认 409
3. **`GET /bills/:id/late-fees`**（ADMIN）：查询滞纳金记录（含计算过程）
4. **可见性收敛**（docs/03-权限矩阵.md）：
   - 管理者账单详情返回完整滞纳金记录（含计算过程）
   - 租客账单详情只返回已确认的最终金额（`confirmedAmount`/`confirmedAt`），不暴露建议值与计算细节
5. **DTO**：`CreateLateFeeDto`（`confirmedAmount?` ≥0 整数、`notes?`）

### 测试

6. `late-fee.util.spec.ts`：日比例 / 封顶 / 宽限期内 / 固定金额 / 边界（恰好宽限、恰好封顶）/ 空规则 / 取整 / overdueDays 自然日
7. `bills.service.spec.ts`：+9 例（404、PAID 拒收、未逾期 400、已缴清 400、生成建议、刷新建议不重复建单、确认入账、重复确认 409、查询 404）
8. `dto/dto-validation.spec.ts`：+5 例（空请求、完整字段、0 减免、负数、非整数）

## 决策记录

- **建议值唯一性**：同一账单最多一条未确认建议，重复调用刷新（避免定时任务每日重算时堆积重复记录）
- **确认后不再产生新建议**：已确认后再次调用返回 409，避免叠加计费（增量计费留待后续按需扩展）
- **到期日当天不算逾期**：`overdueDays = 0` 时拒绝（「到期日过后」才逾期）
- **入账语义（v1）**：`confirmedAmount/confirmedBy/confirmedAt` 即入账记录；滞纳金与收款核销的联动（收款总额含滞纳金、核销标记）需新增字段，留待后续任务（见交接记录遗留问题）
- 单位统一为「分」，与全系统金额一致
