# T216: 旧资料批量导入（CSV）

## 背景

`docs/00-项目计划书.md` §2.2 把「导入现有资料」列为第二阶段；§3.5 又把「数据补录（旧租客）」
列为人工事项。dev 库现有 153 位租客，逐条手录不现实，这是上线前的阻塞项。

## 范围

| 项 | 内容 |
|---|---|
| 实体 | 租客（`tenants`）、合同（`contracts`）、账单（`bills`），顺序固定 |
| 接口 | `GET /imports/:entity/template`、`POST /imports/:entity/preview`、`POST /imports/:entity/commit`（`dryRun` 默认 `true`） |
| 校验 | 必需列、格式、租客/房源/合同引用存在性、金额与日期、账期与类型组合判重 |
| 写入 | 校验全过后单事务写入；**任一行有错整批不写**；成功写一条 `IMPORT` 审计 |
| 前端 | 「系统设置 › 资料导入」逐步页：下载模板 → 选文件 → 预检（逐行错误）→ 确认写入 |

## 设计取舍

- **整批原子**：半批成功会让「哪些进来了」难以追踪，补录场景修好文件重跑成本低。
- **判重不覆盖**：租客按手机号、合同按合同编号、账单按（合同+账期+类型）。已存在记为 skipped，
  不覆盖人工在系统里改过的数据。
- **金额按字符串解析**：`1800.00` → 180000 分，避免浮点误差。
- **不引入 CSV 库**：模板由本系统输出，只需处理 BOM / CRLF / 引号 / 字段内换行。

## 验收标准

| # | 标准 | 验证 |
|---|---|---|
| 1 | CSV 解析正确（BOM、CRLF、引号、字段内换行、行号） | `csv-parse.spec.ts` 7 条 |
| 2 | 缺列 / 空文件 / 超 5000 行 → 400 | `imports.service.spec.ts` |
| 3 | 任一错误都阻止写入，且不记审计 | 单测「有错误时即使 dryRun=false 也不写库」 |
| 4 | `commit` 默认 dryRun，只有显式 false 才写 | 单测「默认 dryRun 为 true」 |
| 5 | 金额字符串精确转分 | 单测「写入时金额字符串精确转分」 |
| 6 | 三种角色：仅 ADMIN 可访问导入 | `authorization.e2e-spec.ts`「旧资料导入（T216）」 |
| 7 | OpenAPI 无漂移 | `npm run openapi:check` |
