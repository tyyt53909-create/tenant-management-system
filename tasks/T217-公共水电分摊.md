# T217: 公共水电分摊

## 背景

`docs/09-待确认清单.md` §7 明确：第一版公共区域水电「记为运营成本，不向租客分摊；分摊规则放第二阶段，预留」。
`PublicArea` 与公共 `Meter` 都已存在，`MeterBillingService` 对公共表直接返回「按运营成本处理，不扣费」，
分摊规则一直是空白。

## 范围

| 项 | 内容 |
|---|---|
| 数据模型 | `PublicUtilityBill`（楼栋+表类型+账期唯一）与 `PublicUtilityAllocation`（单据+合同唯一） |
| 总额来源 | ① 公共表当月首尾读数 × 单价自动计算；② 直接录入总额 |
| 分摊基数 | 计费月内生效中（ACTIVE）且房间面积非空的合同，按面积占比 |
| 接口 | `GET /public-utilities`、`GET /:id`、`POST /preview`、`POST /`、`POST /:id/generate-bills`、`DELETE /:id` |
| 开单 | 「生成补缴账单」按分摊逐条创建 `UTILITY` 账单，幂等键 `UTILITY:ALLOC:{allocationId}` |

## 关键规则

- 金额以分为单位；每笔向下取整，余额补给基数最大的一笔 → 分摊合计恰好等于总额
- 公共表读数不足两笔或末读数小于首读数 → 400
- 面积缺失的房间不参与分摊（不按 0 面积白拿）
- 已生成账单的单据不可删除

## 验收标准

| # | 标准 | 验证 |
|---|---|---|
| 1 | 分摊合计等于总额（含余数处理） | `allocation.spec.ts` 6 条 |
| 2 | 公共表用量计算与三种 400 情形 | `public-utilities.service.spec.ts` |
| 3 | 生成补缴账单幂等、跳过 0 金额、记录生成时间 | 同文件 |
| 4 | 三角色权限（仅 ADMIN） | `authorization.e2e-spec.ts`「公共水电分摊（T217）」 |
| 5 | 迁移可在新库执行 | `migrate deploy` 于新建库 |
| 6 | OpenAPI 无漂移、docs-check 表数一致 | `npm run openapi:check`、`node scripts/check-docs.js` |

## 不在范围

- 后台页面（本轮只做接口）
- 按人头/按房间均摊等其他分摊方式
