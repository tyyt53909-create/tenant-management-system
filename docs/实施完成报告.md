## 🔧 批量添加元信息的方法

### 方法 1：手动添加（推荐）

在每个文档开头添加以下头部：

```yaml
---
status: draft
owner_tier: strong
applies_to:
  - 相关代码路径
last_verified: 
verified_commit: 
supersedes: null
superseded_by: null
version: 1.0
---
```

**各文档的 applies_to 建议**：

| 文档 | applies_to |
|------|------------|
| 00-项目计划书.md | 全项目（留空或 `null`） |
| 01-架构设计.md | `src/**` |
| 03-权限矩阵.md | `src/common/guards/**` |
| 04-状态机.md | `src/modules/**/**.service.ts` |
| 05-接口规范.md | `src/modules/**/**.controller.ts` |
| 06-安全与合规清单.md | 全项目 |
| 07-测试策略.md | `src/**/*.spec.ts` |
| ADR 文档 | `null`（决策类文档） |

### 方法 2：使用脚本（需 Node.js）

创建 `scripts/add-metadata.js`：

```javascript
const fs = require('fs');
const path = require('path');

const docs = [
  { file: 'docs/00-项目计划书.md', tier: 'human', applies: null },
  { file: 'docs/01-架构设计.md', tier: 'strong', applies: 'src/**' },
  { file: 'docs/03-权限矩阵.md', tier: 'strong', applies: 'src/common/guards/**' },
  // ... 其他文档
];

docs.forEach(({ file, tier, applies }) => {
  const content = fs.readFileSync(file, 'utf-8');
  
  const metadata = `---
status: draft
owner_tier: ${tier}
applies_to:${applies ? `\n  - ${applies}` : '\n  - null'}
last_verified: 
verified_commit: 
supersedes: null
superseded_by: null
version: 1.0
---

`;
  
  fs.writeFileSync(file, metadata + content);
  console.log(`✅ 已处理: ${file}`);
});
```

运行：`node scripts/add-metadata.js`

## 🎯 CODEOWNERS 实施说明

### 单人仓库下的实施步骤

由于您提到可能所有提交来自同一个 GitHub 账号，CODEOWNERS 的实施需要特别说明：

#### 方案 A：仅作为提醒标记（推荐）

1. **修改 CODEOWNERS**：将所有 `@owner` 替换为您的 GitHub 用户名
   
   例如：`@owner` → `@zhangsan`

2. **GitHub 仓库设置**：
   - Settings > Branches > Branch protection rules
   - 保护 `main` 分支
   - 启用 "Require a pull request before merging"
   - 启用 "Require approvals" 设置为 1
   - **不启用** "Require review from Code Owners"

3. **效果**：
   - PR 中会自动标记 CODEOWNERS 涉及的文件
   - 提醒您这些文件需要特别注意
   - 自己审核后点击 "Approve" 再合并

#### 方案 B：使用第二个账号

如果您有多个 GitHub 账号（如个人 + 工作账号）：

1. 将第二个账号添加为仓库协作者（只读权限）
2. 在 CODEOWNERS 中使用第二个账号作为审核人
3. 启用 "Require review from Code Owners"
4. 关键 PR 需切换到第二个账号审核

#### 方案 C：邀请协作者

邀请信任的朋友/同事作为只读协作者，负责审核关键代码。

## 🔍 文档检查脚本说明

### 当前模式：警告模式

脚本当前运行在**警告模式**（`DOCS_STRICT_MODE=false`），意味着：

- ✅ 检查 INDEX.md 一致性
- ✅ 检查元信息完整性
- ✅ 检查内部链接有效性
- ⚠️  代码变更需同步文档（仅警告，不阻止合并）
- ⚠️  文档过期检查（仅输出提醒）

### 何时升级为严格模式

当代码开始开发后，修改 `.github/workflows/docs-check.yml`：

```yaml
- name: 运行文档检查（严格模式）
  run: |
    node scripts/check-docs.js --strict
  env:
    DOCS_STRICT_MODE: 'true'
```

严格模式下，代码变更未同步文档会导致 CI 失败。
