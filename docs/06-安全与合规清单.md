## 1. 个人信息保护

### 1.1 个人信息分类

根据《中华人民共和国个人信息保护法》，系统涉及的个人信息分类：

| 信息类型 | 字段 | 敏感等级 | 处理方式 |
|----------|------|----------|----------|
| **一般个人信息** | 姓名、性别 | 低 | 明文存储，列表脱敏 |
| **个人联系方式** | 手机号、邮箱、地址 | 中 | 明文存储，列表脱敏 |
| **敏感个人信息** | 证件号码 | 高 | 加密存储，列表不返回 |
| **财务信息** | 账单、收款记录、余额 | 中 | 明文存储，权限隔离 |
| **生物识别信息** | - | - | 第一版不涉及 |

### 1.2 数据加密要求

#### 传输加密
- ✅ 所有接口强制 HTTPS（TLS 1.2+）
- ✅ 证书由可信 CA 签发（Let's Encrypt / 阿里云）
- ✅ 禁用 HTTP 明文传输（80 端口重定向到 443）

#### 存储加密
```typescript
// 字段级加密：证件号
model TenantRegistration {
  idNumber String  // 加密存储（AES-256-GCM）
}

// 加密实现
import * as crypto from 'crypto';

const ALGORITHM = 'aes-256-gcm';
const KEY = process.env.ENCRYPTION_KEY; // 32字节密钥

function encrypt(text: string): string {
  const iv = crypto.randomBytes(16);
  const cipher = crypto.createCipheriv(ALGORITHM, KEY, iv);
  
  let encrypted = cipher.update(text, 'utf8', 'hex');
  encrypted += cipher.final('hex');
  
  const authTag = cipher.getAuthTag();
  
  // 返回格式：iv:authTag:encrypted
  return `${iv.toString('hex')}:${authTag.toString('hex')}:${encrypted}`;
}

function decrypt(encrypted: string): string {
  const [ivHex, authTagHex, encryptedText] = encrypted.split(':');
  
  const iv = Buffer.from(ivHex, 'hex');
  const authTag = Buffer.from(authTagHex, 'hex');
  const decipher = crypto.createDecipheriv(ALGORITHM, KEY, iv);
  
  decipher.setAuthTag(authTag);
  
  let decrypted = decipher.update(encryptedText, 'hex', 'utf8');
  decrypted += decipher.final('utf8');
  
  return decrypted;
}
```

### 1.3 数据脱敏规则

| 字段 | 原始值 | 脱敏后 |
|------|--------|--------|
| 手机号 | 13812345678 | 138****5678 |
| 邮箱 | user@example.com | u***@example.com |
| 证件号 | 11010119900101001X | 不返回（完全隐藏） |
| 银行卡号 | 6222021234567890 | 622202******7890 |

**实现示例**：
```typescript
// common/utils/mask.util.ts
export class MaskUtil {
  static phone(phone: string): string {
    if (!phone) return '';
    return phone.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
  }

  static email(email: string): string {
    if (!email) return '';
    const [name, domain] = email.split('@');
    const maskedName = name.charAt(0) + '***';
    return `${maskedName}@${domain}`;
  }
}

// DTO 使用
export class TenantListItemDto {
  id: string;
  name: string;
  
  @Transform(({ value }) => MaskUtil.phone(value))
  phone: string;
  
  @Transform(({ value }) => MaskUtil.email(value))
  email: string;
}
```

| **合同操作** | 创建、修改、终止、续签 |
| **权限变更** | 创建用户、修改角色、禁用账号 |

### 2.2 密码安全

| 要求 | 实现 |
|------|------|
| 加密算法 | bcrypt（salt rounds = 10） |
| 密码强度 | 至少 8 位，包含字母和数字 |
| 密码策略 | 不存储明文密码，不可逆向 |
| 密码重置 | 通过邮箱验证链接（30分钟有效） |

```typescript
import * as bcrypt from 'bcrypt';

const SALT_ROUNDS = 10;

async function hashPassword(password: string): Promise<string> {
  return bcrypt.hash(password, SALT_ROUNDS);
}

async function verifyPassword(password: string, hash: string): Promise<boolean> {
  return bcrypt.compare(password, hash);
}
```

### 2.3 会话管理

| 配置 | 值 |
|------|-----|
| Access Token 有效期 | 7天 |
| Refresh Token 有效期 | 30天 |
| Token 存储 | Redis（支持主动失效） |
| 并发登录限制 | 允许（同一用户多设备） |
| 异常登录检测 | 记录 IP 变化，异地登录提醒（第二阶段） |

**Token 撤销**：
```typescript
// 登出时撤销 Token
async function logout(userId: string, token: string) {
  // 将 Token 加入黑名单（有效期内）
  const ttl = this.jwtService.decode(token).exp - Math.floor(Date.now() / 1000);
  await this.redis.setex(`blacklist:${token}`, ttl, '1');
}

// JWT 验证中间件
async function validateToken(token: string) {
  // 1. 验证 Token 签名
  const payload = this.jwtService.verify(token);
  
  // 2. 检查黑名单
  const isBlacklisted = await this.redis.get(`blacklist:${token}`);
  if (isBlacklisted) {
    throw new UnauthorizedException('Token 已失效');
  }
  
  return payload;
}
```

## 3. 数据备份与恢复

### 3.1 备份策略

| 数据类型 | 备份频率 | 保留周期 | 备份位置 |
|----------|----------|----------|----------|
| 数据库全量 | 每天凌晨 3:00 | 30天 | 阿里云 RDS 自动备份 |
| 数据库增量 | 实时（Binlog） | 7天 | 阿里云 RDS |
| 对象存储 | 实时（版本控制） | 永久 | 阿里云 OSS |
| 审计日志 | 每月归档 | 永久 | 阿里云 OSS |
| 配置文件 | Git 版本管理 | 永久 | GitHub / GitLab |

### 3.2 备份验证

**上线前必须完成备份恢复演练**：

```bash
# 演练清单
1. 下载最新的数据库备份文件
2. 在测试环境恢复数据库
3. 验证数据完整性（记录数、关键表数据）
4. 验证应用可正常连接和查询
5. 记录恢复耗时（RTO: Recovery Time Objective）
6. 记录数据损失情况（RPO: Recovery Point Objective）
```

**目标**：
- RTO（恢复时间目标）：1 小时内完成恢复
- RPO（数据丢失目标）：5 分钟内的数据（通过 Binlog 增量恢复）

### 3.3 灾难恢复预案

**场景 1：数据库故障**
1. 切换到 RDS 从库（如果配置了主从）
2. 通知运维和开发团队
3. 分析故障原因
4. 从备份恢复主库
5. 重建主从同步

**场景 2：应用服务器故障**
1. 负载均衡自动切换到健康实例
2. 重启故障实例或启动新实例
3. 检查日志和监控指标
4. 修复根因问题

**场景 3：对象存储文件丢失**
1. 从 OSS 版本历史恢复文件
2. 检查文件完整性
3. 更新数据库中的文件 URL（如需要）

## 9. 安全事件响应预案

### 9.1 数据泄露事件

**响应流程**：
1. **确认泄露范围**（1小时内）
   - 泄露了哪些数据？
   - 影响多少用户？
   - 泄露途径是什么？

2. **止损措施**（4小时内）
   - 关闭泄露接口
   - 撤销泄露的 Token
   - 强制受影响用户修改密码

3. **通知用户**（24小时内）
   - 邮件/站内通知受影响用户
   - 说明泄露的信息类型
   - 提供补救措施

4. **上报监管**（72小时内）
   - 如涉及敏感信息，上报网信办
   - 准备事件报告

5. **复盘改进**（7天内）
   - 分析根因
   - 修复漏洞
   - 更新安全措施

### 9.2 账号被盗事件

**用户自助措施**：
- 通过邮箱重置密码
- 联系管理员冻结账号

**管理员操作**：
1. 冻结账号（禁止登录）
2. 撤销所有 Token
3. 检查异常操作（审计日志）
4. 回滚恶意操作（如有）
5. 通知用户重置密码
6. 解冻账号
