# 备份、PITR 与恢复演练（OPS-07 / T280）

> 目标：任何一次误删/误改都能在可接受时间内恢复，并且**演练过**。

## 1. 备份策略

| 层级 | 方式 | 频率 | 保留 |
|---|---|---|---|
| 逻辑备份 | `scripts/backup-db.sh`（pg_dump custom） | 每日 | 14 天（`RETENTION_DAYS` 可调） |
| 物理/PITR | 托管 RDS 自动备份或 WAL 归档 | 持续 | 按云厂商策略（建议 ≥7 天） |
| 对象存储 | OSS 版本控制/跨区域复制 | 按需 | 与业务约定 |

- 逻辑备份文件：`tenant-<db>-YYYYmmdd-HHMMSS.dump` + `.sha256`。
- 默认 `umask 077`；备份目录权限应仅运维账号可读。
- 备份文件**必须异地/对象存储留存**；本脚本只负责本机文件，上传由部署侧 cron/OSS 工具完成。
- 生产备份失败应接告警（可复用 OPS-04 `AlertService` 或外部监控）。

## 2. 每日备份

```bash
DATABASE_URL='postgresql://...' \
BACKUP_DIR=/var/backups/tenant \
RETENTION_DAYS=14 \
./scripts/backup-db.sh
```

建议 crontab（UTC）：

```cron
30 18 * * * cd /opt/tenant && DATABASE_URL=... BACKUP_DIR=/var/backups/tenant ./scripts/backup-db.sh >> /var/log/tenant-backup.log 2>&1
```

（北京时间 02:30，避开 01:00 定时任务。）

## 3. 恢复

```bash
DATABASE_URL='postgresql://...目标库' ./scripts/restore-db.sh backups/tenant-....dump --yes
```

- 先按文件内容校验 `.sha256`（脚本自动做），不依赖 checksum 里记下的旧路径。
- `pg_restore --dbname` 连接目标库；不要把连接串当成备份文件名。
- `--clean --if-exists` 会删除目标库同名对象；**禁止对生产库直接试**。
- 过期清理按文件名里的 UTC 时间，解析不出时间的文件不删。
- 恢复后执行 `npx prisma migrate deploy` 确认迁移状态（备份来自旧版本时）。

## 4. 恢复演练（每月至少一次）

1. 创建独立空库 `tenant_rehearsal`；
2. 执行：

```bash
REHEARSAL_DATABASE_URL='postgresql://.../tenant_rehearsal' \
  ./scripts/restore-rehearsal.sh backups/tenant-....dump --yes
```

3. 脚本校验 public 表数 ≥20，并打印 bills/users 行数；
4. 抽查登录、账单列表、最近一笔收款；
5. 记录演练时间、备份文件、耗时、问题；
6. 清理演练库（`DROP DATABASE tenant_rehearsal`）。

> 演练库与 `DATABASE_URL` 指向同一数据库时脚本会拒绝执行（忽略密码、默认端口和 query），防止只改 `sslmode` 就覆盖生产库。

## 5. PITR（按 DEC-07 托管数据库）

- 若使用阿里云 RDS/托管 PostgreSQL：开启自动备份 + WAL 归档，按时间点恢复由控制台完成；恢复后同样执行第 4 节抽查。
- 若自建 PostgreSQL：需配置 `archive_mode=on`、`archive_command`/`pgBackRest`，本仓库不内置 WAL 归档脚本。
- 逻辑备份不能替代 PITR：它只能恢复到备份时刻。

## 6. 已知边界

- 脚本假定 `pg_dump/pg_restore` 与数据库主版本兼容（PostgreSQL 16）。
- 本机无 `postgresql-client` 时脚本会明确报错；CI 不执行真实备份。
- 备份加密由存储层（OSS 加密/磁盘加密）负责；如需客户端加密，后续可加 GPG 包装。
- 未自动上传对象存储，部署侧需补 cron/生命周期策略。
