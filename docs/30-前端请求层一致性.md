# 前端请求层一致性（COM-05 / T285）

## 1. 问题

ISS-25：前端用中文 `message` 判断错误。表现有三类：

1. **按文案分支**：`message.includes('正在轮换中')` 决定是否重试刷新 —— 后端改一个字，多标签页并发刷新就会把用户踢下线。
2. **按状态码猜原因**：`status === 409` 就提示「房态已被其他人更新」，但 409 也可能是唯一键冲突。
3. **重复提示**：请求层拦截器已弹「账单已缴清」，页面 `catch` 又弹「删除失败」，用户看到两条互相矛盾的消息。

## 2. 统一解析

`utils/apiError.ts` 是唯一解析入口：

```ts
const { code, message, status, details, requestId } = parseApiError(error);
```

- `code`：后端 `AllExceptionsFilter` 保证存在的业务错误码（`ERROR_CATALOG`）。
- `message` 取值顺序：**校验 details → 错误码文案表 → 后端 message → 调用方 fallback**。
  错误码文案放在前端常量表里，避免把后端 `message`（可能含 SQL、字段名）直接展示。
- 无响应 → 网络错误文案；`ERR_CANCELED` → 「请求已取消」，调用方不应提示。

## 3. 不再用中文判断

| 位置 | 旧 | 新 |
|---|---|---|
| `utils/request.ts` 刷新重试 | `message.includes('正在轮换中')` | `code === 'AUTH_REFRESH_ROTATING'` |
| `RoomStatusDialog` 版本冲突 | `status === 409` | `code === 'ROOM_VERSION_CONFLICT'` |

后端为此新增错误码 `AUTH_REFRESH_ROTATING`（401），`jwt.service.ts` 的并发宽限分支改用
`apiError(ErrorCode.AUTH_REFRESH_ROTATING)` 抛出，`codeForMessage` 保留旧文案兜底映射。
`docs/05` §5.2 已登记，`error-codes.spec.ts` 双向校验通过。

## 4. 提示去重

`utils/notify.ts`：

- `markApiErrorNotified(error)`：请求层弹过提示后标记该异常对象；
- `notifyApiError(error, fallback)`：已提示过 / 已取消 → 静默返回 `false`；否则按统一解析提示并标记；
- `notifyLocalError(message)`：本地校验错误（文件类型、必填项）直接提示。

请求层只对非 `silentError` 请求提示；页面 `catch` 一律用 `notifyApiError`，因此同一个失败
只会出现一次提示，且内容是后端给出的具体原因。

## 5. 覆盖范围

- `request.ts`、`useDialogForm`、`usePagedTable`、`csv.ts`（导出）。
- 页面：bills / tenants / maintenance / checkout / contracts / buildings / rooms / meters /
  cleaning / audit / statistics / public / settings（Tag、BusinessSettings、DataImport、InviteCodes）。
- 组件：ReceiptModal、SettlementVoucherModal、VoucherRecognitionModal、TenantAccountCapabilities、
  ContractAttachments、RoomPhotoEditor、RoomStatusDialog、MeterFormDialog、BatchReadingDialog、
  MeterSimulatorDialog。
- 剩余 `ElMessage.error('固定文案')` 仅用于**本地前置校验**（例如「请填写新单价」）或
  「已由调用方明确文案」的场景，不读取后端 message。

## 6. 已知边界

- 错误码文案表需要与后端 `ERROR_CATALOG` 同步；后端新增错误码未登记时，前端回退展示后端 message。
- 不统一做「错误码 → 国际化」，当前只有中文。
- 小程序端（`miniprogram/`）请求层尚未接入，留待 FE-02。
