## 2. 生产 docker-compose 说明

当前 `docker-compose.yml` 是**本地开发**编排（PostgreSQL 16 + Redis 7，端口映射到宿主机、弱密码、`restart: unless-stopped`）。**不可直接用于生产**。

### 2.1 与开发的差异要求

| 项 | 开发现状 | 生产要求 |
|---|---|---|
| 数据库 | 容器内 PostgreSQL，密码 `tenant_password` | 优先使用**阿里云 RDS**；若自建容器则必须强密码 + 内网隔离，**不映射端口到公网** |
| 端口暴露 | `5432`/`6379` 映射到宿主机 | 数据库与 Redis **不对外映射**，仅容器网络内可达 |
| 应用进程 | `npm run start:dev` | `npm run build` 后 `node dist/main`（或 `npm run start:prod`） |
| 反向代理 | 无 | Nginx/Caddy 终止 TLS，转发 `/api` 到后端，静态托管 `frontend-admin/dist` |
| 日志 | 控制台 | 落盘 + 轮转（或云日志服务） |
| 重启策略 | `unless-stopped` | 建议 `always` 并配置健康检查 |
| 迁移 | `prisma migrate dev` | **`npx prisma migrate deploy`**（只前滚，不重置） |
| 种子 | `prisma db seed` | 仅在首次部署执行，且**必须**显式提供 §1.1 的四个账号变量 |

### 2.2 首次部署顺序（建议）

```bash
# 1) 准备环境变量（不要提交）
cp backend/.env.example backend/.env   # 然后逐项改为生产值

# 2) 安装依赖并生成 Prisma Client
cd backend && npm ci && npx prisma generate

# 3) 只前滚迁移（生产禁用 migrate dev / db push）
npx prisma migrate deploy

# 4) 首次初始化账号（生产必须显式提供强凭据，否则脚本拒绝执行）
NODE_ENV=production ADMIN_EMAIL=... ADMIN_PASSWORD=... \
  CLEANER_EMAIL=... CLEANER_PASSWORD=... npx prisma db seed

# 5) 构建并启动
npm run build && NODE_ENV=production node dist/main

# 6) 前端构建（生产 API 必须 HTTPS）
cd ../frontend-admin && npm ci && VITE_API_BASE_URL=https://<domain>/api npm run build

# 7) 小程序构建（生产 API 必须 HTTPS，构建期强校验）
cd ../miniprogram && npm ci && VITE_API_BASE_URL=https://<domain>/api npm run build:mp-weixin
```

### 3.2 逻辑备份（自建 PostgreSQL 时）

```bash
# 全库自定义格式备份（可并行、可选择性恢复）
pg_dump -h <host> -U tenant_user -d tenant_system -Fc -f tenant_system_$(date +%F).dump

# 仅数据（结构由迁移管理）
pg_dump -h <host> -U tenant_user -d tenant_system --data-only -f data_$(date +%F).sql
```

### 3.3 恢复步骤

```bash
# 1) 停应用，避免写入
# 2) 空库恢复（-c 会先 DROP，生产慎用；建议恢复到新库后切换）
createdb -h <host> -U tenant_user tenant_system_restore
pg_restore -h <host> -U tenant_user -d tenant_system_restore -Fc tenant_system_2026-10-13.dump

# 3) 校验迁移状态与关键数据
cd backend
DATABASE_URL='postgresql://...@<host>:5432/tenant_system_restore?schema=public' npx prisma migrate status
# 关键表计数核对：users / tenants / contracts / bills / payment_records / late_fees

# 4) 切换 DATABASE_URL 并重启应用
```

## 4. 已知部署限制（务必阅读）

1. **本机存在三套 PostgreSQL 实例**（5432 无迁移历史、5433 无 `late_fees.settledAmount`、5434 迁移完整）。部署到新环境时**必须**用 `prisma migrate deploy` 从零建立，不要复制本地数据目录。
2. **本机 3000 端口被 colima ssh 占用**，后端开发端口实际为 `3100`；生产请显式设置 `PORT` 并在反代中对应。
3. 前端 dev proxy 已修正为默认 `127.0.0.1:3100`，无需 `.env.local` 直连即可使用同源 `/api`。若改后端端口，同步设置 `VITE_API_PROXY_TARGET`。**生产走 Nginx 反代，不依赖该 proxy**。
4. 文件上传默认落本地磁盘（`UPLOAD_DIR`），多实例部署时必须改为 OSS 或共享存储，否则各实例文件不互通。
5. 存活探针用 `GET /api/health/live`（`/api/health` 同义，只表示进程还在）。就绪探针用 `GET /api/health/ready`。数据库、Redis 或上传目录任一不可用时 ready 返回 503，live 仍返回 200。上传目录必须已经存在且进程可写。
6. 生产镜像自 T253 起基于 `node:24-alpine`；容器收到 SIGTERM 后先停止接收新请求，再关闭定时任务与 Prisma/Redis 连接，25 秒未关完会强制退出。`docker-compose.prod.yml` 已设置 `stop_grace_period: 30s`、`init: true`、只读根文件系统（`/tmp` 为 tmpfs，`uploads` 为可写卷）、`cap_drop: ALL` 与 `no-new-privileges`；不要在容器内写入根文件系统。

### 7.3 HTTPS 与小程序合法域名

1. 把证书放到 `./certs/fullchain.pem` + `./certs/privkey.pem`，用 TLS 叠加文件启动：
   `docker compose -f docker-compose.prod.yml -f docker-compose.tls.yml --env-file .env.prod up -d`；
   默认发布 `443:8443`（可用 `WEB_TLS_PORT` 改端口），TLS 1.2/1.3 + HSTS + HTTP/2。不叠加时保持纯 HTTP，证书缺失不影响启动。
   也可以在前端挂 Caddy/云 LB 终止 TLS（后端保持 HTTP，`TRUST_PROXY=1` 已在 compose 中设置）。
2. 小程序生产构建强制 `VITE_API_BASE_URL=https://<合法域名>/api`（`utils/api-config.js` 构建期校验，localhost 必失败）。
3. 微信公众平台 → 开发管理 → 服务器域名：`request`/`uploadFile`/`downloadFile` 三项加 `https://<合法域名>`；`socket` 如用 MQTT over WS 另加 `wss://<合法域名>`。

### 7.4 发版与回滚

### 7.5 变量清单与接手部署（T211）

**为什么单独写这一节**：`docker-compose.prod.yml` 用 `${VAR:?}` 做必填插值，缺任何一个都会直接拒绝启动；而 `.env.prod` 按红线不入库。结果是「只有最初部署的那个人能重新部署」—— 实际发生过一次：接手时仓库里没有变量清单，只能从运行中的容器反查真实值。现在模板进了仓库，**值仍然只在部署机（或密码管理器）**。

- 模板：仓库根目录 [`.env.prod.example`](../.env.prod.example) —— `cp .env.prod.example .env.prod && chmod 600 .env.prod`，再把所有 `CHANGE_ME` 换成真实值。

**compose 硬性要求（缺一即拒绝启动）**

| 变量 | 说明 |
| --- | --- |
| `DB_PASSWORD` | PostgreSQL 密码 |
| `JWT_SECRET` | ≥32 字节随机串 |
| `ENCRYPTION_KEY` | 32 字节随机串（证件号字段级加密） |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 初始管理员；生产 seed 守卫拒绝默认邮箱/密码，密码 ≥12 位 |
| `CLEANER_EMAIL` / `CLEANER_PASSWORD` | 初始保洁账号，同上 |

**有默认值（可不设）**：`TAG`（`local`）、`BACKEND_IMAGE` / `WEB_IMAGE`、`WEB_PORT`（80）、`WEB_TLS_PORT`（443）、`DB_USER` / `DB_NAME`、`REDIS_PASSWORD`（空=不启用 `--requirepass`）、`STORAGE_DRIVER`（`local`）、`OSS_*`、`VITE_API_BASE_URL`（`/api`）。

**接手已有部署的最短路径**

1. 找部署机上的 `.env.prod`（若无，向原部署者索取；值在密码管理器里，**不要**从容器反查后写进仓库）；
2. 没有就按 `.env.prod.example` 重建，密钥类变量见下方红线；
3. `docker compose -f docker-compose.prod.yml --env-file .env.prod up -d` → `curl -sf http://<host>/api/health`。

**密钥红线（改之前想清楚）**

- 多实例部署约束见 `docs/24-多实例运行约束.md`：共享 Redis/DB/对象存储，`MULTI_INSTANCE=true` 时禁止本地 uploads。
- 后台任务 Worker 与队列变量见 `docs/23-后台任务与队列.md`；生产 compose 已含 `worker` 服务。
- 指标抓取与告警变量见 `docs/22-可观测性与告警.md`；Prometheus/Grafana 实例由部署侧提供，不在仓库内配置。
- `ENCRYPTION_KEY` 更换必须走换钥流程（T271）：新钥写入 `ENCRYPTION_KEY`、旧钥写入 `ENCRYPTION_KEY_PREVIOUS` → `npm run rotate:id-numbers`（dry-run）→ `npm --prefix backend run rotate:id-numbers -- --apply` → 验证后移除旧钥。旧钥只用于解密，不用于加密。
- `JWT_SECRET` 更换会让所有已签发令牌立即失效（用户需重新登录）—— 这通常是想要的，但要挑时间点。
- `DB_PASSWORD` 更换需要同时改数据库侧（compose 不会替你改）。

### 7.6 Nginx 边界（T254 / OPS-03）

- **上传上限**：`client_max_body_size 10m`，与后端 `files` 模块的 `MAX_SIZE=10MB` 一致。8MB 照片可通过；超过 10MB 由 nginx 直接返回 `413`，响应体为 JSON：`{"code":"PAYLOAD_TOO_LARGE","message":"请求体超过 10MB 上限"}`。
- **安全头**：所有静态响应与错误响应带 `X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`、`Permissions-Policy`、`Content-Security-Policy`；`/index.html` 单独重复声明，避免 `add_header` 覆盖。CSP 显式放行 `https://accounts.google.com`（Google 登录）。
- **限流**：`limit_req_zone` 按来源 IP 30r/s、burst 60，超限返回 `429`；接口级配额仍由后端 `THROTTLE_*` 控制。若前面还有云 LB，nginx 看到的是 LB 地址，需按实际拓扑调整 `real_ip`。
- **HTTPS**：见 §7.3；启用后 8443 返回 `Strict-Transport-Security`，HTTP/2 开启。
- **校验**：改配置后 `docker compose ... up -d --build web`，再执行 `curl -I https://<域名>/` 与一次 11MB 上传确认 JSON 413。
