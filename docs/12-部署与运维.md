## 1. 环境变量清单

### 1.1 后端（`backend/.env`，**不入库**，见 `.gitignore` 第 17 行）

| 变量 | 必填 | 生产要求 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | ✅ | 生产指向 RDS，且**必须**带 `?schema=public` | Prisma 连接串 |
| `NODE_ENV` | ✅ | `production` | 影响 seed 守卫、错误暴露粒度。邮箱万能码只在值正好为 `development` 且 `OTP_DEV_BYPASS=true` 时生效。值为 `production` 且未设置 `TRUST_PROXY` 时，信任一层反向代理 |
| `OTP_DEV_BYPASS` | 生产必须关闭 | 未设置或非 `true` | 与 `NODE_ENV=development` 同时成立才接受验证码 `123456` |
| `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` | 生产要发邮箱验证码时必填 | 缺任一项则拒绝发送 | 不把验证码写入日志。`SMTP_PORT` 默认 465，`SMTP_FROM` 可选 |
| `TRUST_PROXY` | 可选 | 一层 Nginx 时用 `1` | `false`/`0` 关闭，`true` 信任全部跳数，正整数为跳数。本地直连保持关闭，避免伪造 `X-Forwarded-For` |
| `THROTTLE_GLOBAL_LIMIT` | 可选 | 默认 100 次/分钟/IP | 全局限流。`THROTTLE_AUTH_LIMIT` 默认 10 次/分钟，`THROTTLE_OTP_LIMIT` 默认 5 次/小时/邮箱 |
| `PORT` | ✅ | 建议 3000（对外由反代转发） | 监听端口 |
| `JWT_SECRET` | ✅ | **≥32 字节随机串**，禁止默认值 | 缺失时启动即抛错（fail-closed，见 `config/jwt.config.ts`） |
| `JWT_ACCESS_EXPIRY` | 可选 | 默认 `15m` | Access Token 有效期 |
| `JWT_REFRESH_EXPIRY` | 可选 | 默认 `7d` | Refresh Token 有效期 |
| `ENCRYPTION_KEY` | ✅ | 32 字节随机串 | 证件号等字段级加密 |
| `UPLOAD_DIR` | 可选 | 建议挂载持久卷 | 文件上传目录；**未在 `.env.example` 中登记**（见 §6 待确认） |
| `REDIS_HOST` / `REDIS_PORT` | 生产必填 | 生产指向云 Redis，默认 `localhost:6379` | OTP 与限流计数。生产连不上则拒绝启动；开发连不上时降级为进程内存并警告 |
| `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` | P1 | 真实密钥，**仅存于环境变量** | 阿里云 OSS |
| `OSS_BUCKET` / `OSS_REGION` | P1 | — | 同上 |
| `DEFAULT_BUILDING_ID` | 可选 | 默认 `building-001` | 单楼栋部署时的默认楼栋 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | ✅ 生产 | **必须显式提供**，密码 ≥12 位 | 初始管理员；缺失时生产 seed 直接拒绝执行 |
| `CLEANER_EMAIL` / `CLEANER_PASSWORD` | ✅ 生产 | **必须显式提供**，密码 ≥12 位 | 初始保洁账号；同上。**未在 `.env.example` 中登记**（见 §6） |

### 1.2 前端后台（`frontend-admin/.env.local` 或构建期注入）

| 变量 | 说明 |
|---|---|
| `VITE_API_BASE_URL` | 后端 API 地址。**未配置时回退 `/api`**（配合 Vite dev proxy 或 Nginx 反代）。生产必须为 HTTPS 且带 `/api` 前缀。 |
| `VITE_API_PROXY_TARGET` | 仅开发服务器使用，默认 `http://127.0.0.1:3100`，须与后端 `PORT` 一致。不影响生产反代。示例见 `frontend-admin/.env.example`。 |

开发启动：在 `backend/` 准备未入库的 `.env`（不要覆盖已有密钥或数据库连接），安装依赖后执行 `npm run start:dev`；在另一终端执行 `npm --prefix frontend-admin run dev`。打开 `http://localhost:5173` 或 `http://127.0.0.1:5173`。
开发服务器只监听本地 IPv4 回环，固定端口 5173（占用时报错，不自动换端口）。新工作树不会自动继承主工作树未跟踪的 `.env`，须单独配置；不得提交真实配置。

### 1.4 密钥红线（AGENTS.md §8）

## 2. 生产 docker-compose 说明

当前 `docker-compose.yml` 是**本地开发**编排（PostgreSQL 16 + Redis 7，端口映射到宿主机、弱密码、`restart: unless-stopped`）。**不可直接用于生产**。

### 2.1 与开发的差异要求

| 项 | 开发现状 | 生产要求 |
|---|---|---|
| 数据库 | 容器内 PostgreSQL，密码 `tenant_password` | 优先使用**阿里云 RDS**；若自建容器则必须强密码 + 内网隔离，**不映射端口到公网** |
| 端口暴露 | `5432`/`6379` 映射到宿主机 | 数据库与 Redis **不对外映射**，仅容器网络内可达 |
| 应用进程 | `npm run start:dev` | `npm run build` 后 `node dist/main`（或 `npm run start:prod`） |
| 反向代理 | 无 | Nginx/Caddy 终止 TLS，转发 `/api` 到后端，静态托管 `frontend-admin/dist` |
| 日志 | 控制台 | 落盘 + 轮转（或云日志服务） |
| 重启策略 | `unless-stopped` | 建议 `always` 并配置健康检查 |
| 迁移 | `prisma migrate dev` | **`npx prisma migrate deploy`**（只前滚，不重置） |
| 种子 | `prisma db seed` | 仅在首次部署执行，且**必须**显式提供 §1.1 的四个账号变量 |

### 2.2 首次部署顺序（建议）

```bash
# 1) 准备环境变量（不要提交）
cp backend/.env.example backend/.env   # 然后逐项改为生产值

# 2) 安装依赖并生成 Prisma Client
cd backend && npm ci && npx prisma generate

# 3) 只前滚迁移（生产禁用 migrate dev / db push）
npx prisma migrate deploy

# 4) 首次初始化账号（生产必须显式提供强凭据，否则脚本拒绝执行）
NODE_ENV=production ADMIN_EMAIL=... ADMIN_PASSWORD=... \
  CLEANER_EMAIL=... CLEANER_PASSWORD=... npx prisma db seed

# 5) 构建并启动
npm run build && NODE_ENV=production node dist/main

# 6) 前端构建（生产 API 必须 HTTPS）
cd ../frontend-admin && npm ci && VITE_API_BASE_URL=https://<domain>/api npm run build

# 7) 小程序构建（生产 API 必须 HTTPS，构建期强校验）
cd ../miniprogram && npm ci && VITE_API_BASE_URL=https://<domain>/api npm run build:mp-weixin
```

## 3. 备份与恢复

### 3.1 备份策略（docs/09-待确认清单.md §14 已确认）

- 数据库：使用**云数据库自动快照**，每日一次，保留 30 天
- 对象存储：开启**版本控制**或定期复制
- ❌ 不做异地备份（第二阶段再议）
- ✅ **上线前必须做一次恢复演练并写入 `docs/07-测试策略.md`**

### 3.2 逻辑备份（自建 PostgreSQL 时）

```bash
# 全库自定义格式备份（可并行、可选择性恢复）
pg_dump -h <host> -U tenant_user -d tenant_system -Fc -f tenant_system_$(date +%F).dump

# 仅数据（结构由迁移管理）
pg_dump -h <host> -U tenant_user -d tenant_system --data-only -f data_$(date +%F).sql
```

### 3.3 恢复步骤

```bash
# 1) 停应用，避免写入
# 2) 空库恢复（-c 会先 DROP，生产慎用；建议恢复到新库后切换）
createdb -h <host> -U tenant_user tenant_system_restore
pg_restore -h <host> -U tenant_user -d tenant_system_restore -Fc tenant_system_2026-10-13.dump

# 3) 校验迁移状态与关键数据
cd backend
DATABASE_URL='postgresql://...@<host>:5432/tenant_system_restore?schema=public' npx prisma migrate status
# 关键表计数核对：users / tenants / contracts / bills / payment_records / late_fees

# 4) 切换 DATABASE_URL 并重启应用
```

## 4. 已知部署限制（务必阅读）

1. **本机存在三套 PostgreSQL 实例**（5432 无迁移历史、5433 无 `late_fees.settledAmount`、5434 迁移完整）。部署到新环境时**必须**用 `prisma migrate deploy` 从零建立，不要复制本地数据目录。
2. **本机 3000 端口被 colima ssh 占用**，后端开发端口实际为 `3100`；生产请显式设置 `PORT` 并在反代中对应。
3. 前端 dev proxy 已修正为默认 `127.0.0.1:3100`，无需 `.env.local` 直连即可使用同源 `/api`。若改后端端口，同步设置 `VITE_API_PROXY_TARGET`。**生产走 Nginx 反代，不依赖该 proxy**。
4. 文件上传默认落本地磁盘（`UPLOAD_DIR`），多实例部署时必须改为 OSS 或共享存储，否则各实例文件不互通。
