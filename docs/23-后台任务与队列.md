# 后台任务与队列（OPS-05 / T278）

> 决策：DEC-06 使用 BullMQ + Redis；Web 只负责触发，Worker 独立消费，失败可重试/查看/重放。

## 1. 角色

| 进程 | 启动 | 职责 |
|---|---|---|
| Web（`dist/main.js`） | `npm run start:prod` | HTTP API；`@nestjs/schedule` 只做 cron 触发；`PROCESS_ROLE=web` |
| Worker（`dist/worker.js`） | `npm run start:worker` | 消费 `scheduler` 队列；`PROCESS_ROLE=worker`，不触发 cron |

- `QUEUE_ENABLED=true`：cron 入队，Web 不执行任务；Worker 执行。
- `QUEUE_ENABLED=false`（默认）：保持旧的同步执行，适合本地/单机/测试。
- 手动 `POST /api/scheduler/:name/run` 始终同步执行，便于立即看结果。

## 2. 队列

- 队列名：`scheduler`；prefix：`QUEUE_PREFIX`（默认 `tenant-jobs`，Web/Worker 必须一致）。
- jobId：`{任务名}-{去重键}`（BullMQ 不允许冒号）：
  - `daily-jobs-2026-10-25`
  - `monthly-bill-generation-2026-10`
  - `notification-cleanup-2026-10-25`
- 多实例 Web 同时 cron：同 jobId 只入队一次；最终仍由 PostgreSQL 咨询锁保证只执行一次。
- 重试：`QUEUE_ATTEMPTS`（默认 3）+ 指数退避 `QUEUE_BACKOFF_MS`（默认 5000）。
- 完成任务保留 100 条；失败任务**不自动删除**，由运维清理。

## 3. 运维接口（ADMIN）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/jobs/stats` | waiting/active/completed/failed/delayed；`enabled=false` 时 stats 为 null |
| GET | `/api/jobs/failed?limit=20` | 失败任务（id/name/data/failedReason/attemptsMade/timestamp） |
| POST | `/api/jobs/failed/:id/retry` | 重放失败任务 |
| DELETE | `/api/jobs/failed/:id` | 删除失败任务 |

## 4. 部署

`docker-compose.prod.yml` 增加 `worker` 服务（extends backend，覆盖 command 与 `PROCESS_ROLE=worker`，关闭健康检查）。启动：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d backend worker
```

本地开发：

```bash
cd backend
QUEUE_ENABLED=true REDIS_URL=redis://127.0.0.1:6379 npm run start:worker:dev
```

## 5. 优雅关闭

- Worker 收到 SIGTERM/SIGINT：`worker.close()` 等待当前任务 → `app.close()` 关闭 Prisma/Redis。
- 容器 `stop_grace_period` 继承 backend 的 30s；长任务需确保小于该值，或调大。

## 6. 已知边界

- 队列只承载定时任务；邮件/通知 Outbox 仍待 COM-01 后续接入。
- 未实现队列优先级、限流、独立 Worker 池；报表/邮件可后续拆队列。
- 未暴露 BullMQ 指标到 `/api/metrics`（OPS-09 可补）。
- 失败任务永久保留会占 Redis 内存；建议监控 `failed` 数并定期清理。
