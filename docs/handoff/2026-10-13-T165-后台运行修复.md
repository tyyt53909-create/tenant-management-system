# T165 后台换主题后无法使用：运行修复

## 范围与环境

- 用户要求：修复换 UI 后网页进不去，并检查其他问题。
- 分支：`feature/T165-admin-qiju-theme`；工作树：`glowing-engine`。
- 模型：GPT-6.1 Sol；本地修复未提交、未创建 PR。
- 保留原有主题提交及用户未跟踪的预览、脚本文件；未重置分支、未执行数据库迁移或 seed。

## 根因与修复

1. 新工作树没有后端 `.env`，3100 后端未运行，前端代理却指向被其他服务占用的 3000。
   - 代理默认改为 `127.0.0.1:3100`，支持 `VITE_API_PROXY_TARGET`；增加前端配置示例，后端 PORT 示例对齐 3100。
   - 从现有主工作树配置创建未入库、权限 600 的本地 `backend/.env`；没有覆盖已有配置或更换密钥。
   - 后端使用已有配置启动在 3100，前端现有 Vite 进程继续在 5173。
2. Vite 原来只监听 IPv6 `::1`，`127.0.0.1:5173` 连接被拒。
   - 显式监听 IPv4 本地回环，固定 5173，端口占用时不悄悄改端口。
3. 自定义 CSS 变量先于 Element Plus 基础 CSS 导入，被默认样式覆盖。
   - 导入顺序改为基础 CSS → 主题变量 → 全局样式；浏览器计算主色由 `#409eff` 恢复为 `#535b43`。
4. 房源分页缺少 `@current-change`，页码变化但数据不变。
   - 绑定 `fetchData`；真实浏览器确认第一次下一页后行数据变化。
5. 请求层 401 可无限刷新重试，登录失败也会重放密码请求，并发请求各自刷新，失败时清除所有本地设置。
   - 排除登录/注册/刷新请求，最多重试一次，共用刷新 Promise，刷新加超时和返回 token 校验；退出时仅删除认证 token。
   - 添加 5 个请求层回归测试和 2 个开发代理配置测试。
6. Vue Router 使用已弃用的 `next` 回调；账单和报修标签传空类型，引发组件警告。
   - 守卫改为返回值，标签使用合法的 `primary` / `info` 类型。
7. JWT 单元测试依赖未跟踪 `.env` 的密钥。
   - 只在该测试中注入明确的测试密钥并还原环境；不改运行时密钥校验。
