## 四之二、合并前修复的两个既有 CI 阻断（本轮最重要的发现）

合并 PR #19~#23 时，CI 第一次真正跑起来（此前 5 个 stacked PR 的 base 是 feature 分支，**根本不触发 CI**），于是暴露两个**既有**缺陷 —— 都不是本批改动引入的：

### 1. `backend-ci` 自 10-16 起一直是红的

- **现象**：`Lint, Type Check & Test` 在 `检查 OpenAPI 与前端类型` 步骤失败：
  `[env] 缺少环境变量 JWT_SECRET` → `Error: JWT_SECRET 环境变量未设置！` → exit 1。
- **根因**：`npm run openapi:check` 需要**启动 Nest**（导出 OpenAPI 要实例化 AppModule），而 `jwt.config` 缺 `JWT_SECRET` 即抛错；该步骤自己声明的 env 里有 `DATABASE_URL/NODE_ENV/REDIS_HOST/REDIS_PORT`，**唯独漏了 `JWT_SECRET`**。
- **时间线**（用 `gh run list` 核实）：backend-ci 最后一次成功是 **10-15**；`openapi:check` 这一步是 **10-16 21:24** 随 OPT-15/T188 加进来的 → 之后所有运行都是 failure。也就是说 `docs/13` 勾选的「三端 CI 全绿」从 10-16 起就不成立，而且**没人发现**，因为日常 PR 都是叠在 feature 分支上的（不触发 CI）。
- **修复**：把共享测试环境提到 **job 层级** `env:`（`DATABASE_URL`、`NODE_ENV=test`、`REDIS_HOST/PORT`、`JWT_SECRET`、`ENCRYPTION_KEY`），并删掉两个步骤里的重复 env —— 这样「新增步骤忘记带变量」这类问题不会再犯。
- **附带**：修好后 `npm run test:cov`（覆盖率门禁）也会第一次真正在 CI 跑；本地实测 **exit 0**（statements 90.14 / branches 79.81，阈值 85/72）。

### 2. `prisma:seed` 在 CI 里根本跑不起来（backend-e2e 与 Playwright 都挂在这）

- **现象**：`TypeError: Unknown file extension ".ts" for .../prisma/seed.ts`。
- **根因**：`prisma:seed` 与 `prisma.seed` 配置用的是 `ts-node --compiler-options '{"module":"commonjs"}'`，而 `backend/package.json` 是 `"type": "module"` → Node 20 下 ts-node 的 CJS 钩子对 `.ts` 不生效（本地 Node 26 恰好能跑，所以只在 CI 暴露）。
- **修复**：仓库里的 TS 执行统一到 **`tsx`**：`prisma:seed`、`prisma.seed` 配置、`simulate:meters`、`simulate:mqtt` 全部改 `tsx`，并把 `tsx` 显式加进 devDependencies（此前只靠 `npx tsx` 隐式取用）、移除 `ts-node`；Dockerfile 里提到 ts-node 的注释一并更正（构建期是 `tsc` 编译 seed，本就不需要）。
- **验证（全部在临时库上做，不碰 dev 数据）**：全新库 → `prisma migrate deploy`（含 T211 的新索引）✓ → `npm run prisma:seed` ✓ → `npx prisma db seed`（走配置）✓ → 查种子数据是否违反同房源唯一索引：**0 笔** ✓（CI 的 seed 不会撞新约束）。
