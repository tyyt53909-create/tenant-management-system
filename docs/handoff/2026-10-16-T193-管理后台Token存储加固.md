## 完成内容

### 1. 后端 HttpOnly Cookie 传输与安全响应头
- **依赖接入**：安装并接入 `helmet` 与 `cookie-parser`。
- **安全响应头**：配置 `configureSecurityAndMiddleware` 挂载 `helmet`，输出 `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin` 与 `X-Frame-Options: SAMEORIGIN`。
- **HttpOnly Cookie 工具与端点支持**：
  - 新增 `src/modules/auth/auth-cookie.util.ts`（包含 `setRefreshTokenCookie`、`clearRefreshTokenCookie`、`extractRefreshToken`）。
  - Cookie 属性：`httpOnly: true`, `secure: production`, `sameSite: 'strict'`, `path: '/api/auth'`, `maxAge: 7d`。
  - `AuthController.login`, `register`, `googleAuth`, `loginWithEmailCode` 在成功签发 token 时自动向客户端种植 HttpOnly `refresh_token` Cookie（同时保留响应体 JSON 以向后兼容小程序）。
  - `AuthController.refresh` 优先从请求体读取，缺失时自动从 `req.cookies.refresh_token` 读取，刷新成功后自动轮换更新 Cookie。
  - `AuthController.logout` / `logoutAll` 清除客户端 HttpOnly Cookie。
  - `RefreshTokenDto.refreshToken` 标记为可选以适配 Cookie 模式，并通过 openapi 校验。

### 2. 前端管理后台内存 Token 与静默刷新
- **彻底剥离 localStorage 中的 Token**：
  - `frontend-admin/src/utils/request.ts` 开启 `withCredentials: true`。
  - 导出 `setAccessToken` / `getAccessToken`，将 access token 全局保存在内存中。
  - `localStorage` 中不再保存任何 `access_token` 或 `refresh_token`（登出与过期时仅清除遗留的 legacy 键）。
  - 401 自动刷新：向 `/auth/refresh` 发起带凭据请求，通过服务端 HttpOnly Cookie 完成刷新，并将新 access token 存入内存重放原请求。
- **Pinia UserStore 与路由守卫**：
  - `useUserStore` 移除 `localStorage` 依赖，提供 `restoreSession()` 方法。
  - `router.beforeEach` 在用户进入或刷新受保护页面时，若内存中暂无 token，自动触发 `restoreSession()` 静默尝试恢复登录态；若 Cookie 存在则无感知恢复，无凭据则跳转登录页。
  - `useManagementStore` 移除 `localStorage` 检查，改为直接读取 `userStore.token`。
