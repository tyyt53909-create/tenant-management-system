## 一、OPT-07#2：`process.env` 收敛（已完成）

原先 `src/` 中有 16 处直接读 `process.env`。收敛成 **0 处实际读取**（剩余命中都是说明性注释）：

- **启动期配置集中化**：新增 `backend/src/config/bootstrap.config.ts`（`loadBootstrapConfig()` + `resolvePort()`），`main.ts` 不再读 env，只拿解析结果。
  - ⚠️ 关键顺序：必须在 `await NestFactory.create(AppModule)` **之后**才读。`ConfigModule` 是在模块初始化时才把 `.env` 载入 `process.env`，提前读会静默丢掉 `.env` 里的 `PORT`/`CORS_ORIGINS`/`LOG_LEVEL`/`TRUST_PROXY`。
  - 顺带修掉一个隐患：原 `app.listen(process.env.PORT ?? 3000)` 遇到非法 `PORT`（如 `abc`）会直接抛错，现在 `resolvePort` 回退到 3000。
- **纯函数/静态模块**改为参数传入：`createHttpLogger(level, stream?)`、`new AllExceptionsFilter(nodeEnv)`、`mountOpenApi(app, { enabled })`。
- **模块级常量**：`auth-cookie.util.ts` 原来的 `REFRESH_TOKEN_COOKIE_OPTIONS`（`secure: process.env.NODE_ENV === 'production'`）是**在 import 时求值**，早于 `.env` 载入；现改为 `refreshTokenCookieOptions(secure)`，由 `AuthController` 从 `ConfigService` 取 `NODE_ENV` 后传入（7 个调用点）。
- **DI 工厂**：`meters.module.ts` 的 `METER_ADAPTER` 工厂改为注入 `ConfigService`。
- **删除冗余兜底**：`redis` / `files` / `google-auth` / `health` / `email-otp` / `crypto` 中的 `ConfigService.get(...) || process.env[...]` —— `ConfigService` 本身就回退到 `process.env`，这些兜底是多余的。
- 测试：新增 `backend/src/config/bootstrap.config.spec.ts`（6 例）；`http-logger` / `auth-cookie.util` / `auth.controller` / `health.service` 的 spec 按新签名与依赖更新。
- 例外：`*.spec.ts` 仍会刻意操作 `process.env`（测试注入配置），这是测试的正常用法。
