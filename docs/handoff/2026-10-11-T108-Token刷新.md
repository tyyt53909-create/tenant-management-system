## 技术实现

### Token 刷新流程

```typescript
POST /auth/refresh
{
  "refreshToken": "eyJhbGc..."
}

// 处理流程：
1. 验证 Refresh Token → jwtService.verifyToken()
2. 解析 payload（userId, role）
3. 查询用户 → prisma.user.findUnique()
4. 检查用户是否存在 → 不存在返回 401
5. 检查用户是否激活 → 未激活返回 403
6. 生成新的 Access Token → jwtService.refreshAccessToken()
7. 返回新 Token

// 响应：
{
  "accessToken": "eyJhbGc..."
}
```

### 为什么只返回 Access Token？

**设计决策**：
- Refresh Token 不轮换（保持原 Refresh Token 有效）
- 前端保存 Refresh Token（HttpOnly Cookie 或 LocalStorage）
- 只在 Access Token 过期时调用刷新接口
- 简化前端实现

**替代方案**（未采用）：
- 轮换 Refresh Token（每次刷新都生成新的 Refresh Token）
- 优点：更安全（限制 Token 重用）
- 缺点：复杂度高，需要管理 Token 失效

### 错误处理

```typescript
try {
  const payload = await this.jwtService.verifyToken(dto.refreshToken);
  // ... 验证用户
  const accessToken = await this.jwtService.refreshAccessToken(...);
  return { accessToken };
} catch {
  // 捕获所有验证失败（Token 无效、过期等）
  throw new UnauthorizedException('Token 无效或已过期');
}
```

**优点**：
- 统一错误处理
- 不暴露具体错误原因（安全）
- 前端处理简单（401 = 重新登录）

## 前端集成示例

### 自动刷新 Access Token

```typescript
// axios 拦截器示例
axios.interceptors.response.use(
  response => response,
  async error => {
    const originalRequest = error.config;
    
    // Access Token 过期（401）
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;
      
      try {
        // 刷新 Token
        const { data } = await axios.post('/auth/refresh', {
          refreshToken: localStorage.getItem('refreshToken')
        });
        
        // 更新 Access Token
        localStorage.setItem('accessToken', data.accessToken);
        
        // 重试原请求
        originalRequest.headers.Authorization = `Bearer ${data.accessToken}`;
        return axios(originalRequest);
      } catch {
        // Refresh Token 也失效，跳转登录
        window.location.href = '/login';
      }
    }
    
    return Promise.reject(error);
  }
);
```

### Token 存储建议

| Token 类型 | 存储位置 | 有效期 | 说明 |
|----------|---------|--------|------|
| Access Token | 内存 或 LocalStorage | 15分钟 | 短期，频繁使用 |
| Refresh Token | HttpOnly Cookie（推荐） 或 LocalStorage | 7天 | 长期，仅用于刷新 |

**安全建议**：
- Refresh Token 使用 HttpOnly Cookie（防止 XSS）
- HTTPS 传输（防止中间人攻击）
- 定期轮换 Refresh Token（可选）
