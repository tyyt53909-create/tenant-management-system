## 为什么做这个

复查 `docs/00-项目计划书.md` 时发现 §2.1「必做功能」与 §3.3 第 2 周的「标签管理」**从未实现**：
`Tenant.tags` 只是一个没有任何入口、没有校验、没有任何展示的 `Json?` 列。这是第一版 P0 范围里唯一剩下的功能项。

## 数据模型

| 变更 | 说明 |
|---|---|
| 新增 `Tag` | `id / name（唯一）/ sort / createdAt / updatedAt` |
| 新增 `TenantTag` | 复合主键 `(tenantId, tagId)`，两侧 `onDelete: Cascade` |
| 删除 `Tenant.tags` | 旧 JSON 列 |

迁移 `20261018170000_tenant_tags`：

1. 建两张表与索引
2. 把既有 `tenants.tags` 里的字符串数组回填为 `tags` 与 `tenant_tags`（ID 用 `'tag_' || md5(name)`，同名复用）
3. `jsonb_typeof(...) <> 'array'` 的旧值忽略（该列从未有界面入口，实际不含业务数据）
4. 删除 `tenants.tags`

**验证过**：在空库执行 `migrate deploy` 全链路成功；另建测试库插入 `["學生","有寵物"]`、`["學生"]`、`NULL`、`{"a":1}` 四类数据后执行，得到 2 个字典项、3 条关联，对象型旧值被正确忽略。

## 后端

- `/tags`：`GET` 对 ADMIN / TENANT / CLEANER 开放（打标签时的候选），`POST/PATCH/DELETE` 仅 ADMIN
- `GET /tags` 返回 `tenantCount`（使用人数），删除确认时用
- 租客 `create/update` 接受 `tagIds`：
  - 未传 → 不改动；传 `[]` → 清空；最多 20 个
  - 任一 ID 不存在 → **400**（不静默忽略，否则用户会以为保存成功）
- `GET /tenants?tagId=` 支持按标签筛选
- 响应里的 `tags` 是 `{ id, name }[]`，按字典 `sort`、`name` 排序

## 管理后台

- 租客列表新增「标签」列与标签筛选下拉
- 新增/编辑弹窗新增多选标签（可选可清空）
