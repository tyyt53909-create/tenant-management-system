# T160 管理后台真实使用体验修复（2026-10-13）

## 背景
用户要求「在真正使用的细节方面优化，提升使用便捷性」。
本轮先做 UX 审计，再按影响面修复，不做无依据的改动。

## 发现并修复的问题

### 1. 翻页失效（阻断级 · 6 个页面）
分页同时绑定了 v-model:current-page 与 @current-change="handleQuery"，
而 handleQuery 第一行是 pagination.page = 1 —— 点第 2 页会被立刻弹回第 1 页。
**翻页功能实际从未可用**。

受影响：bills / checkout / contracts / maintenance / meters / tenants

修复：current-change 只负责拉数据，不再重置页码；tenants 另拆 handleSizeChange
（仅在「每页条数」变化时回第 1 页）。

### 2. 租客搜索必然 400（阻断级）
租客页有「姓名」「手机号」输入框，但后端 QueryTenantsDto 未声明这两个参数，
配合全局 forbidNonWhitelisted → 一填就 400。主搜索入口完全不可用。

修复：DTO 补 name/phone；服务层模糊查询（name 大小写不敏感、phone 支持只输后几位）；
空串/纯空格视为不筛选。

顺带修 isActive：原 @Type(() => Boolean) 会把查询串 "false" 转成 true
（与 T156 的 unreadOnly 同类问题），改为 @Transform。

### 3. 回车不能查询
15 个列表页只有 1 处支持 @keyup.enter。用户在筛选框输入后本能按回车，无反应。

修复：给有文本输入的查询表单加回车支持（tenants 2 处、contracts、rooms、cleaning）。
纯下拉筛选的页面无需处理。

### 4. 删除确认不含对象标识
8 处确认框有 5 处只写「确定要删除吗？」，看不出删的是哪条。

修复：全部补对象标识与后果说明，按钮统一为「确定删除/取消」：
合同编号 / 账单编号 / 报修标题 / 水电表号 / 楼栋名 / 租客姓名 / 房号；
后果提示含「不可恢复」「历史读数一并删除」「名下仍有合同会被后端拒绝」等。

### 5. 空状态无法区分「无数据」与「筛选无结果」
13 个列表页有 9 个用默认「暂无数据」，用户筛选后无法判断是系统没数据还是
条件没命中，容易误以为数据丢失并重复录入。

修复：按是否有筛选条件给不同提示
- 有筛选：「没有符合条件的 X，试试调整 …」
- 无筛选：「暂无 X，点击右上角「新增 X」开始录入」

### ⚠️ Element Plus sort-method 陷阱（重要，供后续参考）
EP 传给 sort-method 的入参形态**随列的 sort-by 配置而变**：
- 配了 sort-by → 传 { value: <字段值> }
- 没配 sort-by → 传**整行对象**
写成 Number(row) 会得到 NaN → 比较器恒返回 0 → 表格「点表头没反应」，
**不报错、极难定位**（本轮为此实测多轮才确认）。
结论：**不写 sort-method**，统一用内置 sortable + sort-by。
前提已验证：金额为整数（分）、日期后端一律返回完整 ISO 串（核验 200 条 0 例外）。
日期列另派生「仅日期」字段（dueDateOnly/startDateOnly/endDateOnly）使排序键与显示值一致。
