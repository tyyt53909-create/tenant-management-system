## 文档类型定义

### 事实来源类（Truth Source）
**定义**: 必须与代码严格同步，代码变更时必须更新。

**包括**:
- 数据模型、权限矩阵、状态机、接口规范、架构设计

**更新要求**:
- 代码变更时同步更新文档
- 更新 `last_verified` 和 `verified_commit`
- CI 检查代码变更是否同步文档

---

### 决策类（Decision）
**定义**: 只新增不修改，通过 supersedes 取代旧决策。

**包括**:
- ADR（架构决策记录）
- 安全与合规清单
- 测试策略

**更新要求**:
- 不修改已有文档内容
- 新决策创建新文档并设置 `supersedes` 字段
- 旧文档状态改为 `superseded`

---

### 过程类（Process）
**定义**: 记录项目过程，完成后归档。

**包括**:
- 项目计划书
- 任务书
- 交接记录
- 周报

**更新要求**:
- 只追加更新记录，不修改原内容
- 完成后改为 `archived` 状态
- 移入 `docs/archive/` 或保留原位

---

## 新增文档流程

1. **创建文档**，填写完整元信息（见模板）
2. **在 INDEX.md 中登记**（添加到对应分类表格）
3. **提交 PR**，CI 自动检查
4. **合并后文档生效**

### 元信息模板

```markdown
---
status: draft                          # draft | active | superseded | archived
owner_tier: strong                     # human | strong | medium | cheap
applies_to:                            # 对应的代码路径（可多个）
  - src/modules/rooms/**
  - prisma/schema.prisma
last_verified:                         # 最后核对日期（YYYY-MM-DD）
verified_commit:                       # 核对时的 Git commit hash（前7位）
supersedes: null                       # 取代了哪份文档（可选）
superseded_by: null                    # 被哪份文档取代（可选）
version: 1.0                           # 文档版本号
---

# 文档标题

> 简短描述

**变更历史**：
- YYYY-MM-DD: 初始版本
- YYYY-MM-DD: 更新说明（commit: abc1234）
```

## 废弃文档流程

1. **将文档状态改为 `superseded` 或 `archived`**
2. **移动到 `docs/archive/` 目录**
3. **在 INDEX.md 中更新状态和归档位置**
4. **新文档的 `supersedes` 字段指向旧文档**

## 文档检查规则

### 自动检查（CI）
- ✅ INDEX.md 与实际文件一致
- ✅ 元信息完整且合法
- ✅ 内部链接有效
- ⚠️  代码变更需同步文档（警告模式）
- ⚠️  文档过期检查（>30天未核对）

### 人工检查
- 核心文档（owner_tier=human）需人工审核
- 数据模型、权限、状态机变更需确认
- ADR 新增需人工批准
