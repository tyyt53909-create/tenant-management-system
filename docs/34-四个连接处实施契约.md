## T335 的增量模型与行为（先前核验阶段）

本 PR 为 expand 步骤。`UtilityPolicyVersion` 保存合同及费用类型的不可变版本、明确选择的三种 collectionMode、六位小数的分额费率、单位、生效读数时点、确认人及依据。计算范围为 `METER_DELTA_FLAT_RATE`，舍入为 `HALF_UP_CHARGE_V1`，先以 decimal 合计再取整分。新增版本的生效点递增；相同规则的相邻段复用原版本。跨已有版本的责任段需在切点拆分。

`MeterResponsibilityInterval` 在本阶段只登记有真实起点、终点的闭合段，消费时间采用 `[startAt,endAt)`，起终读数差计算本段用量。相邻段可共享边界读数。TENANT 必须解析为指定合同及租客；OWNER 仅能登记已确认空置或无租约覆盖的区间。租客归属复用 T328 的交接事实解析，冲突及缺交接返回阻断。未来、模拟、乱序回退、跨物理表交接需先处理原问题。责任字段及读数以服务器资料确定。

数据库使用 `btree_gist` 及排他约束防止同表责任段重叠，另有起终时间、租客/房东字段形状、非负费率和版本唯一约束。部署迁移账号需具有安装 PostgreSQL 自带 `btree_gist` 扩展的权限。迁移可重跑，既有财务表保持原金额和来源。新表为空，存量规则通过管理者逐项核验后产生。

`UtilityRuleConfirmation` 保存 UUID 请求键、规范化资料哈希与原结果。相同请求重放返回原结果，异内容返回 `IDEMPOTENCY_CONFLICT`。规则、责任段、审计、重放结果同事务提交。预览的 SHA-256 包括实际表计、租约、区间读数、旧规则、已有责任段、账户和流水；确认锁内重读，变化返回 `PREVIEW_STALE`。阻断详情通过 `UTILITY_RULE_BLOCKED` 的 `details.blockingIssues` 返回。

核验接口返回 `financialPostingEnabled=false` 和 `financialEffect=NONE`。三种模式仅呈现试算。预付缺账户或账实不符另列 billingIssues，可以保存已核对的规则，正式计费仍需解除阻断。规则确认产生的纪录供下一步计费切换使用，正式资金授权仍需对相应费用及政策验收。

已核验某合同/费用类型的规则后，该项的既有即时、单表、批量与周期表计结算统一返回 `BLOCKED / RULE_POSTING_NOT_ENABLED`，保留原游标。该切换隔离防止后付或直缴继续被旧预付引擎收费。缺规则的存量处于原路径，本阶段的盘点逐项列出 LEGACY_REVIEW_REQUIRED；新规则正式计费及全部旧入口收口仍需后续切换 PR。

### 正式费用、规则与资金来源

`UtilityCharge` 是不可变消费事实，与 Bill、PaymentRecord 和 PrepayTransaction 分开。保存表计、房间、合同/租客、首个责任段及规则版本的限制删除外键，真实起终读数与时间、精确分段快照、所有使用的责任段及规则版本、模式、整数分总额/抵扣/应收/外部参考、资金凭证及经办人。全额预付也产生完整 Charge。空置 OWNER 只记录用量，金额为零。直缴只记录供应商参考费用，不代表已向供应商付款。

| 模式 | 预付账户 | 房东应收 | 供应商参考 |
|---|---|---|---|
| PREPAY_WITH_SHORTFALL | 正额费用须存在且余额与全量流水合计一致；锁内重读后抵扣可用额 | 只创建不足部分 UTILITY Bill | 0 |
| POSTPAID | 不要求、不自动扣款 | 全额 UTILITY Bill | 0 |
| DIRECT_TO_PROVIDER | 不要求、不扣款 | 不创建 Bill / PaymentRecord | 全额参考费用 |

内部模式满足 `totalAmount = prepayApplied + receivableAmount`；直缴满足 `totalAmount = providerAmount`，内部金额为零。数据库检查约束校验非负整数金额、凭证与正额的对应关系及模式形状；同表真实消费时间 `[startAt,endAt)` 使用排他约束禁止重叠，同时保留起终读数唯一键。不能换读数 ID 或请求 ID 重收已有区间。全局游标不回退，历史尾费落在游标后方时仍须受控更正流程；本切片不补收历史调整。

正式价格仅取已明确确认的 UtilityPolicyVersion，不以 Meter 当前显示价或旧可修改历史单价代替。相邻责任段可连续覆盖同一合同/租客；跨租客、跨合同或缺口不拼成一个费用。跨费率必须有真实界点读数，换表/回退须有已确认的旧表末数及新底数；合计 decimal 精确金额后 HALF_UP 一次取整分，费率字符串和版本 ID 随分段保存。跨收款模式须在界点分段结算。显示价变化不改变已确认条款。

### 开放责任段与封口

TENANT 可仅选择真实起读数，明确确认持续责任范围；不会生成虚构的未来终读数，也不推断未来入住事实。每次计费仍核对整段实际入住/退租证据。OWNER 必须有真实起终读数。封口通过原责任段编号、原起点/责任/规则及真实终点重新预览、明确确认；只追加真实终点和封口证据，原确认人及初始依据保留，另记本次审计。存在超出封口时点的已入账费用时阻断。开放段排他约束保护后续范围，实际交接时先封口再登记下一段。

### API、重放与事务

新增路由仅 ADMIN：

| 路由 | 行为 |
|---|---|
| POST /api/utility-charges/preview | meterId、可选 settleUntil；RepeatableRead 只读预览，financialEffect=NONE，返回来源、模式、金额及 reviewToken |
| POST /api/utility-charges/confirm | meterId、requestId UUID、reviewToken、同一 settleUntil；锁内重算，变化返回 PREVIEW_STALE |
| GET /api/utility-charges/:id | 查询持久正式费用与来源快照；非租客端路由 |

确认按请求 advisory lock → 排序 room → 排序 contract → 排序 meter → 覆盖检查 → prepay row 执行。人工、设备、批量读数、单表/批次结算和周期收费均调用同一报价和正式写入核心，不启动嵌套根事务。预付账户锁后再核对余额/流水，多个表不会复用同一可用额。验房确认、修改/删除以及退租完成先协调同一 room，锁内重读事实，避免中途改变归属依据；这里不宣称其他支付/押金/退款交错的全局 X-04 已验收。费用、抵扣、差额/全额应收、读数游标、待通知意图及 UtilityPostingConfirmation 原结果同事务提交；失败完整回滚。重复确认重放原结果，异内容返回 IDEMPOTENCY_CONFLICT。

周期工作台保留 T333 的逐项事务、持久结果和失败重试；结果增加 chargeId、collectionMode、prepayApplied、receivableAmount、providerAmount。预览指纹含规则、责任和账户流水状态；这些资料变化需重新检查与确认。同账户的前一项抵扣导致后一项预览分配变化时，后一项阻断要求重新预览，不静默更改已确认资金分配。直缴通知文案明确不产生房东应收。

Charge.notificationState=PENDING 是与费用同事务保存的待通知意图，尚无通用投递 worker，不表示外部送达。周期工作台原有站内通知仍按 T333 状态机执行并链接 chargeId，完整渠道状态/去重及待办归 LINK-03。

### 旧入口收口与操作

缺明确规则返回 LEGACY_REVIEW_REQUIRED；缺唯一连续责任或交接冲突返回 OWNERSHIP_UNRESOLVED；预付缺账户/账实不符、缺费率界点及未确认换表均 BLOCKED 并保留游标。既有已结算记录、账单和资金历史保持原凭证，不批量推断同意或回填重收。

手工创建 UTILITY Bill 和手工挂接 METER_READING 的预付流水已阻断；现有水电凭证金额不可改写。公共费用的单据、只读分摊和旧记录可查询，`generate-bills` 因尚无已确认分摊政策版本及历史责任来源，明确返回 UTILITY_RULE_BLOCKED，保留原单据。CSV 的 UTILITY 新增导入亦逐行报错，整批不入账；历史迁移须在后续独立核账流程完成。不能用这两条路径绕开 POSTPAID/直缴规则；它们的正式来源转换归 LINK-01 后续范围。

合同「水电规则与交接」先确认依据，再在「正式水电计费」查看五项金额后另行确认。网络响应丢失保留原请求，刷新后可重试。单表结算也携带预览令牌，资料变化不能静默执行。管理后台保留既有组件、手机布局和后端权限。对账独立列外部直缴参考，按正式费用事实核对金额，不能将直缴当作房东应收或收入。

T336 的真实数据库及桌面/手机验收见证据文件。外部支付、OCR、实表、短信/邮件/微信真实送达、Docker 冷启动及整包联合发布验收仍为 NOT_RUN；本 PR 不宣称完整四链发布就绪。
