## 🔴 P0：安全缺口（必须立即修复）

### 1. 租客数据完全无隔离 ⚠️ 严重

**问题描述**：
- 所有 GET 接口（/rooms、/bills、/contracts、/tenants）只有 `JwtAuthGuard`
- 没有 `@Roles` 装饰器
- 任何已登录租客可以查看所有租客的数据
- 违反权限矩阵：「租客只能访问自己的数据」

**影响**：
- 租客 A 可以查看租客 B 的账单、合同、个人信息
- 严重的隐私泄露风险

**修复方案**：
```typescript
// 1. 实现 BuildingGuard（数据隔离守卫）
// 2. 为所有租客相关接口添加 @Roles('TENANT') 和数据过滤
// 3. 在查询中添加 where: { tenantId: req.user.id }
```

**相关任务**：T110（Building 隔离守卫）

---

### 2. PII 明文存储 ⚠️ 严重

**问题描述**：
- `Tenant.idNumber` 以明文存储在数据库
- 列表接口直接返回身份证号
- 文档要求：AES-256-GCM 字段级加密 + 列表不返回

**影响**：
- 数据库泄露会暴露所有租客身份证号
- 不符合数据保护法规（GDPR、个人信息保护法）

**修复方案**：
```typescript
// 1. 创建加密工具类（AES-256-GCM）
// 2. Prisma middleware 自动加密/解密
// 3. DTO 中标记敏感字段，列表接口不返回
// 4. 数据库迁移：加密现有数据
```

---

### 3. JWT 加固不足 ⚠️ 高危

**问题描述**：
- `jwt.strategy.ts:17` 有硬编码 `'fallback-secret'` 兜底
- access/refresh 使用同一密钥
- 无令牌类型区分
- 无令牌轮换/撤销机制
- 邀请码「使用后失效」未实现

**影响**：
- 容易被暴力破解
- refresh token 泄露等同于永久访问权限
- 无法撤销已发放的令牌

**修复方案**：
```typescript
// 1. 移除 fallback-secret，强制环境变量
// 2. access/refresh 使用不同密钥
// 3. 在 payload 中添加 type: 'access' | 'refresh'
// 4. 实现 Redis 黑名单机制
// 5. InviteCode.usedAt 字段 + 验证逻辑
```

---

### 4. 审计日志完全缺失 ⚠️ 高危

**问题描述**：
- 没有实现任何审计日志
- 无法追溯敏感操作
- 文档要求：所有敏感操作可追溯
- 财务系统合规底线

**影响**：
- 无法审计账单、收款、退款操作
- 纠纷时无据可查
- 不符合财务合规要求

**修复方案**：
```typescript
// 1. 创建 AuditLog 实体和模块
// 2. 实现 AuditInterceptor
// 3. 标记需要审计的接口（@Audit 装饰器）
// 4. 记录：用户、操作、IP、时间、前后数据
```

**相关任务**：T112-T113
