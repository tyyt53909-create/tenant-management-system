## 📋 拆分原则

### 优先级排序逻辑

1. **地基优先**：后续所有模块依赖，出错代价最高
   - 项目骨架、数据库迁移、认证与邀请码、权限守卫、审计日志
   - 状态机框架、金额快照规则、预付账户流水

2. **样板模式**：完整做通一个模块作为范本
   - 房源模块（CRUD + 状态 + 权限 + 测试 + 文档）

3. **核心主线**：按业务依赖顺序
   - 租客 → 合同 → 账单 → 预付 → 报修 → 退租

4. **必做外围**：核心需求，不可延后
   - 公开看房页、收租提醒、滞纳金建议、站内通知

5. **可延后候选**：时间不足时砍
   - 保洁小程序端、基础统计、标签系统

6. **预留扩展**：第二阶段功能只做接口空实现
   - 仪表适配器、通知渠道、支付接口、设备令牌表
