## 1. 定位、基准与复核

- **审查基准**：`dd042e2`（2026-10-18，T213 合并）。
- **本轮复核基准**：`3af78e0`（2026-10-23，含 T230 照片上传 + OpenAPI 生成物修正；该分支尚未合入 `develop`）。
- **M0 落地基线**：`53df199`（`develop`）。若 T230 先合入，STATUS 中的 T230 会从 `unmerged` 转为 `verified`。
- **结论**：工程骨架与 AI 治理已成熟，但以“真实楼栋上线收租”为标准仍是演示级（约 2.3/5）。主要风险集中在生产可启动性、金流/合同正确性、身份与授权默认开放、扩展点只有骨架。
- **复核后仍成立的核心 P0**（现场 `git grep` 定位）：
  - Redis 只读 HOST/PORT，生产 `requirepass` 时 NOAUTH，且 `retryStrategy` 返回 `null`。
  - OTP 使用 `Math.random()`、明文存 Redis、失败计数非原子。
  - `RolesGuard` 在无 `@Roles` 时放行，且不是全局守卫。
  - 邮箱 OTP / Google 首登自动建立 TENANT，`email_verified ?? true`，`pending-` 假手机号。
  - 合同 `renew()` 在旧合同 ACTIVE 时为新合同建同房间 DRAFT，撞 `idx_contracts_room_id_unfinished`。
  - 出账排程只查 `paymentCycle = MONTHLY`，季付/半年付/年付永不出账。
  - 收款 `SELECT ... FOR UPDATE` 的错误被空 `catch` 吞掉，且没有 Idempotency-Key。
  - 财务数据可硬删除；P2003 被映射成 500。
  - 公开房源照片仍走需要 JWT 的 `/api/files/`。
  - `EmailChannel` 没有 transport，邮件静默丢弃；无优雅停机，镜像仍是 Node 20。
- **已部分修复**：RoomPhoto DTO 已拒绝站外 URL；JWT fallback 已成死代码（`jwt.config.ts` 会先抛错）；nginx 已有部分安全头；合同部分唯一索引已落库（但续签未适配）。
- **规模数字以现场为准**：`backend/prisma/schema.prisma` 当前 **37 models**，OpenAPI 当前 **154 条路由**（T252 新增 `/health/live`）；不要沿用分析中的 28/121。

## 3. 保留的设计（不得以重构为名推翻）

- 金额一律以「分」整数存放与计算。
- refresh token 用 HttpOnly cookie + 轮换 + Redis session，access token 短效。
- 登录与 OTP 入口的 Redis 限流。
- 上传做 magic-byte 检测与 EXIF 清除（本轮改为 fail-closed）。
- 证件号 AES-GCM 加密 + 独立查重 hash。
- `scopedWhere()` 租客数据隔离；范围 id 缺失必须 403，不得退化成全表查询。
- 房间乐观锁 `version`。
- 账单 `dedupKey` 防重、`JobRun` 任务记录、PostgreSQL advisory lock 防重入。
- OpenAPI 导出 + `openapi:check`；`scripts/check-docs.js` 文档检查；任务书/handoff 治理。

- **可靠性与运维**：生产 compose（含 `REDIS_PASSWORD`、HTTPS）冒烟通过；SIGTERM 30 秒内优雅退出；8MB 照片经 nginx 上传成功、11MB 回 413 JSON；自动备份 + 恢复演练脚本化；5xx/排程失败/备份失败/磁盘/证书告警可触达。
- **合规**：ICP 备案完成；小程序隐私保护指引与弹窗上线；审计日志不含明文个资；证件查看全程留痕。

### 4.2 UAT 主线（14 步，摘要）

1. 建楼栋/房间（含挂牌价与 3 张照片，其中一张 8MB）→ 上传成功、未登录可见、无 GPS EXIF。
2. 预建租客（证件号）→ 列表遮罩、库内密文、重复提示。
3. 生成 7 天一次性邀请码 → 绑定租客与角色。
4. 租客登录并输入邀请码 → 绑定预建租客；未受邀者被拒。
5. 建合同 → 送签 → 签署；同房间第二份重叠合同 → 409。
6. 生成押金账单并收款 → 押金台账余额 = 押金；收据连续编号。
7. 月付/季付合同（月中开始）触发开账 → 月付每月一张、季付每季一张、首期按日折算、重跑不重复。
8. 逾期账单 → +1 天标记逾期、滞纳金按日累计、−3/0/+1/+3/+7 各提醒一次。
9. 部分收款 → 同 Idempotency-Key 重送 → 作废该笔收款 → 只记一次、产生冲正、账单回待缴、审计有前后值。
10. 报修附照片 → 后台指派 → 双方留言 → 完工 → 租客确认并评价 → 实时可见、时间线完整。
11. 到期前 60 天提醒 → 发起续签 → 签署 → 旧合同 RENEWED、新合同次日 ACTIVE、账单不重不漏。
12. 发起退租 → 最终抄表 → 结算单 → 完成 → 含未缴/水电/扣款/押金退还；单一事务；押金台账归零。
13. 退租后保洁 → 自动建任务 → 指派 → 完成附照片 → 房态可租。
14. 审计日志 → 每步有记录；无密码、证件号明文。

M2 尚未具备的能力按分析 02 §11 的替代路径验证，并在验收记录注明“替代”。

```yaml
---
status: active                 # draft | active | completed
execution_status: active       # draft | active | blocked | completed，优先于 status

plan_ref: M0                   # M0–M5 或 SEC-01 / FIN-01 / OPS-08 / QLT-03
blocked_by: DEC-04, needs-human # 单行逗号分隔；无则留空

branch: docs/T250-m0-closeout
depends_on: T255
handoff: docs/handoff/2026-10-23-T250-M0生产化收口.md
---
```

规则：
- `parseFrontMatter` 只解析单行 `key: value`，**不要写 YAML 列表块**；`blocked_by`/`depends_on` 用单行逗号分隔。
- `acceptance_evidence` 放在 `tasks/evidence/`（不受 docs-check 的 frontmatter/INDEX 强制）。
- `completed` 必须同时有可验证的 merge 证据、handoff 文件、handoff 已登记 `docs/INDEX.md`。
- `plan_ref` 缺失或格式非法在 `task_id >= 250` 时为 error；`blocked_by` 只允许 `T\d{3}`、`DEC-0[1-9]`、`M[0-5]`、`needs-human`。
