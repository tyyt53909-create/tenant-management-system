# 管理后台：角色路由、型别化 API 与组件拆分（FE-01 / T286）

## 1. 角色路由（ISS-30）

此前 `router.beforeEach` 只判断「有没有 token」，任何已登录账号都能打开管理页面。后果：

- 保洁点进「账单与收款」，页面先渲染骨架、再连续 403，看起来像系统故障；
- 侧栏显示全部入口，等于给了错误的功能预期；
- 后端虽然拦住了数据，但前端没有任何「你不该在这里」的明确反馈。

### 实现

| 位置 | 变化 |
|---|---|
| `src/utils/access.ts` | `canAccessRoute` / `filterNavigation` / `roleLabel` 纯函数 |
| `src/router/index.ts` | 每条路由声明 `meta.roles`；守卫在取到用户后校验，不允许则跳 `/forbidden` |
| `src/views/forbidden/index.vue` | 说明当前角色、所需角色，并提供「返回可用首页 / 退出登录」 |
| `src/components/layout/MainLayout.vue` | 侧栏与 `⌘K` 搜索走同一份过滤后的导航 |

### 角色矩阵（前端可见入口）

| 页面 | ADMIN | CLEANER | TENANT |
|---|---|---|---|
| 工作台 `/dashboard` | ✅ | — | — |
| 房源 / 房源模型 | ✅ | ✅ | — |
| 保洁任务 | ✅ | ✅ | — |
| 通知中心 | ✅ | ✅ | ✅ |
| 账单 / 合同 / 租客 / 楼栋 / 水电 / 退租 / 预付 / 统计 / 审计 / 设置 / 公告 | ✅ | — | — |

与 `docs/03-权限矩阵.md` 的后端角色一致：前端只做「入口与提示」，真正的数据边界仍在后端守卫与服务层。

### 守卫细节

- 用户信息缺失（刷新页面首次导航）时先 `fetchUserInfo()` 再判断，避免把「还没加载完」误判成无权限。
- 未声明 `meta.roles` 的路由视为「需要登录、任何角色可访问」；未登录仍走 `/login`。
- `/forbidden` 自身不参与校验，防止重定向循环。
- 「返回可用首页」按角色分流：保洁回 `/cleaning`，其余回 `/dashboard`（保洁没有工作台权限）。

## 2. 型别化 API

- `api/meters.ts`：`settleMeter` / `getUnsettledUsage` / `settleBatch` 从 `Promise<any>` 改为
  `MeterSettleResult` / `UnsettledUsage` / `SettleBatchResult`，字段与后端
  `meter-billing.service.ts` 的返回一致（含 `settled`/`usage`/`amount`/`reason`/`deduction`）。
- `api/statistics.ts`：`getBuildingsForFilter` 去掉 `.then((res: any) => res.data)`，
  显式断言响应形状后再取 `data`。
- `types/index.ts`：`User.role` 增补 `CLEANER`（后端 `UserRole` 一直有该值，前端类型此前漏了）。

## 3. 大组件拆分

`views/bills/index.vue` 636 行，混着展示规则、滞纳金状态机与交互。抽出
`src/utils/billRow.ts` 纯函数：

| 函数 | 职责 |
|---|---|
| `unpaidOf` / `paymentSummary` / `paymentTitle` | 未缴金额与收款摘要（溢缴不为负） |
| `overdueDaysOf` / `showOverdue` | UTC 口径逾期天数；后端 `isOverdue` 优先 |
| `canReceive` | 哪些状态允许收款 |
| `lateFeeDisabledReason` | 滞纳金不可用原因（已缴清/已取消/未逾期/无欠款） |
| `lateFeeStateOf` / `lateFeeOutstanding` / `lateFeeDisplayAmount` | 滞纳金四态与未核销额 |
| `summaryToLateFee` | 账单自带摘要适配成 `LateFee`，省一次请求 |

页面只保留 Vue 响应式状态与交互，纯规则可被 `billRow.spec.ts` 直接覆盖（10 例）。

## 4. 已知边界

- 角色路由是**体验层**控制，不是安全边界；后端 `RolesGuard` 仍是唯一权威。
- 保洁的可用页面较窄（房源/空间/保洁/通知）；待 WRK-01 员工角色细化后再扩展。
- `views/space/index.vue`（859 行）未拆分，本轮只抽了账单页规则；空间模型涉及 2D/3D 渲染，
  拆分需要同步 fixture 与 Playwright 场景，留待后续。
- 前端类型仍以手写 `types/index.ts` 为主，`types/api.generated.ts` 仅覆盖 OpenAPI 路径级类型。
