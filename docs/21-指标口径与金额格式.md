# 指标口径与金额格式（FIN-10 / T275）

> 本文是「指标怎么算、金额怎么显示、导出走哪条管道」的唯一事实来源。
> 新增页面或报表若与本文件冲突，以本文件为准；确需新口径时先改本文并说明消费者。

## 1. 金额

- 数据库与 API 的金额一律是**分**（整数）。禁止在 DTO、Service、组件里存元或浮点金额。
- 后端换算统一用 `backend/src/common/utils/money.util.ts`：`yuanToCents` / `centsToYuan` / `centsToYuanString` / `formatCents`。
- 前端换算统一用 `frontend-admin/src/utils/money.ts`：`formatMoney`（`¥1,234.56`）、`formatMoneyPlain`（`1234.56`）、`formatSignedMoney`（`+¥1.00`）、`centsToYuan` / `yuanToCents`。
- `frontend-admin/src/utils/table.ts` 只做再导出，保留旧调用的兼容层。
- CSV 里的金额使用 `formatMoneyPlain` / `centsToYuanString`（不带 `¥`、不带千分位），避免 Excel 把带符号文本当公式或文本。
- 业务日期一律经 `BusinessClock`（`Asia/Shanghai`），禁止用进程本地时区推导账期/月份。

## 2. 指标口径

| 指标 | 定义 | 时间基准 | 消费者 |
| --- | --- | --- | --- |
| 出账 `billed` | 账单 `amount` 合计，排除 `CANCELLED` | 区间报表：`dueDate` 落在区间 | 统计页、管理摘要 |
| 已收 `paid` | 收款 `amount` 合计 | 区间报表：`paidAt` 落在区间；管理摘要：账单 `paidAmount` | 统计页、仪表板趋势、管理摘要 |
| 未收 `remaining` | `max(0, billed - paid)`；不含另计滞纳金 | 跟随所在视图 | 统计页、管理摘要 |
| 收缴率 `collectionRate` | `paid / billed`，保留 1 位小数；`billed = 0` 返回 `null` | 跟随所在视图 | 统计页、管理摘要 |
| 出租率 `occupancyRate` | 区间末存在有效合同（`ACTIVE/EXPIRED/RENEWED` 且日期覆盖该时刻）的房间数 / 房间总数，保留 1 位小数 | 区间末；区间在未来时取当前时刻 | 统计页、楼层分组 |
| 收入趋势 | 按 `PaymentRecord.paidAt` 的业务月归集，缺失月份补 0，单位分 | 近 N 个自然月 | 仪表板 |
| 水电用量/费用 | 月内读数 `usage` 合计；费用 = `usage × 读数业务日生效单价` | 读数 `readingTime` | 仪表板水电概览、对账 |

### 2.1 为什么统计页与管理摘要的数不一样

- **统计页**是区间报表：出账按 `dueDate`、收款按 `paidAt` 归入所选区间。
- **管理摘要**是全量快照：`billed = 所有未取消账单金额`、`paid = 所有账单 paidAmount`，用于「现在总共欠多少」，不是某个月的成绩。
- 两者都由 `finance-metrics.ts` 的同一组函数计算，差别只在传入的数据集与归期字段；管理摘要响应带 `caliber.scope = 'ALL_TIME'` 明确标注。
- 不允许把两者混在同一个卡片里比较，也不允许为对齐数字而改动对方口径。

### 2.2 出租率

- 按「区间末端」计算，而不是当前房态；历史报表不会串台到今天。
- 有效合同状态：`ACTIVE`、`EXPIRED`、`RENEWED`，且 `startDate <= asOf <= endDate`。
- 区间末端在未来时，`asOf` 截到当前时刻，避免前瞻性空档。

## 3. 导出管道

### 3.1 前端（管理后台）

唯一模块：`frontend-admin/src/utils/csv.ts`

- `toCsv(rows, columns)`：本地生成，带 UTF-8 BOM、引号转义、公式注入防护（以 `= + - @` 开头加 `'`）。
- `downloadCsv(content, fileName)`：把本地生成的 CSV 作为 Blob 下载。
- `downloadCsvFromServer(url, params, fileName)`：调用后端导出接口，统一成功/失败提示；原 `utils/export.ts` 已删除。
- 列定义集中在 `utils/resourceCsv.ts`，金额列用 `centsToYuan`。

### 3.2 后端

唯一模块：`backend/src/common/utils/csv.util.ts`（`generateCsv`），金额用 `money.util.ts`。

- 账单、预付流水、退租结算、抄表台账都复用同一个生成器。
- 导出接口只读，不得在导出过程中写库或触发扣费。

## 4. 空数据与演示值

- 任何指标在无数据时必须返回真实零值 + 明确的 `hasData: false`（或等价字段），由前端显示空态。
- **禁止**在 Service 或组件里写死演示数字（水电概览的 `isDemo` 演示数据已在 T275 移除）。
- 示例：`GET /meters/usage-overview` 返回 `hasData`，前端显示「暂无抄表数据」，不再回落 `32.6 m³` 之类的假值。

## 5. 业务默认值来源（T276）

- 新合同滞纳金规则：`SystemSetting.billing.defaultLateFeeRule`（设置中心）；合同显式 `lateFeeRule` 优先。
- 新预付账户预警阈值：`SystemSetting.prepay.defaultLowBalanceThreshold`；显式 `lowBalanceThreshold: 0` 保留 0。
- 水电表类型默认单价：`MeterPriceHistory`（`meterId IS NULL`），由设置中心写入；建表未传单价时使用。
- 环境级配置（JWT/Redis/SMTP/时区）不在设置中心，仍由环境变量与 `env.schema` 校验。

## 6. 验收清单

- `grep -rn '/ 100).toFixed\\|/100).toFixed' frontend-admin/src` 应只剩纯数量（用量、比例）计算。
- `grep -rn "utils/export" frontend-admin/src` 必须为 0。
- 新增指标必须复用 `finance-metrics.ts`，并在本文件第 2 节登记。
- 新增金额展示必须复用 `money.ts` / `money.util.ts`。
