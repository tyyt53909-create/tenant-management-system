# 管理后台设计系统（可读性与一致性基线）

> 本文件是 `frontend-admin` 的样式事实来源：令牌、字级地板、对比度要求、页面骨架与断点行为。
> 改动全局样式前先读本文件；改动后若动摇了下述基线，同步更新本文件并跑一遍 §6 的量测。

---

## 1. 为什么有这份文件

改动前，后台的样式分三层并行且互相覆盖，没有单一来源：

| 层 | 文件 | 载入方式 | 原状 |
|---|---|---|---|
| V2（原型移植） | `src/style.css` | `main.ts` | 定义了一整套 `--primary/--text-*` 令牌 |
| V3（全模块原型） | `src/styles/optimized-ui.css` | `MainLayout.vue` 的 `<style src>` | **又定义了一遍** `:root`，把 `--primary` 从 `#535b43` 改成 `#515c43`、`--text-muted` 改成 `#8d9087` |
| Element Plus 运行时 | `src/styles/element-variables.css` | `main.ts` | EP 组件用 V2 那组色，于是自绘组件与 EP 组件同屏不同色 |

结果是同一个橄榄绿在按钮和标签上是两个色值，而 `--text-muted` 一路浅到 3.0–3.5 的对比度。

## 2. 令牌：唯一来源

**所有颜色、字号、动效令牌集中在 `frontend-admin/src/styles/tokens.css`**，由 `main.ts` 在 `element-plus/dist/index.css` 之后、其余样式表之前引入。

- 其他样式表**只引用不重新定义**。`style.css` 的 `:root` 只剩基础排版（字体族、字号、前景/背景），`optimized-ui.css` 的品牌色覆盖块已删除。
- `element-variables.css` 的文字色引用本文件的令牌（`--el-text-color-secondary: var(--text-muted)`），保证 EP 组件与自绘组件同色。
- 品牌绿统一为 `#535b43` 系列（EP 与登录页本来就用这组，改动面最小）。

## 3. 文字对比度（WCAG AA = 4.5:1）

量测底色三处：卡片 `#fffefa`、页面 `#f7f5f0`、表头 `#f7f7f3`。

| 令牌 | 值 | 卡片 | 页面 | 表头 | 允许用在哪 |
|---|---|---|---|---|---|
| `--text-primary` | `#302f2a` | 13.29 | 12.42 | 12.55 | 正文与标题 |
| `--text-secondary` | `#5e6058` | 6.32 | 5.90 | 5.97 | 次级正文 |
| `--text-muted` | `#6f6c63` | 5.20 | 4.82 | 4.89 | **默认次级文字**：任何底色上都可以 |
| `--text-subtle` | `#78756b` | 4.57 | 4.23 ✗ | 4.29 ✗ | **只允许用在卡片底上的说明文字** |

**禁止新增浅于 `--text-muted` 的文字色。** 需要更轻的观感时，改用更浅的底色而不是更浅的字。

语义色作为**文字**时必须用加深变体（原色作文字时只有 3.6–4.4，连自己的浅底徽章都不达标）：

| 令牌 | 值 | 卡片 | 页面 | 自身浅底 |
|---|---|---|---|---|
| `--success-text` | `#4f7355` | 5.31 | 4.92 | 4.73（对 `#eaf3ed`） |
| `--warning-text` | `#98612f` | 5.09 | 4.72 | 4.56（对 `#fbf0e0`） |
| `--error-text` | `#a54f44` | 5.47 | 5.07 | 4.77（对 `#fbebe8`） |
| `--info-text` | `#556e75` | 5.37 | 4.98 | 4.67（对 `#f0eee7`） |

填充、边框、图形仍用 `--success/--warning/--error/--info` 原色。相关全局规则（`style.css`）：

- `link` 型按钮 → `*-text`（停用态除外，WCAG 豁免停用控件）；
- 提示条 `.el-alert--*` 的标题与描述 → `*-text`；
- 填充型语义色按钮（全站仅「批量抄表」一个）底色 → `--success-text`，白字才够 5.36。

## 4. 字级地板

- **任何文字不得小于 11px**（`--font-micro`）；语义性内容（表格副行 `.table-subline`、记录副行 `.record-cell small`）用 `--font-small`（12px）；页面标题用 `--font-title`（20px）。
- 手机断点同样适用：曾经把 `.management-metric p` 压到 9px、`h2` 压到 10px，现已取消。

## 5. 页面骨架与断点

- **每页必须有 `<h1>` 页面标题**：列表页统一由 `components/common/ResourcePanel.vue` 提供（`title` / `description` / `count`，操作按钮经 `#actions` 插槽 Teleport 到顶栏的 `#page-head-actions`）。`optimized-ui.css` 中把它压成 11px 灰标签的规则已移除，改为 `--font-title`。
- **卡片语言以 V3 为准**：`border: 1px solid var(--border)`、`border-radius: 13px`、`box-shadow: 0 18px 65px rgba(46,42,31,.043)`。仪表板的 `.metric-card` 已对齐这组值。`audit` / `buildings` / `statistics` 三个仍用 `el-card` 的页面已迁到 `ResourcePanel` + `.management-metric`。
- **顶栏两个触发器（`单据识别入账` / `搜索页面与服务…`）任何宽度都不得折行**：`white-space: nowrap`，且 ≤1120px 时整体切成 36×36 图标态（规则在 `optimized-ui.css` 末尾，因为 `search-trigger` 的宽度由该层定义）。1024–1120px 之间若不切换，文字会被 flex 压成一字一行的竖排；只加 `nowrap` 而不切换则会把顶栏撑出横向滚动。

## 6. 怎么验证

1. 起本 worktree 的 dev server（`.claude/launch.json` 的 `admin-worktree`，5176）。
2. 在浏览器面板执行本文件同款稽核脚本（遍历所有文字节点）：输出最小字号、低于 11px 的元素、每个文字节点与其**实际**背景的对比度。
3. 目视宽度：**808 / 1121 / 1440**。三个宽度下都应满足：顶栏 `scrollWidth == clientWidth`、文档无横向滚动、触发器高度 36。
4. 回归：`npm test`（12 文件 49 用例）、`npm run lint`、`npm run build`（含 `vue-tsc -b`）、`E2E_BASE_URL=http://127.0.0.1:5176 npx playwright test e2e/01-login.spec.ts`。

## 7. 已知例外与不在范围

- **装饰性元素不适用文字标准**（已逐一确认非文字）：仪表板 `·` 分隔点（1.75）、`UtilitiesOverviewCard` 的 `.dot`、`property-detail` 的空态图标 `#929783`、房间符号 `#888b75`、`.record-glyph` 的 `#7c846e`，以及各类图标底色（均 ≥3:1）。
- **停用态不适用**：`全部标记已读`、账单行的 `收款` / `滞纳金` 等 `is-disabled` 按钮仍是浅色，属 WCAG 豁免范围。
- `src/styles/element-plus.scss` 全库无 import，是死代码（改了也不会生效）；`sass` 仍在 devDependencies。清理另议。
- 重新整理页面或 refresh token 轮替失败会直接跳回 `/login`（登录态储存设计，T191/T206），与样式无关，未处理。
- 统计页的 6 张摘要卡复用 `.management-metric` 的 class 语言，**不**换成 `ManagementMetrics` 组件——后者绑定 `ManagementKey` 与 store，而统计页自带走日期区间查询。
