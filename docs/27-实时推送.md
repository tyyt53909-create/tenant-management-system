# 实时推送：WebSocket + 轮询后备（COM-02 / T282）

## 1. 通道

- 后端：Socket.IO 命名空间 `/notifications`，仅推送「新站内通知」事件 `notification`。
- 前端：管理后台 `MainLayout` 登录后连接；收到事件只刷新未读数（列表页按需拉取）。
- 轮询后备：连接失败/断开时每 30s 调 `GET /notifications/unread-count`；重连成功后停止轮询。

## 2. 鉴权

- 握手只认 `auth.token`，必须是 **Access Token**（`tokenType=ACCESS`）。`?token=` 会被忽略，避免令牌进入代理日志。
- CORS 使用与 HTTP 相同的 `CORS_ORIGINS` 白名单，不反射任意来源。
- 校验失败/过期/Refresh Token → 立即断开，不加入任何房间。
- 房间：`user:{userId}`，服务端只向本人推送；不广播全局。

## 3. 服务端

- `NotificationsGateway`：`handleConnection` 验签、join、断线日志。
- `NotificationsService.create`：站内通知落库后 `emitNotification(userId, notification)`；WS server 不存在（Worker/测试）时静默跳过。
- 客户端仍需通过 REST 获取完整列表；WS 只用于「有新通知」提示，避免消息体重复与权限绕过。

## 4. 配置与部署

- 前端：`VITE_WS_URL`（可选）；未设置时用 `window.location.origin`，适用于同域 nginx 反代。
- nginx 需转发 `/socket.io/` 并支持 WebSocket Upgrade（生产模板后续补；当前 staging 可用同域）。
- 多实例：Socket.IO 默认单实例内存 adapter；多实例实时广播需 Redis adapter（OPS-06 后续，未在本次实现）。

## 5. 测试

- 单元：有效 token join、Refresh/无效 token 断开、emit 只发指定房间、无 server 静默。
- 前端：`vue-tsc` 与 lint；实际连接由 Playwright/手工验证（CI 不检测 WS 握手）。

## 6. 已知边界

- 多实例下未接 Socket.IO Redis adapter，跨实例推送不保证；当前按 DEC-07 单机部署。
- 未做消息可靠投递/离线补发；离线用户依赖下次轮询与列表拉取。
- 小程序未接 WebSocket（FE-02 后续）。
