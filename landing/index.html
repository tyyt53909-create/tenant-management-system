房态状态机 / ROOM LIFECYCLE

报修全流程 / SERVICE FLOW

一个房间从空到满，每一步都有据可依

报修不是发个消息，而是一条能追的工单

房态不是随便改的一个下拉框。每次流转都要过校验：没有合同不能直接标已出租，有未结账单不会让你安静退租。

提交之后，工单会依次经过受理、派单、处理与确认。每一步都有时间戳，处理说明和照片都留在工单上。

  1. 空置可带看、可预订；保洁完成才回到可租状态。
  2. 已预订锁定房间，等待签约；预订到期可自动释放。
  3. 已出租绑定了生效中的合同，账单从合同参数生成。
  4. 维护中不计入可租，维修完成后回到空置或待清洁。
  1. 已提交选择类别、紧急度，写下问题并上传照片。
  2. 已受理 → 已派单管理者确认并安排处理人。
  3. 处理中 → 待确认维修完成后等你确认实际结果。
  4. 已完成工单归档，处理说明与照片可随时回看。

常见问题 / FAQ

上线前最常被问到的几件事

数据放在哪里？能不能自己部署？

整套系统可以部署在你自己的服务器上，PostgreSQL 与 Redis 都在你的网络里，对象存储可接阿里云 OSS 或本地磁盘。仓库里有多阶段的 Dockerfile 与生产编排文件，不依赖托管平台。

租客需要装 App 吗？

不需要。租客端是微信小程序，扫码或搜索进入，用手机号或邮箱验证码登录。合同、账单、报修、余额都在小程序里，不占手机存储。

账单和收款怎么避免重复入账？

收款请求必须带唯一交易号，服务端在同一事务里做幂等判断，重复提交返回 409 而不是再记一笔。账单支持部分缴付，已缴金额与状态由服务端计算。

水电费怎么算？

按表计读数与生效中的价目计算，价目支持按时间生效的历史版本。抄表后自动从预付余额扣费并写一条流水；智能表可通过 MQTT 上报读数，模拟读数会被单独标记、不参与结算。

保洁能看到租客的账务吗？

不能。保洁角色只有现场工作台：空置房源、清洁状态、开始与完成清洁、上传照片。合同与账务接口对保洁角色直接拒绝，不靠前端隐藏。

多人同时改房态会冲突吗？

不会。房态变更走状态机校验并带版本号，后提交的一方会收到冲突提示而不是覆盖前一个人的结果。定时任务在多实例下通过咨询锁选主，同一任务不会并行跑两遍。
